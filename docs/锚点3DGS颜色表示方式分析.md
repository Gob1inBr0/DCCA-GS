# 锚点式 3D 高斯泼溅的颜色表示方式分析

> 日期：2026-08-23
> 关联 Obsidian 笔记：锚点外观/颜色表示（新增 5 篇，见 `Reading List.md`）
> 对象：`Scaffold-GS / HAC++ / DCCA-GS` 这一条锚点式 3D 高斯泼溅主线，以及用“特征替代球谐函数”的代表工作。

## 结论先行

“用特征（Feature）替代球谐函数（SH）”不是一个简单的替换，而是把“存储”换成“生成”：不再逐高斯存一组庞大的 SH 系数，而是存一个紧凑特征向量，再由轻量网络（MLP）在渲染时解码出颜色或 SH 系数。它在**模型大小**与**渲染质量**之间重新权衡，本质上是通过引入可学习的中间表示来换取紧凑性。本文按“直接存 SH → 特征+MLP 解码 → 更激进的表示族替换 → 特征增强 → 前馈预测 → 颜色正则化/压缩”六条路线梳理，并落到 DCCA-GS 上：**DCCA-GS 走的是“特征 + 视角方向 → mlp_color → 3 通道直接 RGB”**，即连 SH 系数都不预测，是这条范式里最激进的一种。

---

## 1. 背景：3DGS 的颜色到底是什么

3D 高斯泼溅（3D Gaussian Splatting，3DGS）用各向异性高斯基元表示场景，每个基元除位置、协方差、不透明度外，还带一组**视角相关颜色**参数。经典 3DGS（Kerbl 2023）用**球谐函数（spherical harmonics，SH）系数**编码这组颜色：存储一个 `N × (C × (deg+1)²)` 的 SH 系数张量，渲染时用射线方向把 SH 评估成 RGB。SH 系数随阶数（deg，通常 3 阶 = 16 个系数/通道）增长很快，是模型体积的主要来源之一，且**表达高频/镜面/各向异性能力有限**。

锚点式方法的出发点正是绕开“逐高斯存 SH”：用稀疏锚点 + 特征 + MLP 现场生成高斯属性。

## 2. 六条颜色表示路线

### A. 直接存 SH（原始 3DGS / gsplat）

- 每个高斯直接存一组 SH 系数，渲染时评估得到视角相关 RGB。
- 优点：结构简单、视角相关；缺点：存储大（每高斯几十到上百个系数）、冗余高、难压。
- 代表：原始 3DGS、gsplat。体积口径下 3DGS 约 612 MB（DCCA-GS 提案参考值）。

### B. 特征 + MLP 解码（Scaffold-GS → HAC++ → DCCA-GS）

- 锚点存一个**特征向量 `f`**，每个锚点解码 K 个“神经高斯”；颜色由 MLP 从特征（+视角方向）现场预测，而非直接存。
- 这一条是当前主线。Scaffold-GS 奠基，HAC/HAC++ 再加哈希网格上下文 + 熵编码把特征等属性压进比特流。
- 关键权衡：**特征维度直接决定体积与质量**。特征越大、质量越高、模型越大；调小则属性预测退化、出现伪影。这正是 SOGS 指出的“两难”（见 D）。
- 代表：Scaffold-GS、HAC、HAC++、DCCA-GS。

### C. 换表示族：ASG 外观场替代 SH（Spec-Gaussian）

- 不满足于“SH 表达高频不足”，用**各向异性球面高斯（anisotropic spherical Gaussian，ASG）**外观场替代 SH：特征 `f`（如 24 维）→ MLP → ASG 参数 → 潜在特征 → 另一个 MLP → 最终颜色。
- 优点：更好建模镜面/各向异性高光，不增高斯数；缺点：参数与计算增加，ASG 参数能否量化/进比特流需重新设计。
- 代表：Spec-Gaussian（2402.15870）。

### D. 特征增强：二阶锚点（SOGS）

- 不改变“特征预测属性”范式，而是**增强特征本身**：引入协方差二阶统计量与特征维间相关，在每个锚点内“补回”降维损失，配合选择性梯度损失优化纹理与几何。
- 目的：用很小的额外开销，在**减小特征维、缩小模型**的同时保住甚至提质量。
- 代表：SOGS（2503.07476）。对 DCCA-GS 的 `feat_dim` 与体积权衡最有参考价值。

### E. 前馈预测：AnchorSplat / ATSplat

- 在需要**前馈（feed-forward）**的设定下，用图像/几何先验生成锚点，再经 Transformer + MLP 直接回归每个锚点对应高斯的属性（含 SH 系数）。
- AnchorSplat：用 3D 几何先验（点云/体素/RGB-D）做锚点对齐表示，摆脱像素对齐，高斯数不再随分辨率/视角数增长。
- ATSplat：用自适应 3D 令牌（anchor token）+ 渲染误差监督的令牌扩展，恢复 3DGS 的“场景自适应容量分配”，高斯数减少 5.7 倍。
- 与 DCCA-GS 同构（锚点 → 预测属性），但走“免逐场景优化 + 先验引导”，适合大规模/快速重建。

### F. 颜色正则化 + 压缩：DropAnSH-GS

- 面向**稀疏视角**过拟合：锚点基 Dropout（丢锚点及其邻域簇）打断邻居补偿效应；高阶 SH Dropout 把外观信息集中到低阶。
- 副产物是**可压缩性**：低阶集中的 SH 系数可训练后截断，实现无损压缩。
- 代表：DropAnSH-GS（2602.20933）。与 DCCA-GS 的“颜色/MLP 量化 + 熵编码可压缩性”思想互补。

## 3. 对比表

| 路线 | 存储的“颜色”对象 | 是否用 SH | 视角相关/高光能力 | 模型大小 | 压缩兼容性 | 代表工作 |
| --- | --- | --- | --- | --- | --- | --- |
| A 直接存 SH | 每高斯一组 SH 系数 | 是（直接存） | 中（高频弱） | 大 | 需熵编码 | 3DGS / gsplat |
| B 特征+MLP 解码 | 紧凑特征 `f`（+MLP 权重） | 用 / 或直接 RGB | 视 MLP | 中（可控） | 好（特征+MLP 皆可熵编码） | Scaffold-GS / HAC++ / DCCA-GS |
| C ASG 替代 SH | 特征 → ASG 参数 → 潜在特征 | 否（ASG） | 强 | 中偏大 | 待设计 | Spec-Gaussian |
| D 特征增强（二阶） | 紧凑特征 + 二阶统计 | 用 | 视 MLP | 小（特征维可选小） | 好 | SOGS |
| E 前馈预测 | 几何/图像先验生成锚点特征 | 用（SH 由 MLP 回归） | 中 | 小（高斯数少） | 好 | AnchorSplat / ATSplat |
| F 颜色正则化+压缩 | 特征 → SH（低阶集中） | 用 | 中 | 小（可截断压缩） | 好 | DropAnSH-GS |

维度说明：**视角相关/高光能力**衡量能否刻画镜面、各向异性、高频；**模型大小**指颜色相关存储（特征/系数+MLP 权重）的相对量级；**压缩兼容性**指该表示能否顺利进入量化/熵编码/截断类压缩。

## 4. 与 DCCA-GS 的关系

### DCCA-GS 当前的颜色表示

DCCA-GS（ScaffoldGSModel，`scaffold_gs/model.py`）的颜色路径是：

```text
cat_local = concat(anchor_feature(feat), view_dir(ob_view))     # [feat_dim + 3]
color     = mlp_color(cat_local).reshape(n, K, 3)               # 末尾 Sigmoid，3 通道
```

- 每个锚点存特征 `feat`（默认 `feat_dim=50`），每个锚点解码 K=10 个神经高斯；
- 颜色 = **锚点特征 + 视角方向 → mlp_color → 3 通道 RGB**，输出带 Sigmoid（0~1）；
- `appearance_dim=0`（HAC++ 无外观嵌入），即不含单独的逐相机外观码；
- 因此 DCCA-GS **不存、也不预测 SH 系数**——它把“SH 评估”整体换成“MLP 直接回归 RGB”。

### 体积口径下的含义

在 DCCA-GS 的解码必需载荷里（4-28，110k，float32 记账）：Feature 约占 **50.60%**、Scaling 20.00%、Offsets 12.20%、MLP 权重 5.90%。也就是说，**颜色信息的“信息源”在特征（feature）里**，而特征正是体积大头。颜色本身不再逐高斯存 SH，所以体积由“特征 + MLP 权重”决定，而不随（SH 系数 × 高斯数）爆炸。

### 各路线对 DCCA-GS 的启发

- **C（ASG）**：若要处理 UAV/城市里常见的金属、反光、水面等镜面场景，ASG 是比 SH/当前 MLP+RGB 更强的高光表示；但要评估 ASG 参数能否量化并进熵模型，以及额外计算成本。
- **D（SOGS 二阶统计）**：直接指向 DCCA-GS 的 `feat_dim` 与体积权衡（feature 占一半体积）。当想进一步压 `feat_dim` 时，二阶统计特征是“降维保质量”的可用杠杆，且不与 SPA（减锚点数）冲突，可叠加。
- **E（前馈锚点）**：AnchorSplat / ATSplat 的“先验生成锚点 + 自适应扩展”与 DCCA-GS 的锚点生长/稀疏（SPA）异曲同工，可对比前馈与训练侧两种自适应分配的实现成本与效果。
- **F（DropAnSH-GS）**：其“把外观信息集中到低阶以便截断压缩”与 DCCA-GS 的“MLP 量化 + 属性熵编码”在目标上互补；若 DCCA-GS 后续引入 SH（或保留可截断属性），可复用该正则化/压缩思路。
- **B（主线）**：DCCA-GS 已是“特征 + MLP 解码颜色”的典型代表，且更激进（直接 RGB、无 SH）。相对“MLP 预测 SH 系数”的官方 Scaffold-GS/HAC++，DCCA-GS 省去了 SH 系数的存储与评估，但也失去 SH 的显式视角相关性，需要靠 MLP 的视角条件输入来保持视角相关颜色——这是值得在报告里明确的差异。

## 5. 结论与建议

1. **“特征 + 轻量网络解码颜色”是锚点式 3DGS 的主方向**，DCCA-GS 已位于其中并把“SH”整个省掉（直接回归 RGB）。它比逐高斯存 SH 更紧凑，代价是 MLP 权重与特征本身也要入体积（并需熵编码/量化）。
2. **颜色表示的选择是一个“存储-质量-可压缩性”三方权衡**：直接存 SH 最直观但最笨重；特征+MLP 居中；ASG 偏向高光质量但与压缩兼容性待验证；二阶增强偏向省体积保质量；前馈偏向快速与紧凑；DropAnSH 偏向鲁棒+可压缩。
3. **对 DCCA-GS 而言，最有价值的两个口子**：一是用 **SOGS 式二阶统计**应对“feature 占 50% 体积”的瓶颈（降维保质量）；二是若面向反光/金属场景，引入 **ASG 式外观**并评估其量化进熵模型。
4. 后续做颜色表示改动时，需与 DCCA-GS 的既有约定保持一致：**解码端可复现（decoder-reproducible）**——任何颜色解码用的量都要由解码器从已传输信息重算，且变化后要重走“编码 → 解码 → 评估”并复测比特流组成。
