# 概念删除（压缩域）论文故事线草案

- 建立：2026-10-01，分支 `feat/concept-deletion-mvp`
- 配套设计：`../02-design/概念删除_压缩域最小验证实验设计.md`
- 定位：独立论文，DCCA-GS 作为载体出现，**不**并入 3366/ICLR 压缩论文的叙事。

## 一、故事钩子

**"删掉锚点 ≠ 删掉信息。"**

对一个训好的锚点式 3DGS 场景，按概念删除锚点是容易的；但网格编码（hash grid +
三平面）是按整个场景拟合的，被删区域的特征原样留在码流里。MVP 第 2 步要量化的
就是这件事：锚点删干净了，网格里还剩下多少可被利用的信息。这一张图（删除前后、
清理网格前后、码流审计三个条件的残留信息对比）决定整篇论文的基调。

## 二、三个叙事框架（按决定性实验的结果选）

### 框架 A：压缩会议视角——"可删除性是码率-失真之外的第三个轴"

- 主张：让码流支持"删一段即可删除概念"（概念同质锚点分段编码 + 段内独立上下文），
  要付出可量化的码率代价；把"可删除性 vs 码率"画成一条新曲线。
- 证据链：分段设计 → 码率开销曲线 → 删除后解码正确性 → 残留审计通过。
- 标题候选："Deletable Streams: Rate-Cost of Concept Removal in Compressed
  3D Gaussian Splatting" / "The Price of Forgetting: Deletion-Friendly Coding
  for Anchor-Based Gaussian Splatting"。
- 目标：DCC / ICASSP / 数据压缩期刊；风险：审稿人问"谁会为可删除性付码率"——
  用法规（被遗忘权）与平台分发场景（发布后收到删除请求，不可能重新采场）回应。

### 框架 B：视觉会议视角——"压缩即最强删除保障"（当前推荐）

- 主张：未压缩 3DGS 的软删除留下可挖的参数，隐式模型（NeRF）连删哪里都说不清；
  显式锚点表示 + 重编码把被删内容的比特物理移除，是三维场景里可验证遗忘的
  最强形态。贡献三件套：锚点级归属分解、删除-质量-残留三角评测、
  覆盖网格与侧信息的审计协议。
- 证据链：P1 归属 → P2 网格泄漏（"删除不彻底"的反例）→ 清理后码流审计通过
  （"重编码 = 删除保障"的正例）→ 主体质量保持。
- 标题候选："Deletion by Recompression: Verifiable Concept Removal in
  Compressed Gaussian Scenes" / "删掉锚点不等于删掉信息：压缩域三维概念删除
  与残留审计"（英文稿不用中文标题，此处仅示意钩子）。
- 目标：CVPR / ICCV 主会；与 Remove360（arXiv:2508.11431，只测残留不提供删除方法）
  和 NeurIPS 2025 的 3D 生成模型遗忘工作形成互补定位。

### 框架 C：安全会议视角——"学习型三维编解码器的残留信息取证"

- 主张：把熵模型参数/码表/超先验和网格特征当作新的泄漏面，做系统性泄漏分析
  （被删内容能否从侧信息恢复），给出编码器侧的清理清单。
- 前提：P2 的泄漏量必须显著，且最好在熵模型侧信息上也找到可测泄漏。
- 目标：CCS / USENIX Security / PETS；风险：若泄漏不显著，整个框架塌掉，
  只能退回框架 B 的一个章节。

## 三、决定性实验与框架选择

| MVP 结果 | 走哪个框架 |
| --- | --- |
| P2 泄漏显著 + 熵模型侧信息也找到泄漏 | 框架 C 优先，B 兜底（双投策略不可取，选一个主投） |
| P2 泄漏显著，侧信息干净 | 框架 B（网格泄漏作为"删除不彻底"的核心证据） |
| P2 不泄漏 | 框架 A（码率代价是主贡献），P2 的否定结果作为审计协议的必要性证明写入 |

## 四、叙事注意

- 遵守仓库命名规则：正文不造花名；"支持度归属""网格泄漏探针""残留审计"
  首次出现都用一句话说清它是什么。
- 威胁模型必须在第 3 节写死：攻击者拥有删除后的码流/模型与解码器，可渲染任意
  视角；不拥有原始训练图像。审计结论是"该威胁模型下的量化下界"，不承诺绝对删除。
- 双刃剑段落不可省：同一套工具可用于抹除真实痕迹；生成修补内容必须带标识。
- 与未压缩路线的区隔要写成贡献而非回避：软删除的参数残留 vs 重编码的比特移除，
  是显式表示 + 压缩管线的独特优势。

## 五、投稿前必答的五个审稿人问题（预写回应）

1. "删除后重编码和'删锚点另存'有什么本质区别？"——码流级删除保证（比特物理消失）
   + 网格/侧信息的泄漏审计是未压缩路线给不出的；给出两者的残留对比实验。
2. "概念边界切过锚点邻域怎么办？"——支持度分解 + 段间过渡带设计（消融）。
3. "码率代价多大，值得吗？"——给出等质量下可删除编码的开销百分比曲线（框架 A/B 共用）。
4. "残留审计是不是针对性协议？"——协议开源、与 Remove360 基准对话、报告覆盖范围声明。
5. "为什么不直接在未压缩模型上做然后随便压缩？"——正文第 1 节用 P2 的数据回答：
   未压缩删除不清理网格就是漏的；压缩域路线把清理变成了编码问题。
