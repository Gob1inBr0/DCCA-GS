# 训练内锚点合并运行指南

从 GitHub 的 `main` 开始。这个功能用于 HAC++ 训练，在配置的训练步执行一次。常规训练入口是 [train.py](../../train.py)，配对实验入口是 [compare_anchor_merge_saving_filter.py](../../scripts/compare_anchor_merge_saving_filter.py)。

## 训练参数

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--cfg.anchor-merge-step` | 未设置 | 触发合并的训练步，必须晚于本轮所有锚点结构调整 |
| `--cfg.anchor-merge-response-rms-limit` | `0.05` | 预乘颜色和不透明度的联合响应均方根误差上限 |
| `--cfg.anchor-merge-min-saving-bytes` | `1.0` | 每对锚点预计净省字节下限，Python 配置可设为 `None` 以关闭 |
| `--cfg.anchor-merge-candidate-neighbors` | 未设置 | 给定时按最近邻取候选。启用字节下限时默认取码率推导的搜索半径，关闭下限时默认取 16 个近邻 |
| `--cfg.save-anchor-merge-initial` | 关闭 | 在该步首个参数更新前保存 `after_anchor_merge.pth` |

检查点记录已经执行的合并步。从合并前的检查点续训时，指定步触发合并。从已合并的检查点续训时，可继续使用同一合并步。HAC++ 创建优化器时会同步检查点保存的场景倍率，并据此计算偏移和掩码学习率。

## 复现 room 的字节下限对照

使用同一个 `ckpt_18000.pth` 和与其数据划分相匹配的 `camera_schedule.npy`。检查点的 `data_config` 中应含可访问的 `room` 数据路径。Python 环境需能运行 PyTorch、gsplat、HAC++ CUDA 扩展和 SciPy，且 `tmc3` 应能从 `PATH` 找到。先准备一个新结果目录，再从仓库根目录运行以下命令。示例顺序使用单卡，三个正式组也可分开运行。

```bash
set -e
mkdir -p "$RESULT_DIR"
for group in smoke control minimum_one_byte no_minimum; do
  python -m scripts.compare_anchor_merge_saving_filter \
    "$group" "$RESULT_DIR" "$CHECKPOINT_18000" "$CAMERA_SCHEDULE"
done
```

`smoke` 在空间子集上检查实际合并、续训和解码。正式组分别为未合并对照、保留 1 字节下限、取消下限，均从 18k 训到 30k。每组的 `<group>/result.json` 含续训前和终点的独立解码评测、逐文件字节和参数更新记录。训练过程中得到的 `metrics.jsonl` 用于排查，正式画质从 `initial/decoded_eval/metrics.jsonl` 和 `final/decoded_eval/metrics.jsonl` 读取。旧阈值扫描和 35k 续训使用历史快照，复查时按对应核验结果的来源记录定位代码。

如需从同配置重建共享起点，命令需要该配对实验采用的参考检查点和场景目录。

```bash
mkdir -p "$SHARED_RUN"
python -m scripts.run_in_training_anchor_merge \
  common "$REFERENCE_CHECKPOINT" "$ROOM_DATA_DIR" "$SHARED_RUN"
```

该命令生成 `$SHARED_RUN/common/ckpts/ckpt_18000.pth` 和 `$SHARED_RUN/camera_schedule.npy`。正式比较时各组使用同一个共享起点及相机序列。复查已发布数字时优先使用来源记录中的原检查点。

## 比较近邻候选数

配对脚本支持 `--candidate-neighbors`，默认值为 16。使用相同共享检查点、相机序列和响应上限，分别在新结果目录中运行即可比较近邻数量。以下命令对应取消预计字节节省下限的 64 近邻分支。

```bash
mkdir -p "$RESULT_64_DIR"
python -m scripts.compare_anchor_merge_saving_filter \
  no_minimum "$RESULT_64_DIR" "$CHECKPOINT_18000" "$CAMERA_SCHEDULE" \
  --candidate-neighbors 64
```

结果位置与字节下限对照相同。每组的合并报告记录近邻数和各轮候选数量。

## 从当前检查点续训到总计 45k（2026-11-22）

本次检查 `room`、种子 42、码率损失权重 0.002 的训练是否接近平台。两臂分别读取修复空间学习率后的未合并和 64 近邻取消预计字节下限的 30k 检查点。保留 Adam 状态，不再执行合并或增密，训练总预算为 45,000 步。

- 新增训练相机序列使用原生成器延长，逐元素核对前 30k 与原文件完全一致，两臂新增相机相同。
- 每 2,500 步保存检查点，独立压缩和解码，用原来的 39 张留出视角评测 PSNR、SSIM 和 LPIPS，并核对精简文件与标准路径的解码张量逐位一致。
- 学习率计划的长度保持原值，因此超过 30k 后使用原计划的末值。偏移和掩码继续训练，锚点坐标按原配置固定。正式运行前在空间子集上续训 400 步，并检查参数变化及实际编解码。
- 描述性判断预先约定：最后 5k 净增益绝对值低于 0.05 dB，且 40k、42.5k、45k 的极差不超过 0.10 dB，记为在本配置下接近平台。净增益达到 0.05 dB 则继续训练仍有可见收益。该判断不等于数学上的收敛，也不构成多种子统计结论。
- 同时比较相同步数的未合并对照。合并组相对自身变好与合并后画质差距缩小分别记录。文件大小可能随训练变化，需要同时给出实际字节。

提交入口为 `scripts/run_anchor_merge_45k_lyh.sh`。结果目录为 `runs/anchor_merge_45k_room_20261122/attempt_01`，只申请用户授权叠加的 LYH GPU 4–7。来源版本、检查点校验和与相机序列校验和写入 `provenance.txt`。本批已完成，结果已登记 `docs/data/experiments.csv`，完整核验见 `runs/anchor_merge_45k_room_20261122/verified_results.json`。

额外的 35k 提前评测读取正式保存的检查点，在授权空余卡上独立解码。它用于提前观察趋势，不增加训练步数，也不算随机种子重复。训练损失从进度日志约每 10 步的采样重建，按 2,500 步分段取均值，分段边界的显示计数存在小于一个采样间隔的近似；该指标与解码 PSNR 分开解释。
