## 2. 最近一次会话做了什么（09-24 晚—09-25）

按时间顺序，全部已提交推送：

1. **补格**：1-78 λ0.004 新代码基线（27.394 @ 10.67 MB，与另一次复跑
   差 0.004 dB，干净）+ 2-06 λ0.0005 第二种子（28.51 @ 23.39）。
   至此 1-78/2-06 基线双种子齐、4-10 单种子三档。
2. **BD-rate 重算**：全新代码基线对 HAC++ 三点——**画质区间不重叠**
   （我方上限 27.81 < HAC++ 下限 27.84），单一 BD-rate 数字仍是外插伪影。
   结论：**BD-rate 冻结维持**；论文用两种可辩护表述——同画质最近点对
   （体积省 30.6%，画质低 0.146 dB）和平价点（−24% 体积）。
3. **条件表改进的门判定：未过**。把量化步长档位加进残差编码条件、
   分组数 32→128：真实字节变化在 ±0.1%（噪声级）。结论：条件表粒度
   已到该编码架构的天花板。附带修掉一个旧 bug（幅度段的条件索引错位，
   编码解码两端一致地错，所以往返校验一直通过——**往返校验只能证明
   自洽，不能证明按设计工作**）。
4. **用小 MLP 预测概率参数的尝试：负结果**。按符号负对数似然度量省
   15.4%/17.2%（过了门），但接入真实的逐位是非题编码框架后，字节反升
   35–38%。根因：MLP 预测的分布参数比逐位框架拟合的更宽，每个是非题的
   概率离 0/1 更远，逐题多花的比特吃掉了 NLL 收益。**教训：门测量必须
   在与生产编码器同构的框架内做**。静态分组频率统计表保持生产选择。
5. **两份论文准备文档**：方法节中文底稿（渐进分层压缩_方法文档）+
   创新点清单（期刊版创新点文档，四项创新点各带主张/证据/边界/冻结项）。

## 4. 当前数字快照（1-78，全部 150 视角或注明）

| 方法 | 字节 | PSNR |
| --- | --- | --- |
| HAC++（三个独立文件） | 20.0 / 26.3 / 40.6 MB | 27.84 / 28.21 / 28.68 |
| 我们 base 单码率（学习式上下文编码器） | 10.7 / 13.9 / 19.9 MB | 27.39 / 27.69 / 27.81 |
| 我们渐进分层码流 λ0.0005（分字段阶梯+分组频率表条件，150 视角） | 15.75 → 29.95 MB 四档 | 25.01 → 26.70 |
| 同上 λ0.004（16 视角快端口径） | 4.3 → 14.6 MB 五档 | 14.35 → 26.69 |

读法：base 曲线贴着 HAC++（同画质省约 30% 字节）；渐进码流比 base 低
0.7–1.7 dB——**全部差距在码流打包层**（符号本身与 base 完全一致），
不在量化或渲染。

## 6. 本轮踩过的坑（接手人必读）

1. **CSV 写行必须用 csv.writer**：手拼字符串遇到含逗号的字段会错位
   （两次事故）。坏行修复方法见 CHANGELOG 09-25 条。
2. **`s.replace` 补丁会静默失败**：匹配串不精确时不报错也不替换。
   打补丁后必须 grep 验证目标串真的变了。
3. **往返校验通过 ≠ 编码器按设计工作**：两端用同一个错误实现时校验
   依然绿。发现手段是子代理代码审查 + 逐层字节对比。
4. **写代码后先跑子代理审查再跑实验**（09-25 用户要求，已两次抓到
   崩溃级问题：空复合组、embedding 越界）。
5. **训练卡上不共置渲染任务**（OOM 事故一次，自动重试救回但浪费
   7 小时）。
