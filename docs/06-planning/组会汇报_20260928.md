# DCCA-GS 组会汇报（2026-09-28）

主题：期刊版主轴定调并落地（渐进分层码流走完设计→真实码流→全链路实测）；B3 双档配对实验双门通过并采纳；HAC++ 对比补齐低码率延伸点；四个提效方向证负关闭。

## 事实与结论

### 期刊版主轴（9-23 定调）

- 主贡献 = 渐进分层码流（一个文件，四个画质档，传到哪用到哪）。
- 组件分工：SPA 剪枝引用不算贡献；次模覆盖定位紧预算专用组件，不包装成全曲线方法；融合剪枝停止投入，保留机制分析。
- 数字纪律：单格差 < 0.2 dB 不作数、结论需双种子、"+0.521" 停用（其基准被确认是崩溃格，修正后该格增益约 +0.11）。

### 渐进分层码流：设计到全链路实测

| 层 | 内容 |
| --- | --- |
| 表示层 | 嵌套质量阶梯 + 分字段粗化档位（feat/offset 8 倍起步、scaling 2 倍起步，避免对数域悬崖） |
| 编码层 | 二值分解区间编码（零标志→符号→幅度逐位），基层/增强层用（组×粗值幅度桶）复合条件表，条件信息解码端可重算（零边信息契约，验证 100%） |
| 评测层 | 150 视角逐前缀渲染，逐视角数字存档；λ0.0005 / λ0.004 两族曲线 |

- 关键实测（1-78，150 视角，2026-09-28 审计统一口径）：渐进曲线 P0 15.74 MB@25.83 → 满精度 30.48 MB@27.60（满精度档与生产解码逐位一致，见审计一节）。与 base 单码率的剩余差距在码流打包层（静态条件表比学习式编码器贵约 3–6 MB）。
- 负结果：条件表细化（步长档位×分组变细）未过门（≥10% 字节目标，实测 ±0.1% 噪声级）——该编码架构下条件粒度已到顶。学习式概率模型四步全程证负关闭（独立探针里 MLP 对"仅按组"静态表省 45.9% 过门，接入生产码流后对"组×桶"复合条件表零增益；教训：门测量的参照基线必须与生产编码器同构）。

### B3 阶梯对齐训练：重启 → 双档过门 → 采纳

- 方法：训练末期对量化符号到粗阶梯倍数的偏移加惩罚，把符号往基层友好的位置推。
- 波折记录：9-23 写了一半的改动以未提交修改形式在分支切换中丢失（当时"config 开关已加"的记录失实，已更正）；重启后子代理审查抓出 mask 梯度泄漏等 2 个真 bug。v1 权重过猛判负：w=0.05 时 P0 +0.093（门 +0.3 未过）且满精度塌 0.48 dB——惩罚对属性的推力在 Adam 下不随权重线性缩放。
- v2 双档配对实验（同代码同种子，只差惩罚开关）双门通过：

| 档 | P0 增益（150 视角，审计后口径） | 满精度档 | 判定 |
| --- | --- | --- | --- |
| λ0.0005（w=0.01） | **+0.259** | **+0.083** | 采纳 |
| λ0.004（w=0.05） | **+0.916**（12 dB 悬崖上） | −0.026（噪声级） | 采纳 |

- λ0.0005 档四档全面更好（修正口径下 B3 臂满精度 26.23 MB@27.68 对对照 30.48 MB@27.60——省 4.2 MB 还高 0.08 dB）。附带发现：机制收益随悬崖变陡而放大；配对差值在审计前后稳定（+0.256→+0.259）。

### 审计发现（2026-09-28，发布前修正）

1. 量化栅格不一致（真 bug，主因）：分层管线自推的 Q 与生产解码器实际栅格大面积失配（feat 81% 元素、最大偏 0.8 步）。修复：解码器导出本次解码实际栅格，管线消费同一栅格并逐次自检（修复后三场 0 失配）。
2. GT 分辨率不一致（口径，次因）：分层管线在 1897px GT 评测，base/HAC++ 均为 1600px；已统一为 1600px 并参数化。
- 验证：控制 run 修复后满精度 27.6013 = 生产解码 27.6013（逐位）；此前"渐进满精度比解码低 0.9 dB"确认为伪影，修正后渐进曲线上移 0.6–0.9 dB。B3 门判定复验通过。附带修复：.bin 改层级序写入（每个质量档=文件连续前缀，"任意截断"主张此前不成立）；中间档字节核算收紧。

### 与 HAC++ 对比：延伸到低码率

补跑 HAC++ 官方代码 λ0.008 / 0.016（协议与已有三点一致）：λ0.016 → 12.10 MB / 26.868；λ0.008 → 16.34 MB / 27.633。

- HAC++ 紧档不塌，曲线平滑延伸到 12.1 MB——"低码率区只有我们有产品"收缩为"<12.1 MB 独占"（λ0.004 渐进曲线从 7 MB 起步）。
- 延伸段我方 base 全面占优：27.394@10.67 对 HAC++ 26.868@12.10（高 0.53 dB 且小 1.4 MB）；27.695@13.90 对 27.633@16.34（同画质省 2.4 MB）。
- 渐进不打画质仗：修正口径后同字节下渐进低于 HAC++ 约 0.5–0.9 dB（审计前口径 1–2 dB），但 HAC++ 没有"一个文件多档"能力；B3 把独占区起点抬高 0.9 dB。剩余差距来源：静态条件表编码器比 HAC++ 学习式编码器贵。
- 高码率区（20–40 MB）定位不变：base 对 HAC++ 同画质省约 30%（平价点 −24%、最近点对 −30.6% @ −0.146 dB）；BD-rate 数字维持冻结（双方画质区间不重叠，单一数字是外插伪影）。
