## 2. 渐进分层码流：从设计到全链路实测

| 层 | 内容 |
| --- | --- |
| 表示层 | 嵌套质量阶梯 + 分字段粗化档位（feat/offset 8 倍起步、scaling 2 倍起步，避免对数域悬崖） |
| 编码层 | 二值分解区间编码（零标志→符号→幅度逐位），基层/增强层用（组×粗值幅度桶）复合条件表，条件信息解码端可重算（零边信息契约，验证 100%） |
| 评测层 | 150 视角逐前缀渲染，逐视角数字存档；λ0.0005 / λ0.004 两族曲线 |

关键实测（1-78，150 视角，2026-09-28 审计统一口径）：渐进曲线 P0
15.72 MB@25.83 → 满精度 30.48 MB@27.60（**满精度档与生产解码逐位一致**，
见 §3.5 审计一节）。与 base 单码率的剩余差距在码流打包层（静态条件表比
学习式编码器贵约 3–6 MB）——这是下一步最大提升杠杆，也引出了 B3（§3）。

两个负结果如实记录：

- **条件表细化（步长档位×分组变细）：未过门**（≥10% 字节目标，实测
  ±0.1% 噪声级）。结论：该编码架构下条件粒度已到顶。
- **学习式概率模型：四步全程证负关闭**。独立探针里 MLP 对"仅按组"静态
  表省 45.9%（过门），但接入生产码流后对"组×桶"复合条件表零增益。
  教训已入册：**门测量的参照基线必须与生产编码器同构**，否则高估增益。

## 3. B3 阶梯对齐训练：重启 → 双档过门 → 采纳

**问题**：渐进基层（8 倍粗化）失真大，P0 画质低。**方法**：训练末期
对量化符号到粗阶梯倍数的偏移加惩罚，把符号往基层友好的位置推。

过程有两次波折，都如实记录：

1. **代码丢失**：9-23 曾写了一半的改动以未提交修改的形式存在，在分支
   切换中丢失（当时记录"config 开关已加"失实，已更正）。重启后在正确
   的可运行代码线上重新实现，子代理审查抓出 mask 梯度泄漏等 2 个真 bug。
2. **v1 权重过猛判负**：w=0.05 时 P0 +0.093（门 +0.3 未过）且满精度塌
   0.48 dB。机制成立但代价过大——惩罚对属性的推力在 Adam 下不随权重
   线性缩放。

**v2 双档配对实验（同代码同种子，只差惩罚开关）双门通过**：

| 档 | P0 增益（150 视角，审计后口径） | 满精度档 | 判定 |
| --- | --- | --- | --- |
| λ0.0005（w=0.01） | **+0.259** | **+0.083** | 采纳 |
| λ0.004（w=0.05） | **+0.916**（12 dB 悬崖上） | −0.026（噪声级） | 采纳 |

且 λ0.0005 档四档全面更好（修正口径下 B3 臂满精度 26.23 MB@27.68 对
对照 30.48 MB@27.60——**省 4.2 MB 还高 0.08 dB**）。两个附带发现：
机制收益随悬崖变陡而放大（紧档是主战场）；配对差值在审计前后稳定
（+0.256→+0.259，两臂同口径互相抵消，配对设计抗口径事故）。

### 3.5 审计发现（汇报写完后、发布前的关键修正）

用户追问"为什么渐进降低满精度 PSNR"触发全面审计，发现两层问题并修复：

1. **量化栅格不一致（真 bug，主因）**：分层管线自推的 Q 与生产解码器
   实际栅格大面积失配（feat 81% 元素、最大偏 0.8 步）——渐进码流此前
   描述的是"另一个模型"。修复：解码器导出本次解码实际栅格，管线消费
   同一栅格并逐次自检（修复后三场 0 失配）。
2. **GT 分辨率不一致（口径，次因）**：分层管线在 1897px GT 评测，
   base/HAC++ 均为 1600px。已统一为 1600px 并参数化。

**验证**：控制 run 修复后满精度 27.6013 = 生产解码 27.6013（逐位）；
**此前"渐进满精度比解码低 0.9 dB"确认为伪影**，修正后渐进曲线上移
0.6–0.9 dB。B3 门判定复验通过（见上表）。附带修复：.bin 改层级序写入
（每个质量档=文件连续前缀，"任意截断"主张此前不成立）；中间档字节
核算收紧。

## 4. 与 HAC++ 的对比：延伸到低码率后的完整图景

补跑了 HAC++ 官方代码 λ0.008 / 0.016 两点（协议与已有三点一致）：

| λ | 体积 | PSNR |
| --- | --- | --- |
| 0.016 | 12.10 MB | 26.868 |
| 0.008 | 16.34 MB | 27.633 |

三层结论：

1. **HAC++ 紧档不塌**，曲线平滑延伸到 12.1 MB——"低码率区只有我们有
   产品"收缩为"<12.1 MB 独占"（λ0.004 渐进曲线从 7 MB 起步）。
2. **延伸段我方 base 全面占优**：27.394@10.67 对 HAC++ 26.868@12.10
   （高 0.53 dB 且小 1.4 MB）；27.695@13.90 对 27.633@16.34（同画质省
   2.4 MB）。
3. **渐进不打画质仗**：修正口径后同字节下渐进低于 HAC++ 约 0.5–0.9 dB
   （审计前口径为 1–2 dB），但 HAC++ 没有"一个文件多档"的能力；B3 把
   独占区的起点抬高了 0.9 dB。剩余差距的来源明确：静态条件表编码器比
   HAC++ 学习式编码器贵——增强层混合编码器是下一个最大杠杆。

高码率区（20–40 MB）的既有定位不变：base 对 HAC++ 同画质省约 30%
（可辩护口径：平价点 −24%、最近点对 −30.6% @ −0.146 dB）；BD-rate
数字维持冻结（双方画质区间不重叠，单一数字是外插伪影）。
