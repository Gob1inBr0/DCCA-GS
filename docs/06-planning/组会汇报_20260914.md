# DCCA-GS 组会汇报（2026-09-14）

主题：期刊版创新点全部代码化（4 个新分支提交）并各过三轮子代理审查；审查挖出两个既有 bug；背景场方向完成"锚点大而实"实测与字节账工具。

## 事实与结论

- 审查合计抓出 6 个 P0（6 人次），最重的两个是既有 bug：
  - **缓冲双重切片**（影响所有历史选择侧实验）：`adjust_anchor` 末尾手动切片后 `prune_anchor` 又把短缓冲补零回 N 再选一遍，每个投影周期都有幸存锚点的 spa_z / coverage_ema / 敏感度 EMA 被清零（数值推演：N=6 留 4 时正确结果 [10,30,40,60] 变成 [10,30,40,0]）。fusionfix / fusA 的"融合中性偏负"结论是在带病代码上测的；修复后（prune_anchor 成为唯一选择点）期刊版关键对照必须重跑，行为变更点登记 CSV。
  - **次模传参错误**（Phase 1 阻断性）：scores 被按位置传进 pool_factor 参数 → int(张量) 抛异常 → except 静默回退 top-k，次模此前从未真正运行。已改关键字传参；烟测硬门（日志必须有 submod_keep>0）本会拦住假数据；G1 判定等修复版代码同步到服务器后出。
- 创新点状态：复杂度乘子已验证（消融去掉掉 0.41 dB，λ=0.002，1-78），冻结进 ICRA 稿；码率感知剪枝（剪枝排序从"重要度"改为"重要度/比特"，查新结论：训练侧剪枝投影按每锚点比特预算做选择无检索到先例，投稿前需人工精读 ADC-GS/PCGS 确认）；次模覆盖选择（3DGS 剪枝无先例，论文级候选；贪心 1−1/e 近似保证）；熵感知步长分配（监督目标升级为"敏感度/比特"，与码率感知剪枝共用 bits_ema）；背景特征码本（方案 C 原型已实现）。
- 背景锚点"大而实"实测：贡献面积跨 4 个数量级（中位数 1e-5，最高占一帧 7%）；按渲染器真实口径取最大不透明度，面积分位 D1/D5/D10 的中位数 0.744/0.764/0.770（平线，Spearman 0.13；均值口径 +0.26）→ 不透明度对"背景度"没有区分力，判别特征用"面积+梯度"。
- 背景场方案线决策链：四方案排序 D（背景场，治本）> B（合并少而大）> C（特征码本，1 天级）> A（放弃）；C 原型已实现 + 21/21 测试 + 三审查修复；投入决策只差服务器字节账数字：bg bits share <5% 全缓 / 5–25% 先 C / >25% D 立项。
- 配件三件：Fisher 二阶敏感度（已实现，config 门控）；holdout 恢复闸门（掉点超 max(3σ, 0.05dB) 冻结预算收缩 2 个周期，终身 5 次；已实现）；验证集学融合权重 0.7/0.3/0.25（发射脚本就绪）。共享原语 `bits_ema`（decay 0.995、5% 子采样，约 100 步覆盖全锚点，解码端零 footprint）。
- ICRA 冻结稿：数字全部可溯源，欠总览图接入 tex（12 张 SVG/PNG 图库已备）与作者信息，9/15 截止。
- 分支（均未合 main）：`codex/journal-round2-rate-aware`（4fc08b8，方向 1/3/4 全部机制 + bits_ema + 审查修复含双重切片）；`codex/bg-feat-codebook`（f2687c5 + be79d31，方案 C + 字节账脚本）。同步纪律：双重切片修复改变老缓冲行为，同步服务器前让在跑的 ph1 队列跑完。
- 预注册门与判据：rate-aware 两臂同尺寸 ΔPSNR ≥ +0.10；字节账工具 `anchor_byte_account.py`（约 2 分钟/场景）；期刊版关键对照重跑（fusA/base @ r085）。
