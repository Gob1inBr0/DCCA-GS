## 0. 一句话

期刊版的主轴从"DCCA-GS 加多个增强模块"改为：**预算感知、可渐进接收、
零边信息的压缩高斯表示**（Budget-aware / Progressive Compressed Gaussian
Representation）。剪枝侧全部降为"表示分配层"的组件；资源第一优先给真实
分层码流落地。

---

## 1. 期刊版组织结构（定稿）

```text
Representation selection（表示分配层——不承担主增益声明）
        │
        ├── SPA（GaussianSpa 锚点版）      第三方基础方法，引用
        ├── 次模覆盖选择                  紧预算专用选择组件
        └── 融合剪枝（感知调制）          防坍缩安全组件
                 ↓
      保留下来的 anchors
                 ↓
Progressive representation（主贡献所在）
        │
        ├── 全锚点粗层（L0，完整空间结构）
        ├── enhancement layers（L1..Ln 逐层补精度）
        └── progressive bitstream（独立可解、累计字节）
                 ↓
Entropy coding（熵编码层）
        │
        ├── layer-conditioned model（粗层解码结果作条件）
        └── sensitivity / context condition（量化路径 B 并入此处）
```

各位置的论文表述：

- **SPA / MiniSplat**：第三方工作（GaussianSpa，CVPR 2025；Mini-Splatting）
  的采用与锚点版改造，方法节引用，明确不算贡献。30k 协议下 SPA 实际行为
  （锚点 889k→803k，约 −10%）要如实描述。
- **次模覆盖选择**：紧预算专用组件（tight-budget specialization），不包装成
  全曲线方法。机制故事：预算越紧，"选哪些锚点"越重要；预算宽松后选择策略
  的收益迅速消失（六格：紧档双种子正，松档一正一负）。
- **融合剪枝**：防坍缩安全组件。论文定位采用以下表述：
  > 基础 SPA 剪枝在强压缩条件下可能出现覆盖结构坍缩，我们加入受约束的
  > 感知调制以限制危险的剪枝重排序；该机制用于提高极端预算下的鲁棒性，
  > 而非作为独立 RD 增益来源。
  不再为其追加 GPU 消融。它的价值已经兑现：弄清了"看起来合理的感知剪枝
  为什么会崩、如何限制它不崩"（六点记分板均值 −0.06 dB、判定跑差 0.09 dB
  未过门的完整记录是论文负结果素材）。
- **主贡献**：渐进分层码流——全锚点粗层从最早阶段就有完整空间结构，逐层
  增强，解码端零边信息，量化步长可 100% 重建（S3 已验证）；这与"先传
  10% 锚点再传 20%"的选择式路线有本质区别（S2 已证明选择式有天花板）。

## 2. 资源优先级（从高到低）

| # | 事项 | 第一步与判定 |
| --- | --- | --- |
| 1 | **真实分层码流落地（S4）** | L0..Ln 真正独立可解，记录真实累计字节，出"累计字节 → PSNR"曲线。这张曲线出来，渐进 3DGS 压缩的故事才算立住；同时实测分层相对选择式的真实体积代价（当前只有静态编码器记账 1.75× 的归一化估算） |
| 2 | **分层条件熵模型**（渐进 C 家族 + 量化路径 B 合流） | 粗层解码结果 + 局部统计/敏感度作为条件，编码增强层。目标：把 1.75× 的静态记账压向学习式水平 |
| 3 | **HAC++ 公平 RD 补点 / BD-rate 修正** | 先登记脚本 v2 更正行；再用 r3 两个修正点（27.39 @ 10.52、27.81 @ 19.94）重算。重算前需决定曲线版本：旧码一致版（内部协议一致）或混码修正版（更新但跨码，波散 0.215 dB 需标注）；高码率段（26–40 MB）补我方实验点 |
| 4 | 量化路径 B 最小实现 | 并入第 2 项推进，不再单独立项 |
| 5 | 删后恢复探索 | 三臂设计已就绪，一次 30k 训练定去留（预注册门：恢复组 ≥ +0.15 且显著高于随机对照） |
| 6 | 次模收尾 | 写论文素材；不投新 GPU 消融（可选第三种子除外） |
| 7 | 融合剪枝 | 停止投入；保留现有记分板与机制分析 |

## 3. 数字纪律（即刻生效）

1. **"+0.521"停用作头条数字**：其基准（λ=0.004 s42 base 26.98）是后来确认
   的崩溃格，干净复跑 27.39 后该格增益约 +0.11（跨码，需注明）。对外引用
   改用 s104 干净对：+0.143（同尺寸）/ +0.219（基准大小上插值）。总解析
   报告需补更正条目。
2. **BD-rate 冻结**：三套数字并存（脚本 v2 −25.3%/−34.2% 未登记；CSV 旧版
   +1.5%/−16.2%；09-04 +2.5~2.8%），现行版两条曲线重叠区仅 0.02 dB、重度
   依赖外插。**重算并登记前，任何 BD-rate 数字不进论文与结论性表述。**
   对外现状用平价点：base r100 27.86 dB @ 15.24 MB 对 HAC++ 27.84 dB @
   20.03 MB，同画质体积约 −24%。
3. 既有纪律不变：单格差 < 0.2 dB 不作数；结论需双种子。
