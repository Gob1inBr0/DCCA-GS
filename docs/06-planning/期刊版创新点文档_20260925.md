## 创新点 1（主贡献）：锚点式 3DGS 压缩的渐进分层码流

**主张**：首个在锚点式三维高斯压缩上实现的、零边信息的、真实可截断的
质量分层码流；配套实测了两种渐进范式（选择式 vs 分层式）的取舍。

**它是什么**（一段话说清）：把已训练场景的量化符号按精度分位面组织——
基层传所有锚点的粗量化值（场景完整、属性粗糙），增强层传修正残差；
文件在任意层边界截断都是合法可解的前缀；解码端从已解码数据重算全部
量化参数与编码上下文，码流不携带量化参数表。

**支撑证据**（全部实测，指向 CSV/产物）：

1. 范式取舍有预登记比较：排序增益真实（+5~6 dB 对乱序）但选择式有结构性
   天花板（前 50% 锚点差 2.34 dB）；全锚点 4 倍粗化只损 0.60 dB → 分层为主。
2. 真实码流文件与逐块位精确验证（1-78、2-06 两场景的 `.bin` 与曲线）。
3. 分字段粗化档位消除粗化失真（15.75 MB 处 25.24 dB 对统一阶梯 21.89）。
4. 细层用已解码粗层作上下文：每场景省 1.9–2.3 MB。
5. 零边信息端到端验证：量化步长解码端重算逐符号一致（100%/99.999%）。
6. 跨数据集泛化：管线在 2-06/4-10 上零修改运行。

**诚实边界**：分组频率统计表版编码器比学习式上下文编码器贵约 40%
（渐进能力的当前代价）；几何坐标不分层；用 MLP 拟合码表的尝试在真实
逐位框架中为负结果（+35–38%），收益兑现需换训练目标，列为后续可选。

**相邻工作差异**：PCGS（训练日程副产品，我们不动训练）、ProGS（空间粗细，
与我们的数值精度正交）、Octree-GS（多文件多细节层次，我们单文件截断）、
JPEG2000/可分级视频（思路同源，首次入锚点式 3DGS）。

## 创新点 2：覆盖感知的剪枝安全机制（组件化降级）

**主张**（按主轴表述）：基础剪枝方法（GaussianSpa 的锚点版改造，第三方
方法如实引用）在强压缩条件下可能出现覆盖结构坍缩；我们加入受约束的感知
调制以限制危险的剪枝重排序，**用于提高极端预算下的鲁棒性，而非独立
RD 增益来源**。

**证据状态**：防坍缩有效（1.56 dB 崩溃被消除）；但六格记分板显示其均值
−0.06 dB（正常预算下无增益）；组件拆分消融按主轴不再追加 GPU 投入。
**它为何仍值得写**：负结果链完整——"看似合理的感知剪枝为何会崩、如何
限制它不崩"的机制分析（含逐点记分板与判定记录）是论文的分析节素材。

**不再投入**：无进一步训练计划。

## 创新点 3（组件）：紧预算专用的次模覆盖选择

**主张**：预算越紧，"选哪些锚点"越重要——次模覆盖贪心在紧预算档有
双种子一致的增益；预算宽松后收益消失。**定位为紧预算专用组件，不包装
成全曲线方法**。

**证据状态**：六格证据（紧档双种子正、松档一正一负）；同参复跑波散
0.185 dB 已实测；"重初始化开销是否吃掉收益"的边界已量化。表述按主轴
执行（含 "+0.521" 停用、改用干净配对数字）。

**不再投入**：写论文素材；不投新 GPU 消融。

## 创新点 4（机制组件，已定型为工程组件）：解码端可复现的内容自适应量化

**主张变化**：ICRA 版声称 −0.41 dB（该数字经溯源无可追溯实验对，且
v3 消融矩阵判定不成立）；期刊版改述为"小而一致的增益"（三个同代码
干净对全部方向一致为正，均值 +0.059 dB，两格帕累托占优），**从贡献
声明除名、作为工程组件保留**。

**支撑证据**：6 格消融矩阵（6/6 有效性验证通过）；+0.41 dB 溯源结论
（无出处数字）；四领域量化机制调研（四领域独立收敛：连续逐锚点解码端
步长乘子无成功先例）。

**后续路径**：量化改进并入渐进方向的上下文条件（已完成条件化部分）。

## 支撑性贡献（方法学，贯穿全文）

1. **运行来源记录制度**：每次训练把代码版本号、工作区状态、完整启动命令
   写入结果目录（provenance.txt），任何数字可审计到产出它的代码。
2. **数字纪律**：单格差 <0.2 dB 不作数（实测复跑波散 0.185–0.215 dB 支撑）；
   结论需双种子；实验数字唯一事实源为 experiments.csv。
3. **校验锚点机制**：分层渲染实验先渲满精度档，不达已知质量整批作废
   ——本轮两次拦截坏数据。
4. **无出处数字溯源实践**：ICRA 的 0.41 dB 声明被溯源为无实验对支撑
   （连同 v1.1 审计的调和失误一并记录）。
