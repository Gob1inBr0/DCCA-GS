## 2. 对审计三个问题的裁定

### 问题① "接线断路、运行代码丢失" —— **断路属实，"丢失的接线曾生效"不属实**

- 断路确认：消费点经 `getattr` 默认 False，无拷贝即静默降级为纯覆盖（与 fusion 门控 bug 同类：静默失效）。
- 但审计推断"当时跑 A3 的代码里有现在丢失的接线"被 E3 **证伪**：A3 崩溃 run 自己的 ckpt 记录加权旗标为 False。接线不是丢了，是**从未被写过**。
- 审据"PruneLog 轨迹从早期分叉→加权生效"的推断不成立：两臂 cycle=1 的 N 已差 591（909342 vs 908751），这是 CUDA 原子操作非确定性从第 0 步累积的正常现象，与目标函数无关。
- **A2(27.806) 与 A3(26.985) 是同配置、同种子、同代码目录、同秒发射的两个 run，差 0.82 dB。**

### 问题② A4 空操作 —— **属实，采纳**

覆盖约束只在非次模 topk 分支施加（贪心分支从首个实现提交起就绕过），A4 ≡ A2。
A2 的增益由构造不可能来自该约束。A4 取消（主报告 v1.2 已改）。

### 问题③ v2 公式不一致 —— **属实，但无历史影响**

实现是"用 (1+sens) 替换像素质量"（更极端），文档是"相乘"。由于加权从未运行，
该不一致没有污染任何已登记结果。修复分支按文档公式实现（`mass × (1+sens)`）。

### 审计的其他失实（记录在案）

- "懒贪心的堆实现是标准正确形式"——实际实现是**分批近似贪心**（按首轮增益
  排序、批内取 top），不是懒贪心堆。近似质量未被测试覆盖；新单测覆盖
  kappa=1 精确性、预算一致性、加权方向性三点。

## 3. 修正后的结论

1. **A3 三行重标为 A2 同配置复跑**（CSV 已补注）。G1 可把它们当 A2 复跑样本用：
   λ0.004 三个同参值 27.504 / 27.417 / 27.405（紧凑）；λ0.002 两个同参值
   27.806 / 26.985（相差 0.82）。
2. **贪心+咬合预算臂存在复跑不稳定性**（至少在 λ0.002）：对照 topk 臂复跑噪声
   ±0.058、A2 臂 s104/s104r 复跑差仅 0.031，同参 0.82 的偏离是异常重尾。
   G1 的 λ0.002 格误差棒必须按此放大；"中间带"判定不变（承重格在 λ0.004）。
3. **"早期敏感度监督崩溃"与 H2"延迟恢复 84%"双双撤回**：前者是复跑异常被误读，
   后者的对照不是处理效应、且跨代码状态。延迟臂数字保留为描述性记录。
   "敏感度监督无稳定 RD 价值"的大结论不受影响（I6-off、A1、R1/R2/SPB/Fisher/W
   链条完整，与 A3/H2 无关）。
4. **w020 的 27.078（"multi-restart 异常"）与此同科**：本管线偶发同参崩溃的
   第二个独立样本。根因未明（候选：provider OOM→EMA 链、贪心×预算反馈放大
   初始扰动），值得专门排查——这直接决定贪心臂结论的置信区间。
