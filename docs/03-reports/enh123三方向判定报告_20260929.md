## 0. 一句话总览

**三个"还没试过"的提升杠杆——把标志概率换成小 MLP、把增强层条件表换成
学习式上下文模型、把基层粗化档从 8 倍提到 16 倍——在预登记门下全部
证负**：生产复合条件表在全部大字节流上已贴近条件熵；P0 的下限被固定
几何负载钉死。剩余提升空间不在概率模型和粗化档位，只能在几何编码或
锚点表示本身。同时这轮把三条工具链（两臂 A/B 驱动、独立前缀解码器、
通用阶梯参数+扫描器）建完并经受了实战检验。

## 1. 背景与预登记

9-28 盘点未尝试方向后定了三条，判定门全部在跑之前写死：

| 方向 | 一句话 | 预登记门 |
| --- | --- | --- |
| 1. 标志 MLP 接入生产码流 | offset 细化标志（"这个残差是否非零"）的概率由 25 KB 小 MLP 按锚点给出，替代静态表查表 | 净省 ≥10%（offset 增强层，权重计入），两臂 PSNR 逐前缀一致 |
| 2. 增强层学习式上下文 | 用 MLP 按已解码符号预测每道是非题的概率，替代"组×粗值桶"静态表 | 验证侧净省 ≥15%（真实编码比特，权重计入），跨场景同号 |
| 3. 基层 16× 粗化 | 属性阶梯从 8 倍起步提到 16 倍起步，把渐进曲线起点压进 7 MB 以内 | P0 ≤7 MB 且落差 ≤1.5 dB，无倒挂，满精度画质不变 |

方向 2 有两条入册教训作为设计前提：S4（学习式直出概率）对生产表零增益；
探针 v3 的 45.9% 是对"仅按组"弱表测的，不能外推。因此本轮协议的核心是
**同构基线**：静态基线就是生产条件表本身（同格子、同后备链、同几何尾），
训练侧拟合、验证侧出数、真实区间编码器计比特。

## 3. 方向 1：标志 MLP 两臂 A/B —— FAIL，关闭

**做法**：同一编码器跑两臂，唯一差别是 `--s5-offset-mlp` 开关（只改
offset 增强层的"是否非零"段概率来源；MLP 权重 20.3 KB 随码流传输）。

| 臂 | offset 增强层字节 | 满精度画质 |
| --- | --- | --- |
| 基线（静态表） | 3.7499 MB | 27.797 dB |
| MLP 臂 | 3.7658 MB（含权重） | 27.797 dB（逐前缀一致） |

净省 −0.98%（门 +10%），**FAIL**。分层看：L1 省 368 字节（≈0），L2/L3
分别倒贴 4.4 KB / 11.8 KB——层越细（残差越小），静态表的"组×桶"条件
越够用，MLP 连毛收益都拿不到。

**结论**：探针 v3 的 45.9% 相对弱表成立、相对生产表不成立——9-26 入册
的同构教训被整编码器实验再次确认。s5 生产接入证负关闭（负结果台账
第二次入册：学习式标志概率线）。

## 4. 方向 2：字节审计 + 五探针 —— 全 FAIL，方向永久关闭

### 4.1 字节审计（先看清 3–6 MB 差在哪）

给编码器加 `--stage-audit`：逐块把字节归因到三段决策。

| 决策段 | 字节 | 占比 |
| --- | --- | --- |
| A 段（是否非零） | 14.62 MB | 51% |
| B 段（符号） | 6.34 MB | 22% |
| C 段（幅度延续） | 7.52 MB | 27% |

最大的单一流：feat L0 标志 2.66 MB、feat L1 标志 2.37 MB、feat L3
标志 2.27 MB、scaling L0 幅度 3.35 MB、offset L0 幅度 2.21 MB。探针
全部打在这些流上。

### 4.2 五个探针的结果

协议：锚点级 90/10 划分（划分先于任何拟合），静态基线=生产表训练侧
拟合（含后备链），真实区间编码比特，生产表（全量拟合、略偏乐观）作
参照列。

| 流 | 决策数 | 毛省 | 净省（含权重） | 判定 |
| --- | --- | --- | --- | --- |
| feat L0 标志 | 2180 万 | 16.0% | **+6.4%** | FAIL（门 15%） |
| feat L1 标志 | 2180 万 | 2.1% | −9.6% | FAIL |
| offset L1 标志 | 2040 万 | 6.5% | −26.1% | FAIL |
| offset L1 幅度 | 210 万 | 89.9% | −1347.6% | FAIL |
| scaling L0 幅度 | 1.56 亿 | 6.4% | −1.3% | FAIL |

三个观察：

1. **最接近过门的是全流最大的 feat L0 标志（净 +6.4%）**——离 15% 仍差
   一倍多。学习式上下文不是完全提不出信号，是提出的信号付不起自身的
   权重和推理复杂度。
2. **生产表参照列与训练侧基线在每条流上都重合**（例：feat L0 两者都是
   0.266 MB）——同构协议成立，判定测的是生产表本身，不是测量装置。
3. offset L1 幅度流只有 2.1 MB 且毛省 89.9%，但权重比流还大——教训：
   学习式模型只对 MB 级流有意义，小流永远该用静态表。

**结论**：生产"组×粗值桶"复合条件表在全部大流上已贴近条件熵。学习式
上下文方向第三次证负，按设计文档的预登记条款**永久关闭**；静态表保留。

## 5. 方向 3：基层 16× 扫描 —— 无配置过门，独立杠杆关闭

给编码器加 `--ladder` 通用阶梯参数（2 的幂、严格递减、末位必须 1，
解析器拒绝一切破坏伸缩重建的输入），扫描四配置：

| 配置 | P0 | 满精度 | 判定 |
| --- | --- | --- | --- |
| 基线 8× | 16.60 MB @26.007 dB | 30.86 MB @27.797 | 参照 |
| feat+offset 16× | 13.37 MB @22.914 dB | 32.04 MB @27.797 | FAIL（落差 3.09 dB > 1.5） |
| 16× + scaling 4× | 12.86 MB @22.896 dB | 32.07 MB @27.797 | FAIL |
| 仅 offset 16× | 15.65 MB @25.273 dB | 31.18 MB @27.797 | FAIL（且 >7 MB） |

**结构性发现：P0 的下限不由属性字节决定**。该场景固定几何负载（锚点
坐标、mask 等）约 6–7 MB，属性字节全部砍光也进不了 7 MB 以内；而 16×
粗化最多省约 5 MB 属性字节、代价 3 dB。**"7 MB 以内起步"需要动几何编码
或锚点表示本身**（例如几何量化/投影/剪枝联动），属另立方向，本轮不排期。
16× 粗化作为独立杠杆证负关闭。

### 更正（2026-10-01）

本节"结构性发现"、§0 概览末句及 §6 中"P0 的下限被固定几何负载钉死"
"下限在几何侧不在属性侧"的说法**有误**。
原文按不删除原则保留，正确事实如下。出处：逐块字节归因产物
`analysis/enh123/stage_audit/audit.json`（对 1-78 λ0.0005 基线码流
`ph0c_base_r085_lam0005_s42`、681,228 锚点）；同样的两个数字在
`analysis/s2_prefix_sweep/c25_real_bitstream_v2.json` 中独立出现，
互相印证。

1. **P0（16.60 MB）的构成以基层属性字节为主**：基层属性三块合计
   14.25 MB（feat_L0 5.48 + scaling_L0 3.93 + offset_L0 4.84），占
   86%；几何（锚点坐标 G-PCC）实测 1,289,840 字节 = 1.29 MB，占 8%；
   固定负载（哈希网格、解码网络、边界、掩码）1,057,490 字节 =
   1.06 MB，占 6%。
2. **16 倍粗化档位翻倍只省约 3.2–3.7 MB 基层属性字节（约 22–26%）**
   ——基层属性的熵并不随步长翻倍而减半，粗化不敏感的部分占了约四分之
   三。这才是"进不了 7 MB"的真正原因，与几何负载无关。
3. 几何 + 固定负载合计约 2.35 MB：**即使把这两块全部砍光，也只能把 P0
   从 16.60 MB 降到约 14.3 MB**，远到不了 7 MB 以内。
4. **真正能同时缩小全部三块的杠杆是锚点数量（训练侧稀疏化预算）**：
   几何、固定负载、基层属性三块的字节都随锚点数线性变化。
5. 由此，**"换几何编码方式"作为剩余提升空间的表述降级**：几何编码的
   收益上限约 1.2 MB；低码率起点的主要杠杆是锚点预算扫描（训练侧稀疏化
   比例 r 从 0.85 往下调）。

原文"约 6–7 MB 固定几何负载"的错误来源：把"基层属性字节的粗化不敏感
部分"（粗化档位翻倍后仍省不掉的那部分属性字节）误归因为了几何负载。

## 6. 跨方向的结构性结论

三条杠杆指向同一个事实：**静态条件表编码器的信息提取已经到顶，P0 的
下限在几何侧不在属性侧**。与 HAC++ 的 3–6 MB 满精度差距此前被归因于
"静态表比学习式编码器贵"，本轮证明这个差距**不能靠在静态表架构内换
概率模型来消除**——要消掉它只能换编码架构（那正是主贡献"可截断、零
边信息"要保护的约束），或者接受它并靠训练侧组件（B3 已拿 +0.26/+0.92）
和独占区（<12.1 MB）讲故事。

对期刊版的影响：

- 主贡献叙事不需要改：三个证负反而补强了"为什么用简单条件表"的辩护
  （三路尝试的完整负结果链是现成的分析节素材）。
- "剩余杠杆"清单收敛为一条：几何编码/锚点表示（未立项）。
- 负结果台账新增三条，全部有 CSV 行、JSON 产物、分支提交三重出处。
