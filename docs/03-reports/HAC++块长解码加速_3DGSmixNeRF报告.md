# HAC++ 算术编码并行块长：解码时间 vs 码率的权衡（3DGSmixNeRF 项目报告存档）

> 存档说明：本报告来自姊妹项目 3DGSmixNeRF（HAC++ 基座帕累托改进研究）。所有者指令（2026-10-18）将其存档于本仓，**不做对外提交**（HAC++ 官方仓库的 issue/PR 由所有者决定是否发出；英文草稿在 3DGSmixNeRF/docs/hac_chunk_size_issue_draft.md）。
> 数字出处：3DGSmixNeRF/docs/data/experiments.csv（retest_* 行，2026-10-18 空闲机协议口径）。
> 协议：HAC++ 官方配置（λ=0.004、30k 迭代、种子 42、11 景标准基准：Mip-NeRF360×7 + Tanks&Temples×2 + DeepBlending×2），A100 40GB PCIe 单卡。
> **注意：以上为 3DGSmixNeRF 协议实测数字，与本仓 experiments.csv（DCCA 协议）不得混进同一张表比较。**

## 1. 结论一页

HAC++ 的 GPU 算术编解码器有一个写死的并行块长参数 `chunk_size_cuda = 10000`（utils/encodings_cuda.py，每个 CUDA 并行块处理的符号数）。把它改成 **1000**：

- **解码时间 −72.0%**：11 景合计 254.8 s → 71.2 s（空闲机串行协议；单景最慢 bicycle 51.1 s → 15.2 s）；
- **码率 +1.27%**：72.24 MB → 73.15 MB（确定性量，跨种子 +1.43/+1.44% 一致）；
- **解码值逐位一致（bit-exact）**：量化符号由训好的模型决定，分块只改变解码并行度，PSNR/SSIM/LPIPS 完全不变（11/11 景验证）；
- **编码时间同步下降 40–57%**（例：bonsai 22.2 s → 9.6 s）；
- 不重训、不改模型、一个参数。

这是"解码时间 vs 码率"轴上的帕累托改进，文献中（HAC/HAC++/FCGS/PCGS 系列）无人报告过这条权衡曲线。

## 2. 机制

GPU 算术编码把长度 N 的符号流切成 N/chunk 个独立子流并行编解码。基座默认 10000 使单批符号（3 万级）只拆出 3 块并行，GPU 几乎串行。减小块长 = 提高并行度；代价是每个子流的终止码与字节对齐开销（每块约 4.9 字节）。

## 4. 闭式理论（可直接按部署目标求解）

两个定律对五点扫描（10000/3000/1000/300/100，bonsai 与 truck）拟合优度 R²=1.0000：

1. **码率**：ΔBytes = c · N_sym · (1/chunk − 1/10000)，**c ≈ 4.9 字节/块**（每块终止+对齐开销）。
2. **解码时间**：T_dec ≈ 2.9 ms × chunk + 固定开销（每块内符号串行解码）。

两者联立给出最优块长闭式 chunk* ∝ √(c·N/(λ·t))；实测膝点 ≈1000。继续压到 100 会过头——块数过多、固定开销主导，truck 解码时间反弹（4.65 s@300 → 5.50 s@100）。

因此该参数是**部署期的"带宽 vs 延迟"旋钮**：用任一景拟合出 c 与每符号串行时间后，可按目标延迟或带宽预算直接解出块长。

## 5. 互通性注意（改默认值前必读）

块长参与码流分段：用不同 `chunk_size_cuda` 编出的码流**互不兼容**，编码端与解码端必须约定同一值。官方发布管线是自编自解闭环，内部自洽；只有"跨设置混用码流"会受影响。若要消除该限制，可把块长作为参数写进码流头。

## 6. 复现要点

1. 训练任一景（官方配置）或复用已训模型；
2. 编码与解码两步都设环境变量 `HAC_CHUNK_CUDA=<chunk>`；
3. 配对测量脚本：3DGSmixNeRF/code/scripts/chunk_sweep.py（重编码 → 码流+耗时，重解码 → 墙钟 + bit-exact 指纹校验）；
4. 硬件：A100 40GB PCIe，torch 2.7.1+cu128；不同 GPU 的绝对时间不同、结论方向应一致（c 与串行时间需重拟合）。

## 7. 与本仓的关系

- 机制与闭式理论对任何基于官方 HAC/HAC++ 检出的代码同样适用；**具体数值（−72%/+1.27%）是 3DGSmixNeRF 协议与硬件的实测，用于本仓结论前需按 DCCA 自身协议复测**。
- 判定门槛参照：码率代价 +1.27% 远小于常见的码率-质量操作点间距（如 HAC++ 论文 highrate/lowrate 档间距 2–3 倍），且解码值逐位一致，属于无画质损失的纯延迟改进。
