## 0. 摘要（给赶时间的读者）

1. 我们完整训练并压缩了 21 个模型，系统测试了 6 类"剪枝时怎么挑锚点"的
   新方法。每个方法在实验**之前**就写死了及格线，关键结论用两个随机种子
   各跑一遍来防止碰运气。
2. **这一轮最重要的产出不是某个过线的新方法，而是弄清了剪枝的杠杆在哪**：
   在锚点压缩加预算限制这套体系里，精细地改进单个锚点的打分，收益几乎
   为零；真正影响码率-画质关系的，是**预算什么时候开始执行、压到多狠、
   按什么目标来选锚点**。所有 0.2 dB 以上的真实变化全部来自这类结构性
   改动；所有打分类的小改进，没有一个取得超出正常波动范围的正收益。
3. 次模覆盖选择是唯一值得继续研究的选择侧想法：在预算最紧的 λ=0.004，
   两个随机种子下都是正增益（+0.52 / +0.14）；换成相同文件大小再比，
   增益还更大一些（+0.22）。但三个 λ 加起来的总增益 +0.107 没有达到
   +0.15 的及格线，判为"介于达标与不达标之间"，定位是**预算最紧时的
   专用组件**，不是全码率通用的方法。
4. 敏感度信号（衡量"动这个锚点对画面伤害多大"的统计量）的证据链：
   信号能学到（排序相关存在）、但把监督完全关掉只掉 0.021 dB（在正常
   波动范围内）——**信号可以被测量，不等于信号有压缩价值**。
   之前认为的"开局就启用会崩 0.75 dB"经查证撤回：那个崩溃的实验其实是
   同一参数下重新运行碰上的异常，不是敏感度造成的（见 3.5 节）。
5. 单随机种子的结论会翻转（融合方法在种子 42 下 +0.32，换种子 104 后
   约等于 0；Fisher 方法 +0.045 换成 −0.45）。在 0.1 dB 量级的效应上，
   **两个种子是底线**。这次还发现：同一参数重新运行本身也可能差 0.8 dB
   （发生在次模贪心的实验组），重复运行的波动要按实验组类型分别测量。
6. 下一步：主线转向量化路径（此前验证过 0.41 dB 量级的杠杆）；选择侧
   以"负结果的系统证据"写成论文素材。GPU 上待用户确认的实验见第 6 节。

## 1. 背景：任务、系统和这一轮要回答的问题

### 1.1 任务与系统

**任务**：三维场景压缩。输入是一段多视角照片，系统用三维高斯泼溅
（3D Gaussian Splatting，3DGS——用几十万个带颜色、透明度、大小的椭球
拼出场景，能实时渲染）表示场景。原始文件几百 MB，目标是压到几 MB 到
二十几 MB，画质尽量不掉。

**锚点表示**：直接压缩几十万颗高斯太贵。我们沿用 HAC++ 的做法：把高斯
组织到约 50–80 万个稀疏的**锚点**上（锚点是场景中的三维控制点，每个锚点
存一份特征向量和小网络权重，解码端用小网络从锚点"长出"周围的高斯）。
文件大小基本由锚点数量和每个锚点的属性比特数决定。

**压缩管线**：训练 30000 步 → 属性量化 → 熵编码（entropy coding，按出现
概率把数字压成最短的比特流）→ 解码端逐位还原。解码端不需要任何额外
文件（零边信息：所有解码端要用的信号都能从码流里重算出来）。

**剪枝**：训练过程中不断删掉贡献小的锚点来换体积。"哪些锚点该删"由一个
分数决定。**这一轮所有实验都在回答同一个问题：这个分数还能不能做得更
聪明？**（答案基本是"不能"——但"为什么不能"反而更有价值，见第 4 节。）

### 1.2 评价方法

- **RD 曲线**（rate-distortion curve，码率-画质权衡曲线）：横轴是压缩后
  文件大小（MB），纵轴是画质。两个方法比，同大小看谁画质高。
- **PSNR**（峰值信噪比）：画质指标，dB 越高越好，0.1 dB 以上才谈得上
  可感知。
- **λ**（拉格朗日乘子）：训练时画质与体积的权衡系数。λ 越大越省体积、
  画质越低。三档取值：λ=0.004（文件最小 = 低码率端、预算最紧）、
  0.002（中间）、0.0005（文件最大 = 高码率端、最保真）。三档各出一个点，
  连起来就是一条 RD 曲线。
- **同码率比较与 BD-rate**：两个方法的点大小不完全相同，直接比画质会
  混入"多花了比特"的贡献。同码率比较（matched-rate）是把一条曲线插值到
  另一条的文件大小上再比；BD-rate 是把两条曲线在公共区间内积分成一个
  数字（负值 = 同画质更省码率）。本报告从 v1.1 起对关键结论同时给原始
  点差和这两种算法的结果。

### 1.3 这一轮的实验安排

上一轮的结论：融合剪枝只值"防止崩溃"，不值增益；且发现训练后半段预算
几乎不执行。于是这一轮（期刊版第二轮，jr2）分波次系统测试，每波对应
一条预注册的及格线：

| 波次 | 方向 | 及格线 |
| --- | --- | --- |
| Wave 0 / Phase 1 | 次模覆盖选择（换选择目标） | G1 |
| Wave 1 | 码率感知剪枝（分数除以比特数 / 按比特定预算） | G-R1, G-R2 |
| Wave 2 | 精修信号：敏感度/比特、Fisher 二阶、融合权重 | G-SPB, G-F, G-W |
| Wave 3 | 对照与扫描：敏感度全关、预算窗口长短 | （模式 2 证据链、B1 扫描） |
| Wave 4 | 两个机制判定：放松预算能否修复高码率端异常、延迟启用敏感度 | H1, H2 |
| 收尾 | 关键实验组补第二个随机种子 | （验证可复制性） |

## 2. 实验制度：为什么这些数字可信

### 2.1 统一规则

- **场景**：全部在开发场景 1-78 上判定（1050 张训练图、150 张验证图）。
  只用一个场景的局限和补法见 5.3 节。
- **训练**：30000 步；第 15000 步做一次深度重初始化（用深度图把锚点
  重新铺到表面上，之后进入训练后半段）。
- **预算压缩设置（r_post=0.85）**：上一轮发现训练后半段预算基本不执行。
  修复后，后半段把锚点数线性压到重初始化时的 85%，让"删哪些锚点"的
  决策在后半段真实发生。本文 jr2 实验除特别注明外都用这个设置。
- **体积算法**：压缩后九项字节分解求和（MB）。
- **正确性**：每次运行必须通过逐位还原校验（编码再解码完全一致），
  否则作废。

### 2.2 预注册及格线

- **预注册**：每个实验的及格线在开跑前写进设计文档，跑完按原文判定，
  不许事后改标准（防止"多跑几个挑最好看的"）。及格线的数值本轮没有
  事后修改；执行位置有一处调整并已记录（R1/R2/SPB 预注册写在 λ=0.004，
  实际在 λ=0.002 执行，原因记录在异常排查文档里）。
- **两个随机种子**：关键结论用种子 42 和 104 各跑一遍。种子影响初始化
  和数据顺序，同配置换种子结果会波动。
- **正常波动范围**：同一配置重复运行的差异实测为 ±0.058 dB。小于这个
  量级的差异不能当结论。正式及格线取 ±0.10 dB，留余量。
  （v1.2 补充：这个 ±0.058 是在普通打分实验组上测的；次模贪心的实验组
  重复运行波动大得多，见 3.1 节。）

### 2.3 基准数字（场景 1-78，30000 步，压缩后）

| 配置 | PSNR @ 大小 |
| --- | --- |
| 旧协议基准（后半段预算不执行）λ=0.004 / 0.002 / 0.0005 | 27.511 @ 11.72 / 27.750 @ 15.05 / 27.953 @ 23.60 |
| 预算压缩后的基准 λ=0.004 | **26.983 @ 11.08**（比旧协议低 0.53） |
| 预算压缩后的基准 λ=0.002 | 27.730 @ 14.45（旧代码）/ **27.695 @ 13.90**（新代码，本文默认基准） |
| 预算压缩后的基准 λ=0.0005 | 27.597 @ 21.44（**高码率端异常点**：比 λ=0.002 又大又差，见 4.4 节） |

注意第一行和第三行的对比：**预算真正执行后，基准在 λ=0.004 掉了
0.53 dB**——基准变得更容易受伤，这正是选择算法有发挥空间的地方，也是
次模增益出现在这一档的原因（见 3.1 节）。

## 3. 分波次结果与解读

写法说明：`27.504 @ 11.06` 表示压缩后 PSNR @ MB；对基准的差异写作
`+0.52 @ −0.02 MB`（画质差 / 大小差）。

### 3.1 Wave 0 / Phase 1：次模覆盖选择（及格线 G1）——介于达标与不达标之间，唯一的正信号

**想法**：原来的剪枝分数给每个锚点独立打分再求和，天然看不见冗余——
两个锚点盖住同一批像素，会各得一份高分。次模覆盖选择把目标换成
"保留的锚点集合盖住的像素总量最大"：每个像素只算一次，重复覆盖不加分
（次模是这类"加一个成员的收益随集合变大而递减"的数学性质）。求解用
贪心算法（每一步选当前新增覆盖最大的锚点），有 1−1/e 的理论保证。

**结果**（A2 实验组 = 纯覆盖目标；逐格对同 λ 同种子基准）：

| λ | 种子 42 | 种子 104 | 该 λ 平均 |
| --- | --- | --- | --- |
| 0.004（预算最紧） | 27.504 @ 11.06（**+0.52 @ −0.03**） | 27.405 @ 11.28（**+0.14 @ −0.45**） | **+0.332** |
| 0.002 | 27.806 @ 14.43（+0.08 @ −0.02） | 27.676 @ 14.50（−0.05 @ +0.05）* | +0.011 |
| 0.0005 | 27.719 @ 20.55（+0.12 @ −0.89） | 27.280 @ 20.19（−0.17 @ −0.73）** | −0.024 |

\* λ=0.002 的种子 104 基准没跑过（登记表里缺这一行），这格借用了种子 42
的基准，按"约等于 0"读。\*\* λ=0.0005 的两个基准都落在高码率端异常区
（4.4 节），这一档的所有比较都不可信，按缺失处理。

**判定：介于达标与不达标之间。**总增益的算法：六个格子各自对同 λ 同种子
基准求差再平均，得 **+0.107 dB**——没到 +0.15 的及格线，落在
0.05–0.15 之间；一致性也不够（只有 λ=0.004 两个种子同号，λ=0.0005 两个
种子符号相反且该档数据不可信）。

**（v1.1 修正说明）** v1.0 写的总增益 +0.16 是算错了：λ=0.004 的种子 104
那一格错用了种子 42 的基准（26.983），把 +0.14 算成了 +0.42。改用同种子
基准后总增益是 +0.107。判定不变，数字依据修正。

**（v1.2 修正说明）** 原来认为"敏感度加权的覆盖目标（A3 实验组）比纯覆盖
差、在 λ=0.002 直接崩到 26.985"——这个说法撤回。检查两个实验的
checkpoint 里存的完整配置后发现：A2 和 A3 唯一的差别是一个模式字符串，
而这个字符串没有任何代码真正使用它；加权开关在两边都是关闭的。
**A3 的三行结果其实是 A2 同一参数的重复运行**。由此暴露一个新事实：
**次模贪心的实验组，同一参数重新运行在 λ=0.002 相差了 0.82 dB**
（27.806 对 26.985，同种子、同代码、同一秒启动）——所以 G1 在 λ=0.002
那一格的误差范围远大于 ±0.058。λ=0.004 有三个同参数的运行
（27.504 / 27.417 / 27.405，很集中），结论主要靠这一档支撑。

**同码率复核（v1.1 新增）**：担心"+0.14 里有多少只是多花的比特"——实际
相反，次模的点全部**又小又好**，按相同文件大小比只会更强：

| 比较方式 | 数字 |
| --- | --- |
| 种子 42，紧/中码率区间（11.08–14.43 MB）BD-PSNR | **+0.30 dB** |
| 同区间 BD-rate | **−12.0%**（同画质省 12% 码率） |
| 种子 104，在基准的文件大小（11.73 MB）上插值 | **+0.22 dB**（原始点差 +0.14） |

**为什么增益集中在 λ=0.004**：这是唯一一档"预算真正执行把基准打崩"的
参数（26.983，比 λ=0.002 低 0.75），删锚点的决策大量真实发生，"重复覆盖
不加分"才有差异化的机会。λ=0.002 预算松，本来就删不了几个，换什么目标
都一样。

**另一个计算方式（v1.2 补充）**：A2 实验组是带着融合方法的旗标启动的。
相对融合方法本身的净增益是 +0.08（种子 42）/ +0.21（种子 104），两个种子
都是正的。论文里应同时给"对基准"和"对融合方法"两种差值，不能只写 +0.52。

**原计划的 A4 消融实验（v1.2 取消）**：原想问"增益来自次模目标还是来自
'每格至少留一个锚点'的约束"。代码审计发现：这个约束只在非次模的普通
选择路径里生效，贪心路径从一开始就不施加它——所以"次模 + 关约束"和
A2 的有效配置完全相同，跑了没有任何实际效果。这个问题其实已经被代码
本身回答了：A2 的增益不可能来自那个约束（它从未参与过）。真想做有区分
力的消融，方向是"融合方法 + 关约束"（融合方法那条路径上约束是真实生效的）。

### 3.2 Wave 1：码率感知剪枝（G-R1 / G-R2）——失败

**想法**：熵模型训练时顺带统计每个锚点实际编出的比特数（滑动平均，
记 bits_ema；这个统计本身可靠）。两种用法：(R1) 剪枝分数除以比特数的
幂次（"性价比"视角）；(R2) 把预算直接定为总比特数。

**结果**（λ=0.002，对基准 27.695 @ 13.90）：
- R1：27.659 @ 13.67（−0.035 @ −0.23 MB）
- R2：27.582 @ 13.65（−0.113 @ −0.26 MB）

**判定：双双失败**。R1 在正常波动范围内；R2 明确为负。
**解释**：锚点之间的比特数差异远小于画质差异——省下的比特买不回错删的
画质。比特数适合当**分析工具**（看钱花在哪），不适合当**选择依据**
（决定删谁）。

### 3.3 Wave 2：三个精修信号（G-SPB / G-F / G-W）——全部失败

- **G-SPB（敏感度除以比特）**：把"每比特敏感度"当监督目标教给复杂度
  乘子网络。结果 27.612 @ 14.03（−0.082 @ +0.13 MB），失败。
- **G-F（Fisher 二阶）**：用梯度平方的滑动平均近似二阶信息（衡量"动这个
  锚点伤害多大"），替代一阶敏感度。种子 42 下 +0.045（波动范围内），
  种子 104 下 **−0.45**（相同文件大小上 −0.449，明确为负），两个种子
  平均 −0.20。失败，结论是**"无益、不稳定、偏有害"**——一个种子在波动
  范围内、另一个明确为负，跨种子不稳定本身就是负面证据。
- **G-W（融合权重）**：融合分数里敏感度权重从 0.3 扫到 0.1 / 0.2。
  0.1 时 +0.048（波动范围内），0.2 时 −0.22（那次运行中途重启过多次，
  数字偏低）。默认 0.3 最好。失败——分数已经在波动边缘工作，调权重
  没有空间。

**三个失败的共同原因**：都是"怎么打分"层面的小改。在 4.1 节的规律下
（结构性改动才有大效应），它们的真实效应本来就和波动同量级——单种子
实验在这个量级上等于抛硬币。

### 3.4 Wave 3：对照与扫描（I6-off / B1）——两个平静但重要的结果

- **I6-off（敏感度全关）**：把整套敏感度监督（复杂度乘子网络的训练信号）
  完全关掉。结果 27.674 @ 13.84，对基准 27.695 @ 13.90 只差
  **−0.021 dB，在波动范围内**。敏感度信号对最终画质没有可测的贡献。
  （这个实验第一次没跑完——具体原因存疑：启动旗标或压缩阶段内存盘
  写满——最终数字来自重跑的那次。）
- **B1（预算窗口长短）**：后半段预算收紧后保持 5000 / 10000 步
  （默认 2000）。+0.048 / −0.035，全在波动范围内——窗口长短不是杠杆。

### 3.5 Wave 4：两个机制判定（H1 / H2）

- **H1（放松预算修复高码率端异常）——证伪**。λ=0.0005 档基准异常
  （27.597 @ 21.44，比 λ=0.002 又大又差）。假设"异常是预算太紧造成的"，
  对策是取消后半段预算压缩（r_post=1.0，多留 16% 锚点）。结果
  27.562 @ 23.04：对及格线（≥27.80 @ ≤21.4）两项全败；对它要修复的
  异常基准是 −0.035 @ **+1.60 MB**——多花的钱没换来任何画质。假设不成立，
  原因要到量化一侧找（4.4 节）。
- **H2（延迟启用敏感度）——结论撤回（v1.2）**。这个实验组本身是干净
  有效的（27.583 @ 13.81），但它原来的故事（"延迟启用恢复了崩溃实验组
  84% 的损失"）经查证不成立：那个"崩溃实验组"（26.985）其实是 A2 同一
  参数重新运行碰上的异常（敏感度加权从未生效，见 3.1 节和调查报告），
  不是任何处理造成的；而且延迟实验组用的是新代码、崩溃那次用的是旧代码，
  两次的代码版本不同。"开局启用敏感度有害"目前只剩间接迹象（敏感度全关
  无损失、全部精修无正收益的反向佐证），没有直接证据。数字保留作记录；
  要重开这个问题，需要同一代码下的"立即启用 / 延迟启用"成对实验。

### 3.6 收尾：第二个种子的确认（fusA / fisher 的种子 104）——负结果可复制

- **融合方法 fusA**：种子 42 对同种子基准 +0.32（且文件更小，全面占优）；
  种子 104 原始差值 −0.07，但 fusA 的文件比基准小 0.71 MB——**换到基准
  相同的文件大小（11.73 MB）上插值后是 +0.002，正好中性**。结论：融合
  方法没有跨种子稳定的增益，维持"防崩溃组件、不是增益组件"的定位。
  （原始的 −0.07 里有一部分是文件大小差异造成的。）
- **Fisher 二阶**：对同种子融合实验组，相同码率点 **−0.45**；种子 42 那对
  是 +0.045（波动范围内）。两个种子平均 −0.20：Fisher 无益且不稳定。

这两个确认的意义在 4.3 节：单种子结论在这一轮的效应量级下**会翻转**，
两个种子不是奢侈品而是底线。

## 4. 横向规律：杠杆的位置和五条跨波次结论

### 4.0 这一轮最重要的产出：剪枝杠杆的位置

把全部结果放在一起，出现一条清晰的大小关系：

> **打分工程（反复改进单个锚点的重要性分数）的作用，远小于选择目标
> （用什么函数来选），后者又小于预算调度和量化结构（什么时候删、删多少、
> 量化怎么分配）。**

继续在 Fisher、梯度、敏感度、比特加权这类重要性分数上投入，出结果的
概率已经很低；真正控制码率-画质关系的是结构层。这不是设计失误，而是被
21 个模型系统测量出来的边界。它把研究问题从"能不能找到更聪明的剪枝
分数"升级为"**锚点压缩里选择信号的作用边界在哪里**"——后者是更有分量的
研究问题。

### 4.1 大效应全是结构性的，打分工程没有正收益

这一轮所有 0.2 dB 以上的真实变化：

| 变化 | 量级 | 类别 |
| --- | --- | --- |
| 次模贪心实验组同一参数重新运行的异常（λ=0.002） | −0.82 | 运行不稳定（v1.2 新发现） |
| 预算从 0.85 压到 0.55 | −0.378 | 预算（结构） |
| 次模 @λ=0.004（种子 42） | +0.52 | 目标结构 |
| 去掉深度重初始化 | −0.215 | 流程（结构） |
| 预算真正执行使基准 @λ=0.004 下降 | −0.53 | 协议（结构） |

而所有"怎么打分"的小改进（码率折扣、比特预算、敏感度/比特、Fisher、
融合权重、预算窗口）：**没有任何一个取得超出波动范围的正收益**——最大
正效应 +0.048 dB，远低于 +0.10 的及格线；其中四个还明确为负
（R2 −0.11、SPB −0.08、权重 0.2 −0.22、Fisher 种子 104 −0.45）。

原因：在"预算限制 + 打分排序"这套框架里，**分数只决定"预算内留谁"，
而画质大头由预算调度和选择目标决定**。分数把排序做得再好，也改变不了
预算给多少。

### 4.2 敏感度信号：可以被测量，但没有压缩价值（v1.2 修正版证据链）

1. **能学到**：真值标定实验（A1）显示，训练出的打分与敏感度真值在
   秩空间（只比大小顺序）相关约 −0.22~−0.30。信号学到了。
2. **没有价值**：监督全关只掉 0.021 dB（波动范围内）；全部精修信号
   （敏感度/比特、Fisher、权重）也都没有正收益。
3. **（撤回）**原来的第三条证据"开局启用崩 0.75、延迟启用恢复 84%"
   经查证不成立：崩溃那次是同参数重复运行的异常（加权从未生效），
   恢复的对比两边代码版本还不同。敏感度加权覆盖这个方法（v2）作为实验
   **从未真正运行过**——接线已修复（fix/submodular-sens-wiring 分支），
   它是否有害是还没测试的开放问题。

结论：**"信号可以被测量"不等于"信号有压缩价值"**。前半句由 A1 支撑，
后半句由"全关无损失 + 精修全无正收益"支撑，与被撤回的 A3/H2 无关。

### 4.3 单种子结论会翻转：两个种子是底线

两个典型案例：融合 +0.32 → 换种子后约等于 0（同码率 +0.002）；
Fisher +0.045 → 换种子后 −0.45。这一轮精修方向的真实效应和种子间波动
同量级，**单种子实验在这个量级上结论等于抛硬币**。以后所有新方向先用
两个种子过筛。另外这次发现重复运行的波动要分实验组类型看：普通打分
实验组 ±0.058，次模贪心实验组出现过 0.82 的偏离（4.1 节第一行）——
结论的误差范围要按各自的重复运行数据来定。

### 4.4 λ=0.0005 高码率端异常：排除了三个嫌疑，指向量化

（命名说明：λ=0.0005 是文件最大、最保真的一端。v1.0 曾把它叫"低码率
异常"，方向说反了，v1.1 起改。）

异常本身：该档基准（27.597 @ 21.44）比 λ=0.002（27.730 @ 14.45）
**又大又差**——多花 7 MB 买来负收益，RD 曲线在这一端失去单调性。
已排除：(a) 预算不够——H1 多留 16% 锚点被全面压过；(b) 选择信号差——
差异全在波动范围内；(c) 后半段窗口——扫描是平的。
剩下的主要嫌疑：**按内容自适应的量化**（训练末期按内容难度调整量化
精度）与低 λ 的相互作用——逐锚点比特分析显示这一档每个锚点的中位比特数
偏高 39%，主要来自偏移量字段。影响范围：所有 λ=0.0005 的比较（包括
G1 的这一档格子）都不可信。

下一步排查设计：干净的 2×2 实验——内容自适应量化开/关 × λ{0.002,
0.0005}，记录逐字段比特数和重建 PSNR。如果关掉后 λ=0.0005 的单调性
恢复，就得到一个干净的机制结论："λ 和自适应量化控制器发生了非预期的
耦合"——它同时可能孕育下一条量化创新。注意一个约束：按配置校验规则，
关内容自适应量化必须同时关敏感度监督，所以"关"的那格恰好就是 ICRA
论文里"去掉整个复杂度乘子掉 0.41 dB"那个消融的算法方式——λ=0.002 的
"关"这一格兼作新代码上的消融复核锚点。

### 4.5 保险闸门的失败方式本身有信息量

留出视角闸门（holdout gate：留 8 个视角不参与训练，每次删锚点后测它们
的 PSNR，掉点超过阈值就暂停预算执行）每次都成功探测到了掉点——**探测
环节是好的**；但冻结预算只挽回了 7% 的损失（要求 ≥50%）。说明删错的
损失不是"少删一点"能挽回的：锚点删掉后，训练已经把剩下的锚点拟合到
新的状态，回头路不存在。出路在删后恢复（重新加锚点），不在删前保险。

## 5. 对期刊版论文的含义

### 5.1 主线：量化路径

选择侧不作为期刊版核心创新。主线转**量化路径**（复杂度乘子族的扩展）——
那是此前验证过 0.41 dB 量级杠杆的方向。高码率端异常的偏移量比特线索
（4.4 节）是第一个切入点。

### 5.2 选择侧以"杠杆位置"成文

不是把失败实验当废料，而是组织成一个完整的机制故事：**信号可以被测量
而不带来压缩价值；预算真正执行时，结构性决策主导画质，精细的重要性
估计是二阶因素**（4.0 节的大小关系 + 4.1/4.2 节的证据链 + 双种子复制
纪律）。这条证据链回答"锚点压缩里选择算法的杠杆到底在哪"——本身有
发表价值。

### 5.3 场景泛化的边界与策略

本轮所有判定都在场景 1-78 上。目前能严格说的是"**在 1-78 上**，打分层
精修没有形成稳定优势"；还不能说"打分工程普遍没有价值"。补法不是把失败
实验全部扩到多场景（浪费 GPU），而是：**筛选阶段单场景 → 机制确定 →
只把最终写进论文结论的 3–4 个关键配置扩到 2-06 / 4-10 两个场景**
（候选：基准、次模 A2、敏感度全关、一个代表性打分精修、新量化方法）。

### 5.4 ICRA 论文的逐句核对（v1.1 新增）

对 `docs/05-paper/icra2027/main.tex` 逐句核对本轮结果：

- **数字层面：无矛盾。**论文里"去掉乘子掉 0.41 dB"消融的是**整个复杂度
  乘子**（四项结构统计量 + 小网络），不是只去敏感度监督——与 I6-off
  （只关监督，−0.021 dB）不矛盾，两者可以同时成立（乘子靠结构统计量
  有效，监督信号不加分）。融合方法"安全且代价在测量噪声内"与种子 104
  同码率 +0.002 一致；论文引用的 1.56 dB 崩溃是无覆盖约束的旧数据，
  真实存在。
- **叙事层面：一句归因写过了。**摘要里"supervised by render-sensitivity
  statistics, so fine steps flow to anchors that matter"把乘子收益的机制
  记在了敏感度监督上。I6-off 表明监督本身约等于 0 dB，乘子的价值来自
  四个结构统计量。论文已冻结提交，数字不用动；**期刊版必须重新措辞**：
  敏感度监督降级为训练期的可选辅助（甚至可以去掉）——这反而让零边信息
  的故事更干净：乘子纯靠解码端能重算的结构量工作。
