## 0. 摘要（给赶时间的读者）

1. 我们训练了 21 个完整压缩管线，系统测试了 6 类"剪枝时怎么挑锚点"的创新，
   每个创新都在实验**之前**写死了及格线（判定门），关键结论用两个随机种子复核。
2. **本轮最重要的成果不是某个过线的创新点，而是"剪枝杠杆的定位"**：
   在锚点压缩 + 预算约束这套体系里，局部打分工程（importance score
   engineering）的边际价值极低，而**预算何时执行、压多狠、选择目标本身**
   才真正控制 RD 行为（RD 即码率-画质权衡）。所有 ≥0.2 dB 的真效应
   全部来自结构层改动，所有打分类微调没有一个取得正的超噪收益。
3. 次模覆盖选择是唯一值得继续追的选择侧想法：在最紧预算档（λ=0.004）
   两种子同号（+0.52 / +0.14），matched-rate 口径下增益更强
   （+0.22 @ 同尺寸）；但总体聚合 +0.107 未达 +0.15 通过线，判中间带，
   定位为**紧预算专用组件**而非全码率通用算法。
4. 敏感度信号证据链（v1.2 修正版）：信号可学到（秩相关存在）、关掉监督只掉
   0.021 dB（噪声内）——**"信号可测"不等于"信号有用"**。原第三块"0 步启用
   崩 −0.75"经实现核查**撤回**：所谓加权崩溃臂实为 A2 同配置复跑异常
   （加权从未生效；贪心臂在 λ0.002 存在复跑不稳定性）。
5. 单种子结论会翻转（融合 s42 +0.32 → s104 ≈0；Fisher s42 +0.045 →
   s104 −0.45）：在 ≤0.1 dB 的效应量级上，**双种子是底线不是奢侈品**。
   v1.2 追加：同参复跑本身也可能偏离 0.8 dB（贪心臂），复跑噪声按臂类型分层。
6. 下一步：主力转量化路径（唯一验证过 0.41 dB 量级杠杆的方向）；
   **A4 消融取消**（代码级空操作）；新增两项待拍板——贪心臂复跑噪声研究、
   v2 加权新预注册臂（须在修复分支上跑并带 engagement 硬门）；
   ICRA 论文数字不受影响，但一句机制归因需要修正（5.4 节）。

## 1. 背景：任务、系统与这轮实验要回答的问题

### 1.1 任务与系统

**任务**：三维场景压缩。输入是一段多视角照片，系统用三维高斯泼溅
（3D Gaussian Splatting，3DGS）表示场景——即用几十万个带颜色、透明度、
大小的椭球（高斯）拼出场景，能实时渲染。原始 3DGS 文件有几百 MB，
我们的目标是把它压到几 MB 到二十 MB，同时画质尽量不掉。

**锚点表示**：直接压缩几十万颗高斯太贵。我们沿用 HAC++ 的做法：
把高斯组织到约 50–80 万个稀疏的**锚点（anchor）**上。每个锚点存一份特征
向量和小网络权重，解码端用小网络从锚点"长出"周围的高斯。文件大小
基本由锚点数量和每个锚点的属性比特数决定。

**压缩管线**：训练 30000 步 → 属性量化 → 熵编码（entropy coding，
把量化后的数字按出现概率压成最短的比特流）→ 解码端逐比特还原。
解码端不依赖任何额外文件（零边信息契约）。

**剪枝（pruning）**：训练过程中不断删掉贡献小的锚点来换体积。
"哪些锚点该删"由一个分数决定，分数来自渲染贡献统计（记作 ADMM 分数，
ADMM 是一种求解"在预算内保留哪些锚点"这类离散选择的优化方法）。
**这轮所有实验都在回答同一个问题：这个分数还能不能做得更聪明？**
（答案基本是"不能"——但"为什么不能"反而是更有价值的产出，见第 4 节。）

### 1.2 码率-失真评价

- **RD 曲线（rate-distortion curve，码率-画质权衡曲线）**：横轴是文件大小
  （MB，码率一侧），纵轴是画质。比较两个方法时，同大小看谁的画质高。
- **PSNR（峰值信噪比）**：画质指标，dB 越高越好。0.1 dB 以上的差异
  才谈得上可感知。
- **λ（拉格朗日乘子）**：训练时画质损失与体积惩罚的权衡系数。
  λ 越大越省体积、画质越低。我们用三档：λ=0.004（最省体积 = **低码率端
  / 最紧预算**）、0.002（中）、0.0005（最保真 = **高码率端**，文件最大）。
  三档各出一点，连起来就是一条 RD 曲线。
- **matched-rate（同码率）对比与 BD-rate**：两个方法的点大小不完全相同，
  直接比 PSNR 会混入"多花比特"的贡献。matched-rate 把一条曲线插值到
  另一条曲线的码率点上再比；BD-rate / BD-PSNR 在两条曲线的公共区间
  积分，给出单一数字（负 BD-rate = 同画质更省码率）。本报告 v1.1 起，
  关键结论同时给 raw 点差和 matched-rate / BD 口径。

### 1.3 这轮实验要回答的问题

上一轮的结论是：融合剪枝只值"防崩溃"，不值增益；同时发现训练后半段
预算几乎不执行（后面解释）。于是这轮（期刊版第二轮，jr2）系统测试
四个方向，每个方向一个或多个判定门：

| 波次 | 方向 | 判定门 |
| --- | --- | --- |
| Wave 0/Phase 1 | 次模覆盖选择（换目标函数） | G1 |
| Wave 1 | 码率感知剪枝（分数除以比特数 / 按比特定预算） | G-R1, G-R2 |
| Wave 2 | 精修信号：敏感度/比特、Fisher 二阶、融合权重扫描 | G-SPB, G-F, G-W |
| Wave 3 | 对照与扫描：敏感度全关、后半段预算窗口 | （模式 2 证据链、B1 扫描） |
| Wave 4 | 两个机制判定：松预算修高码率端异常、延迟启用敏感度 | H1, H2 |
| 收尾 | 关键臂第二种子确认 | （不设门，验证可复制性） |

## 2. 实验制度：为什么这些数字可信

### 2.1 统一协议

- **场景**：全部在开发场景 1-78 上判定（1050 张训练图、150 张验证图）。
  单场景判定的局限与多场景策略见 5.3 节。
- **训练**：30000 步；15000 步做一次深度重初始化（reinit，用深度图把锚点
  重新铺一遍表面，之后进入训练后半段）。
- **预算比 r_post（咬合预算）**：上一轮发现训练后半段预算基本不执行。
  修复后，后半段把锚点数线性压到重初始化时的 85%（r_post=0.85），
  使剪枝决策在后半段真实发生。本文所有 jr2 实验（除特别注明）都在
  r_post=0.85 下。
- **体积口径**：压缩后九项字节分解之和（MB）。
- **正确性**：每个 run 必须通过比特级还原校验（编码再解码逐位一致），
  否则作废。

### 2.2 判定门制度

- **预注册**：每个实验的及格线在跑之前写进设计文档，跑完按原文判，
  不许事后调整标准。这是为了杜绝"跑很多个、挑最好看的"。
- **双种子**：关键结论用两个随机种子（seed 42 与 104）各跑一遍。
  随机种子影响初始化与数据顺序，同一配置换种子结果会波动。
- **噪声带**：同配置复跑的差异实测为 **±0.058 dB**。任何小于这个量级的
  差异都不能作为结论。正式判定门取 ±0.10 dB，留安全余量。

### 2.3 基准数字（场景 1-78，30000 步，压缩后）

| 配置 | PSNR @ 大小 |
| --- | --- |
| 旧协议 base（预算不咬合）λ=0.004 / 0.002 / 0.0005 | 27.511 @ 11.72 / 27.750 @ 15.05 / 27.953 @ 23.60 |
| 咬合预算 base（r_post=0.85）λ=0.004 | **26.983 @ 11.08**（比旧协议低 0.53） |
| 咬合预算 base λ=0.002 | 27.730 @ 14.45（旧代码）/ **27.695 @ 13.90**（新代码，本文默认基准） |
| 咬合预算 base λ=0.0005 | 27.597 @ 21.44（**高码率端异常点**：比 λ=0.002 又大又差，见 4.4 节） |

注意第一行与第三行的对比：**咬合预算本身在 λ=0.004 让 base 掉了 0.53 dB**。
预算真正执行后，base 变得更容易受伤——这正是选择算法有发挥空间的地方，
也是次模增益出现在这一档的原因（见 3.1 节）。

## 3. 逐 wave 结果与解析

记法：`27.504 @ 11.06` 表示压缩后 PSNR @ MB。对 base 的差异写作
`+0.52 @ −0.02 MB`（画质差 / 大小差）。

### 3.1 Wave 0/Phase 1：次模覆盖选择（判定门 G1）——中间带，唯一正信号

**想法**：原剪枝分数给每个锚点独立打分再求和（模块化目标），
天然看不见冗余：两个锚点盖住同一批像素，会各得一份高分。次模覆盖选择把
目标从"分数和最大"换成"被保留锚点集合覆盖到的像素总量最大"——
每个像素只被算一次，重复覆盖不加分。该问题有贪心算法的近似保证
（1−1/e），工程上用优先队列加速到近线性时间。

**结果**（A2 臂 = 纯覆盖；逐格对同 λ 同种子 base）：

| λ | seed 42 | seed 104 | 逐 λ 均值 |
| --- | --- | --- | --- |
| 0.004（最紧预算） | 27.504 @ 11.06（**+0.52 @ −0.03**） | 27.405 @ 11.28（**+0.14 @ −0.45**） | **+0.332** |
| 0.002 | 27.806 @ 14.43（+0.08 @ −0.02） | 27.676 @ 14.50（−0.05 @ +0.05）* | +0.011 |
| 0.0005 | 27.719 @ 20.55（+0.12 @ −0.89） | 27.280 @ 20.19（−0.17 @ −0.73）** | −0.024 |

\* λ=0.002 的 seed104 base 未跑（缺口已登记），该格用 seed42 base 代用，
结论按"≈0"读。\*\* λ=0.0005 两格的 base 都落在高码率端异常区（4.4 节），
该档所有对比不可信，按缺失处理。

**判定：中间带**。聚合口径：6 格（其中 λ0.002 s104 为代用格、λ0.0005
两格被异常污染）各自求 Δ 后平均，总体 **+0.107 dB**——未达 +0.15 的
通过线，落在中间带 [0.05, 0.15)；一致性条件也不足（仅 λ=0.004 两种子
同号；λ=0.0005 两种子异号且该档数据不可信）。

**（v1.1 修正说明）** v1.0 报的 +0.16 是旧聚合的错误：λ=0.004 的
seed104 格误配了 seed42 的 base（26.983），把 +0.14 算成 +0.42。
种子匹配后总体降为 +0.107——**判定不变（中间带），但数字依据修正**。

**matched-rate / BD 复核（v1.1 新增，脚本 `scripts/bd_matched_rate_jr2.py`）**：
担心"+0.14 里有多少只是多花的比特"——实际相反，次模的增益点全部
**又小又好**，同码率口径只会更强：

| 口径 | 数字 |
| --- | --- |
| s42 紧/中码率区间（11.08–14.43 MB）BD-PSNR | **+0.30 dB** |
| s42 同区间 BD-rate | **−12.0%**（同画质省 12% 码率） |
| s104 在 base 同尺寸（11.73 MB）上插值 | **+0.22 dB**（raw 格 +0.14） |

**机制解释**：增益全部集中在 λ=0.004，这不是巧合。λ=0.004 是唯一
一个"预算真正咬合把 base 打崩"的档（26.983，比 λ=0.002 还低 0.75），
剪枝决策大量真实发生，"重复覆盖不加分"才有差异化的机会。
λ=0.002 预算宽松、本来就剪不了几下，换什么目标函数都一样。
**（v1.2 撤回）**原"A3 臂（敏感度加权覆盖）在 λ=0.004 比 A2 低 0.09、
在 λ=0.002 崩到 26.985"的负发现不成立：ckpt 证明加权从未生效，A3 三行
实为 A2 同配置复跑。由此暴露的新事实：**贪心臂同参复跑在 λ=0.002 可偏离
0.82 dB**（27.806 vs 26.985，同种子同代码）——G1 的 λ=0.002 格误差棒
远大于 ±0.058；λ=0.004 有三个紧凑同参样本（27.504/27.417/27.405），
仍是承重格。另一口径（v1.2 补）：A2 相对 fusA 的次模增量为 +0.08（s42）/
+0.21（s104），双种子同正——论文应同时报告 A2−base 与 A2−fusA。

**A4 消融（v1.2 取消）**：原计划"次模 + 关闭覆盖约束"是代码级空操作——
覆盖约束只在非次模 topk 分支生效，贪心分支从首个实现提交起就不施加约束。
构造上已回答原问题：A2 的增益不可能来自该约束。若要继续做有分辨力的
消融，方向是 fusA + 约束关闭（fusA 臂的约束真实生效）。

### 3.2 Wave 1：码率感知剪枝（G-R1 / G-R2）——失败

**想法**：熵模型训练时顺带统计每个锚点实际编码出的比特数
（滑动平均，记 bits_ema——这个统计本身是可靠的，后续逐锚点比特
分析就靠它）。两个用法：(R1) 剪枝分数除以比特数的幂
（score/bits^τ，"性价比"视角）；(R2) 直接把预算定为总比特预算。

**结果**（λ=0.002，对 base 27.695 @ 13.90）：
- R1：27.659 @ 13.67（−0.035 @ −0.23 MB）
- R2：27.582 @ 13.65（−0.113 @ −0.26 MB）

**判定：双双失败**。R1 差异在噪声内；R2 明确为负。
**机制解释**：锚点之间的比特数差异远小于质量差异——省下的比特
买不回错删的质量。比特数适合做**分析口径**（哪里花的钱多），
不适合做**选择依据**（谁该被删）。

### 3.3 Wave 2：三个精修信号（G-SPB / G-F / G-W）——全部失败

- **G-SPB（敏感度/比特）**：把"每比特敏感度"作为监督目标教给复杂度
  乘子网络。结果 27.612 @ 14.03（−0.082 @ +0.13 MB），失败。
- **G-F（Fisher 二阶）**：用梯度平方的滑动平均近似二阶导信息
  （衡量"动这个锚点伤多大"），替代一阶敏感度。seed 42 +0.045
  （噪声内），seed 104 **−0.45**（同码率点 −0.449，明确为负），
  双种子均值 −0.20。失败，结论是**"无益、不稳健、偏有害"**——
  不是"伤害被复制"（v1.1 措辞修正）：一个种子在噪声内、一个种子
  明确为负，跨种子不稳定本身就是负面证据。
- **G-W（融合权重扫描）**：融合剪枝分数里的敏感度权重 w 从 0.3 扫到
  0.1 / 0.2。w=0.1 +0.048（噪声内），w=0.2 −0.22（异常 run，多 restart）。
  默认 w=0.3 最好。失败——分数已工作在噪声边缘，调权重没有空间。

**机制解释（三个失败共同的原因）**：这些都是"怎么打分"层面的微调。
在 4.1 节的规律下（结构性改动才有大效应），它们的真实效应量级
本来就 ≤0.1 dB，与噪声同阶——单种子实验在这种量级下结论等于抛硬币。

### 3.4 Wave 3：对照与扫描（I6-off / B1）——两个平静但重要的结果

- **I6-off（敏感度全关）**：把整套敏感度监督（复杂度乘子的训练信号）
  完全关掉。结果 27.674 @ 13.84，对 base 27.695 @ 13.90 只差
  **−0.021 dB，噪声内**。也就是说：敏感度信号对最终画质没有可测贡献。
  （这个 run 第一次跑时压缩阶段因内存盘写满而失败，已重跑并以本次
  解码评测为准。）
- **B1（后半段预算窗口扫描）**：预算咬合后保持 5000 / 10000 步
  （默认 2000）。+0.048 / −0.035，全在噪声内——后半段预算窗口的
  长短不是杠杆。

### 3.5 Wave 4：两个机制判定（H1 / H2）

- **H1（松预算修复高码率端异常）——证伪**。λ=0.0005 档 base 异常
  （27.597 @ 21.44，比 λ=0.002 又大又差）。假设"异常是预算太紧造成"，
  对策是回退预算咬合（r_post=1.0，多留 16% 锚点：792723 vs 681228）。
  结果 27.562 @ 23.04：对判定门（≥27.80 @ ≤21.4）双指标全败，
  对它要修复的异常 base 是 −0.035 @ **+1.60 MB**——多花的钱没换来任何
  画质。假设不成立，异常的原因要到量化侧找（见 4.4 节）。
- **H2（延迟启用敏感度）——判定撤回（v1.2）**。该臂（27.583 @ 13.81）本身
  是干净有效的 run，但其预注册叙事"延迟恢复崩溃臂 84% 损失"经核查不成立：
  所谓"A3 崩溃臂"（26.985）实为 A2 同配置复跑异常（敏感度加权从未生效，
  见《A3 臂实现核查与来源调查》），不是处理效应；且延迟臂跑在新代码、
  崩溃臂跑在旧代码，本就跨代码状态。"早期敏感度有害"目前只剩间接迹象
  （I6-off 无损失 + 全部精修无正收益的反向佐证），不构成直接证据。
  延迟臂数字保留为描述性记录；若要重开这个问题，需要同代码的
  立即/延迟配对臂。

### 3.6 收尾：第二种子确认（fusA_s104 / fisher_s104）——负结果可复制

对 λ=0.004 两个关键臂补跑 seed 104（matched-rate 口径，v1.1）：

- **融合剪枝 fusA**：seed 42 对同种子 base +0.32（且更小，支配性优势）；
  seed 104 raw −0.07，但 fusA 比 base 小 0.71 MB——**在 base 同尺寸
  （11.73 MB）上插值后 +0.002，恰好中性**。结论：融合没有跨种子稳健
  的增益，维持"防崩溃组件、非增益组件"的定位。（raw 的 −0.07 里
  有一部分是尺寸效应，matched 后归零。）
- **Fisher 二阶**：对同种子融合臂同码率 **−0.45**。seed 42 那对是
  +0.045（噪声内）。双种子均值 −0.20：Fisher 无益且不稳健（v1.1
  措辞，见 3.3 节）。

这两个确认的价值在 4.3 节展开：单种子结论在这一轮的效应量级下
**会翻转**，双种子不是奢侈品而是底线。

## 4. 横向规律：杠杆定位与五条跨 wave 结论

### 4.0 本轮最重要的成果：剪枝杠杆的定位

把全部结果放在一起，出现一条清晰的不等式：

> **打分工程（score engineering） ≪ 选择目标（objective） ≲ 预算调度与量化结构（budget / schedule / quantization）**

即：继续在 Fisher、梯度、敏感度、比特加权这类重要性分数上卷，
收益概率已经很低；真正控制 RD 行为的是"预算何时执行、压多狠、
按什么目标选、以及量化怎么分配"。这不是本轮的设计失误，而是
被 21 个管线系统测量出来的边界——它把研究问题从"能不能找到更聪明的
剪枝分数"升级为"**锚点压缩里选择信号的作用边界在哪里**"，
后者是更有分量的研究问题。

### 4.1 大效应全是结构性的，打分工程没有正收益

把这一轮所有 |Δ| ≥ 0.2 dB 的真效应放在一起：

| 效应 | 量级 | 类别 |
| --- | --- | --- |
| 贪心臂同参复跑异常（λ0.002，n=2 对） | −0.82 | 复跑不稳定（协议层，v1.2 新发现） |
| 预算 r085 → r055 | −0.378 | 预算（结构） |
| 次模 @λ0.004（s42） | +0.52 | 目标结构 |
| 去掉深度重初始化 | −0.215 | 流程（结构） |
| 咬合预算使 base @λ0.004 掉 | −0.53 | 协议（结构） |

而全部"怎么打分"的微调（码率折扣、比特预算、敏感度/比特、Fisher、
融合权重、预算窗口）：**没有任何一个取得正的超噪收益**——最大正效应
+0.048 dB（w=0.1 和 postw5000），远低于 +0.10 判定线；其中四个臂还
明确为负（R2 −0.11、SPB −0.08、w=0.2 −0.22、Fisher-s104 −0.45）。
（v1.1 修正：v1.0 的"没有一个超出 ±0.06 dB"与表格自相矛盾，已改写。）

原因：在 ADMM+预算框架里，**分数只决定"预算内留谁"，而画质大头由
预算调度和目标结构决定**。分数把"同分锚点里留谁"选得再好，改变不了
预算给多少。这条规律直接决定了下一步的方向选择（第 5 节）。

### 4.2 敏感度信号：可测，但不值钱——证据链（v1.2 修正版）

1. **可测**：真值标定实验（A1）显示，训练出的打分与敏感度真值在
   秩空间（只比大小顺序，不比数值）相关约 −0.22~−0.30。信号学到了。
2. **不值钱**：全关只掉 0.021 dB（噪声内）。信号对最终画质无可测贡献；
   全部精修信号（SPB/Fisher/权重）也无正收益。
3. **（撤回）**原第三块"0 步启用崩 −0.745、20000 步恢复 84%"经实现核查
   不成立：崩溃臂是 A2 同配置复跑异常（加权从未生效），恢复叙事跨代码。
   敏感度加权覆盖（v2）作为实验**从未真正运行过**——接线已修复
   （fix/submodular-sens-wiring 分支），v2 是否有害是未测试的开放问题。

结论：**"信号可测"不等于"信号有用"**；监督信号在咬合预算下没有可测的
RD 价值这一结论由 I6-off 与精修链条支撑，与被撤回的 A3/H2 无关。

### 4.3 单种子结论会翻转：双种子是底线

两个教科书案例：融合 s42 +0.32 → s104 ≈0（matched 后 +0.002）；
Fisher s42 +0.045 → s104 −0.45。这轮精修方向的真实效应量级（≤0.1 dB）
与种子间波动同阶，**单种子实验在这种量级下的结论本质上是抛硬币**。
此后所有新方向的过筛，双种子应为起手配置（A4 已按此改正）。

### 4.4 λ=0.0005 高码率端异常（低 λ 档）：排除三个嫌疑人，指向量化侧

（v1.1 改名：λ=0.0005 是低 λ 档 = 文件最大、最保真的**高码率端**；
v1.0 曾误称"低码率异常"，方向反了。）

异常：该档 base（27.597 @ 21.44）比 λ=0.002（27.730 @ 14.45）
**又大又差**——多花 7 MB 买来负收益，RD 曲线在高端失去单调性。
已排除：(a) 预算不够——H1 多留 16% 锚点被严格支配；(b) 选择信号差
——差异全在噪声内；(c) 后半段窗口——扫描是平的。
剩下的主要嫌疑：**按内容自适应的量化（content-aware quantization，
训练末期按内容难度调整量化精度）与低 λ 档的交互**——逐锚点比特
分析显示该档每锚点中位比特数异常偏高（+39%），主要来自偏移量字段。
影响范围：所有 λ=0.0005 的对比（包括 G1 的该档格子）都不可信。

下一步排查设计（v1.1 新增）：干净的 2×2——content-aware 量化
开/关 × λ{0.002, 0.0005}，共 4 个 run，记录逐字段比特
（偏移量/特征/缩放/掩码）与重建 PSNR。若关掉后 λ=0.0005 的
RD 单调性恢复，就得到一个干净的机制结论："λ 与自适应量化控制器
发生了非预期耦合"——它同时可能孕育下一条量化创新。

### 4.5 保险闸门失败方式本身有信息量

留出视角闸门（holdout gate：留 8 个视角不参与训练，每次剪枝后测它们
的 PSNR，掉点超阈值就暂停预算执行）每次都成功探测到了掉点——
**探测环节是好的**；但冻结预算只挽回了 7% 的损失（要求 ≥50%）。
说明错剪的损失不是"少剪一点"能挽回的：锚点删掉后，训练已经把
剩余锚点拟合到新的状态，回头路不存在。出路在剪后恢复（重新加锚点），
不在剪前保险。

## 5. 对期刊版与论文的含义

### 5.1 主线：量化路径

选择侧不作为期刊版核心创新。主线转**量化路径扩展**（乘子族）——
那是此前验证过 0.41 dB 量级杠杆的方向，需另立设计文档。
高码率端异常的偏移量比特线索（4.4 节）是第一个切入点。

### 5.2 选择侧以"杠杆定位"成文

不是把失败实验当废料，而是整理成统一的机制故事：
**信号可以可测而无用；在咬合预算下，结构性决策主导画质，
精细的重要性估计是二阶因素**（4.0 节的不等式 + 4.1/4.2 的证据链 +
双种子复制纪律）。这套证据链回答"在锚点压缩里，选择算法的杠杆
到底在哪"——本身有发表价值。

### 5.3 场景泛化的边界与策略

本轮所有判定都在场景 1-78。当前能严格说的是"**在 1-78 上**，打分层
精修没有形成稳定优势"；还不能说"打分工程普遍没有价值"。
补法不是把失败实验全部扩成多场景（浪费 GPU），而是：
**筛选阶段单场景 → 机制确定 → 只把最终形成论文结论的 3–4 个关键
配置扩到 2-06 / 4-10**（候选：base、次模 A2、I6-off、一个代表性
打分精修、新量化方法）。

### 5.4 ICRA 论文 claim audit（v1.1 新增）

对 `docs/05-paper/icra2027/main.tex` 逐句核对本轮结果：

- **数字层：无矛盾。** 论文的 0.41 dB 消融是去掉**整个复杂度乘子**
  （四统计量输入 + MLP），不是只去敏感度监督——与 I6-off（只关监督，
  −0.021 dB）不矛盾，两者可以同时成立（乘子靠结构统计量有效，
  监督信号不加分）。融合的"安全且代价在噪声内"与 s104 matched +0.002
  一致；引用的 1.56 dB 崩溃是无覆盖约束的裸融合（真实历史数据）。
- **叙事层：一句归因过誉。** 摘要与 2.1 节"supervised by
  render-sensitivity statistics, **so** fine steps flow to anchors that
  matter"把乘子收益的机制记给了敏感度监督。I6-off 表明监督本身
  ≈0 dB，乘子的价值来自四个结构统计量。论文已冻结提交，数字不用动；
  **期刊版必须重新措辞**：敏感度监督降级为训练期可选辅助（甚至可去），
  这反而强化零边信息故事——乘子纯靠解码端可复算的结构量工作。
