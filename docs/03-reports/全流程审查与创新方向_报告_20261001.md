## 3. 文献调研要点（2025-10 至 2026-10）

### 3.1 必须正视的竞品：ProGS（arXiv:2603.09703，2026-03）

锚点谱系、单码流、八叉树父闭前缀、任意已完成层边界可解码，自称比 HAC++ 省 22.6–53.4% 字节，最低档约 10.75 MB（论文自报数）。**它已进入我们此前的"<12 MB 独占区"叙事**。它的头部传二值化哈希网格 + 解码器权重 + 基步长——有边信息。**CSV 里还没有 ProGS 实测行**，10.75 MB 目前是自报数不是测量；对比表补齐 ProGS 是投稿前的硬要求。

### 3.2 我们两条主张的空白确认

- **"零边信息"（不传步长表/熵模型/码本，量化参数全部由已解码数据重算）在 2025-2026 文献中无人主张**——PCGS/ProGS/SCAR-GS/GoDe 全部把学习式熵模型或码本/字典写进码流头部。最近的先行技术是 PCGS 的步长递归推算 q_s=q_{s-1}/3（解码端可算但建立在学习式熵模型上、未作为主张）——写论文必须引用并说清差异。
- **定向粗层格点的量化感知训练无人做**——GoDe 是随机层采样求鲁棒，4DGCPro 在动态场景，静态锚点谱系中"训练末期把符号推向最粗层格点、专抬最先解码层画质"未见。
- 渐进赛道 2026 年已活跃（ProGS、SCAR-GS、Matryoshka GS），论文定位应从"首个渐进锚点压缩"收紧为"首个零边信息可截断渐进压缩"。
- 工业侧（.spz/SOG）全部单码率非渐进；MPEG 高斯泼溅编码（GSC）提案截止 2027-01，是现成的标准化窗口。

### 3.3 几何方向调研（提案的前提，后被红队部分推翻，见 §5）

调研给出的关键对比——我们每锚点坐标约 80 比特 vs "HAC++ 约 16 比特"——经红队核对属于误读（16 bit 是 HAC 的量化网格深度，不是编码后开销）；但我们自己的 25-27 比特/分量与审计产物 15.2 比特/分量的矛盾也在这一步暴露，最终引出 §5.2 的更正。调研确认的四条几何路线（量化对齐 → 锚点减量 → 学习式几何熵编码 → 几何渐进层）中，"几何做成渐进层"仍是文献空白，保留为候选。

### 5.3 裁定后的方向排序

## 6. 最小化尝试：B3 惩罚去掉 scaling 字段

### 6.1 设计与依据

- **问题格**：1-78 λ0.0005 w=0.05 满精度 −0.482 dB（对照 27.6013 → 实验臂 27.1195，CSV 行 305/306）。该格是目前唯一"增益小、代价大"的 B3 格子（w=0.01 格无代价、λ0.004 格无代价）。
- **嫌疑根因**：scaling 的量化步长基数 0.001 使惩罚梯度经 1/Q 放大约千倍（自家 09-26 变更记录在案）。红队确认"只在基层施加"在代码里没有对应物——现有惩罚本来就只往基层格点推；满精度代价的真实机制是末期 6000 步里惩罚与渲染损失打架，而 scaling 是头号嫌疑字段。
- **改动**：新增 `coarse_ladder_skip_scaling` 开关（默认关，行为不变），把 scaling 字段从惩罚中置零。提交 e47e7af + 单测修复 246a866。

### 6.2 生效证据链（三层）

1. **单元测试**（tests/test_b3_skip_scaling.py，2 通过）：开关开时惩罚值恰等于 feat 项 + offset 项；scaling 是叶子张量且反传后无梯度。
2. **参数解析探针**（服务器）：tyro 按真实路径解析四个旗标 → align=True、skip_scaling=True、start_iter=100。
3. **在线探针**（加载冒烟 checkpoint 原位渲染）：step=5000 惩罚为 None（路径门控正常休眠）；step=10001 惩罚 0.008849（raw 0.176979 × 权重 0.05 × ramp 1.0，算术自洽）——真实渲染路径里开关生效。证据已固化在 `/home/project2/dcca_runs/smoke_b3ns_600s.launch.log`。

**过程发现**：B3 惩罚块嵌在 `if step > 10000` 分支之下（hacpp.py:634），600 步冒烟永远够不到它——这解释了为什么冒烟一开始没有 [B3] 日志，也说明 B3 的 start_iter 必须大于 10000（现默认 24000，合法）。

**设置**：1-78、λ0.0005、seed 42、新环境（训练线与 env2_base 同代码 e47e7af，此后提交全为文档）。三臂 `arscan_r0{70,60,50}_lam0005_s42`，每臂把 `spa-ratio` 与 `spa-post-ratio` 同时设为该档（协议里两个字段同值构成"预算"这一个因子），其余旗标与 env2_base 逐字一致。对照臂 = env2_base（r=0.85：27.8351 dB @ 20.39 MB，685,289 锚点）。spa 是生产已验证路径，本批只改参数，按规程免冒烟。

**预注册门**：
1. 单调性（sanity，不过则本批作废查机制）：最终锚点数随 r 递减，且 r=0.5 < r=0.7。
2. 主门（低码率可扩性成立）：r=0.6 或 0.5 至少一档，分层读数后 P0 ≤ 12 MB 且该档画质 ≥ 22 dB——"预算轴能把起点压到 ProGS 自报最低档（约 10.75 MB）以下或同级"成立，预算轴立为论文轴。
3. 代价记录（强制报告，非否决门）：每档满精度 PSNR 与总体积相对 r=0.85 的变化（playroom 先例：预算 50% 时 −1.23 dB；超 −1.5 dB 显著标红）。
4. 证负条件：锚点数不随 r 变（门 1 失败）或三档 P0 全部 > 12 MB → 预算杠杆降级，三角数据入册存档。
