## 0. 摘要（给赶时间的读者）

1. **方向分三层**。主线上推进的有 2 个：渐进码流分层编码（能力轴，走得最远，
   分层主结构已确认）和量化路径 B+C（效率轴，9-21 刚立项）。收尾写进论文的
   有 3 个：次模覆盖选择（介于达标与不达标之间，紧预算专用）、融合剪枝

   1 个升为主线（渐进码流），1 个离线证伪挂起（scaling 字段换分布），语义、
   4D、删后恢复 3 个还没真正开跑。
2. **与 HAC++ 的实测对比只有一个外部方法**（同数据、同 30k 迭代、同三档 λ、
   同种子，我们自己复跑的参考点）。最硬的数字是平价点：base r100
   27.86 dB @ 15.24 MB 对 HAC++ 27.84 dB @ 20.03 MB，同画质下体积省约 24%。
   整体形态是体积约为 HAC++ 的 58–59%、画质低 0.4–0.7 dB，高码率段（26–40 MB）
   我方没有实验点。

   输出（base −25.3%、加次模 −34.2%，对 HAC++，外插方式）与 CSV 登记的旧版

   （λ=0.004 崩溃格 26.98 → 复跑 27.39；λ=0.0005 异常格 27.60 → 复跑 27.81）。
   详见 §2.3。
4. **撤回 / 降级清单 6 项**（§2.4），写论文时逐条对照，防止旧数字回流。
5. **待办 6 项**（§4），最紧的三件：BD-rate 更正登记与重算、s2/s3 分层数字

### 1.2 主线一：渐进码流 / 分层编码（9-20 立项，当前走得最远）

**问题定义**：现有码流必须完整收到才能解码；目标是"收到前 k% 字节就能渲染出
尽量好的画面"，字节-画质曲线下面积是优化指标。这是一个新的能力轴，不和 RD
曲线上的某个点直接比。

**已走到哪一步**（按时间）：

1. 设计空间定三个家族：A 排序分组（只改打包顺序）、B 分层量化（先粗后细）、
   C 条件熵模型（解码端自回归）。三族可组合（`../02-design/渐进码流方向探索_20260920.md`）。
2. S1 离线检查：A1 组号元数据成本 2.06% 通过；A2 解码端预测贡献排序 81.6%
   （门槛 95%）不通过；C2 分层条件 0.37 bit/符号通过；D1 分组无损分割通过。
3. S2 前缀渲染实测（提交 `408a44f`，**数字未登记 CSV**）：按贡献排序能带来
   +5~6 dB 的排序增益，但增益不靠前——前 50% 锚点比全锚点差 2.3 dB。
   结论：选择式排序有结构性天花板，B/C 分层家族升级为主结构，A 收缩为
   排序元数据层。
4. S3 零训练分层重编码 C2.5（提交 `372ce09`，**数字未登记 CSV**）：
   - 4 倍粗步长的全锚点层只损失 0.60 dB（26.357 dB @ 23.11 MB，静态记账），
     2 倍粗只损 0.21 dB；满精度校验锚点 26.953 dB 与 S2 一致；
   - 量化步长解码端重建 100% 成立（撤销了 S1 阶段 feat 字段恢复率的告警）；
   - 代价：分层字节按静态编码器记账，比学习式编码贵 1.75 倍；归一化估算
     L0 等效约 13.2 MB @ 26.36 dB，同画质比选择式排序省约 7 MB（估算，
     待分层落地后复核）；
   - 过程中发现 attributes.pth 与解码张量存在个别行的巨大差异（scaling 的
     log 空间最大差 21），此后渲染实验一律以解码模型张量为准，并加了校验
     锚点机制。

**下一步**：分层码流落地（真实分层打包与体积开销）、完整字节-画质曲线、
与学习式编码器的公平比较方式。论文主张：首个进入锚点式压缩码流、解码端
零边信息的渐进传输能力；与 PCGS（AAAI'26 Oral）、ProGS 的空间分层思路正交，
机制差别定位已做一轮文献确认（时间线阶段 11）。

### 1.3 主线二：量化路径（9-21 立项，设计草案 v0.1）

**判定前提**（`1584f7d`、`7363017`）：ICRA 稿声明的"去掉内容自适应量化损失
0.41 dB"经溯源判定为无出处数字——有记录的全部历史（DeepBlending 消融 −0.002、
4-28 约 +0.1）与新跑的干净消融一致。v3 消融矩阵 6 格全部通过有效性门，三个
同代码干净对全部"开着不低于关着"（+0.017 / +0.066 / +0.095 dB，均值 +0.059，
其中两对在更小体积下更高画质，即帕累托占优）；λ=0.004 s42 旧基准格
26.98 确认为孤立崩溃格，复跑 27.39（CSV 行 308）。机制从贡献声明除名，
作为工程组件保留。

**候选路径**（`../02-design/量化路径_设计文档_20260921.md`）：四领域调研
（视频编码、学习式图像压缩、点云、3DGS 压缩）独立收敛——"解码端可重算的
连续逐锚点步长乘子"没有成功先例。路径 B（把敏感度统计放进熵模型的条件
输入，主推荐）+ 路径 C（闭式/分档步长，搭车件）+ 路径 D（整体删除，诚实
出口）。**路径 B 的实现与判定实验尚未排队。**

附属状态：探索五（scaling 字段换拉普拉斯/混合分布）已离线证伪挂起；高端档
异常的机制解释（上下文预测变差，不是量化本身）已由 2×2 实验支持。

## 2. 与 HAC++ 的对比现状

### 2.1 对比怎么做的

同场景（1-78，无人机，1200 图）、同迭代（30k）、同三档 λ（0.004 / 0.002 /
0.0005）、同种子（42）、同数据路径；指标全部来自解码后的真实码流，
体积用 fp32 记账（与 HAC++ 原生 float32 MLP 一致），逐位还原校验通过
（`1-78_30k_32dim_DCCA_vs_HACpp.md`）。**实测对比的外部方法只有 HAC++ 一条
线**；PCGS、ProGS、Octree-GS、JPEG2000/可分级视频目前只做定位提及，没有
本仓库复跑的点。

### 2.2 曲线形态与平价点

| λ | 我方 base（r085 协议） | HAC++ 参考 | 说明 |
| --- | --- | --- | --- |
| 0.004 | 26.98 @ 11.08 ⚠️崩溃格，复跑 **27.39 @ 10.52** | 27.84 @ 20.03 | 复跑值在 CSV 行 308 |
| 0.002 | 27.73 @ 14.45（r085）/ 27.86 @ 15.24（r100） | 28.21 @ 26.27 | |
| 0.0005 | 27.60 @ 21.44 ⚠️旧异常格，复跑 **27.81 @ 19.94** | 28.68 @ 40.56 | 复跑值在 CSV 行 305 |

- 整体形态：我方每档体积约为 HAC++ 的 58–59%，画质低 0.4–0.7 dB；曲线在
  HAC++ 左下方（更小体积、更低画质）。高码率段（26–40 MB）只有 HAC++ 有
  实验点。
- **平价点（目前最硬的说法）**：base r100 27.86 dB @ 15.24 MB 对 HAC++
  27.84 dB @ 20.03 MB——同画质下体积是对方的 76%，即省约 24%。
- 加次模后低码率端被拉起：λ=0.004 两个种子同尺寸 +0.52 / +0.14（s104 在
  基准大小上插值 +0.22）；但松预算档为负，所以它是紧预算专用组件，
  不是全曲线增益。

### 2.3 BD-rate：三套数字并存，重算前不进论文

BD-rate 的含义：在两条率失真曲线共同覆盖的画质区间内，方法 B 相对方法 A
多用（正）或少用（负）多少码率。负值才表示更好。当两条曲线几乎不重叠时，
计算要靠区间外推（下表标"外插"），结果的稳健性差，必须标注。

| 版本 | base vs HAC++ | +次模 vs HAC++ | 状态 |
| --- | --- | --- | --- |
| 09-04 首批对比报告（32-dim seed42） | +2.5~2.8% | — | 已降级：两条曲线重叠区仅 0.14 dB，报告自己注明不稳健 |
| CSV `bdrate` 行（约 09-16 登记，图 v1） | +1.5%（外插） | −16.2%（外插） | 同行还有：次模 vs base −25.7%（干净重叠区 27.50–27.73）；60k 对 30k −42.9%（迭代数失配，仅参考） |
| 出图脚本 v2 现行输出（组会 09-17 引用） | −25.3%（外插） | −34.2%（外插） | 本报告复跑 `scripts/plot_rd_submod_vs_hacpp.py` 确认输出一致；A3 +2.4%；**未登记 CSV** |

三个必须处理的问题：

1. **登记与现行不一致**：CSV 是数字唯一事实源，但脚本从 v1 升到 v2（base
   曲线加入 r100 点等）后没有补更正行。写论文引用哪套都会和另一处矛盾。
2. **base 曲线两个端点是已确认的异常格**：λ=0.004 端用了崩溃格 26.98
   （同参数复跑 27.39，相差 0.41 dB）；λ=0.0005 端用了旧异常格 27.60
   （复跑 27.81 且体积更小）。用两个修正点重算，base 对 HAC++ 会明显变好，
   但重算还没做。
3. **外插成分大**：v2 里两条曲线的画质重叠区只有 0.02 dB，−25.3% 主要是
   外推出来的。论文里更站得住的表述是平价点（同画质省 24% 体积）加上
   "次模 vs 自己的 base"这个内部比较（干净重叠区 −25.7%）。

## 3. 两个定位问题的结论

1. **融合剪枝的 base 是不是 SPA？是，两层都成立**。改造对象上，融合剪枝
   就是在 SPA 的 ADMM 剪枝分数里混入覆盖面积和渲染敏感度信号（最初加法、
   修法 A 后改乘法调制）；实验对照上，当时的 base 是 I2+I6+SPA(0.85)+
   MiniSplat 主线，本身含 SPA。
2. **SPA 能不能作为基础工作背景？能，而且项目里已经是这个定位**。SPA 来自
   GaussianSpa（CVPR 2025，arXiv 2411.06019），是第三方发表方法，我们做
   锚点版改造后采用；它从不在贡献列表，写论文在方法节引用即可。去掉融合
   剪枝不影响这个地位。两点注意：(a) 30k 协议下 SPA 实际行为是温和压缩
   （锚点 889k→803k，约 −10%），"ratio 0.85"的字面含义与实际不符，要么如实
   描述要么修协议；(b) 我们的管线含 SPA + MiniSplat（同为第三方工作
   Mini-Splatting 的采用）而 HAC++ 不含，论文要交代"这些是采用的基础措施，
   不是贡献"。
