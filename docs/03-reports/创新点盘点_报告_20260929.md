## 0. 项目一句话

DCCA-GS 是锚点式三维高斯泼溅压缩框架：沿用 HAC++ 的表示（场景压到约 50–80 万个稀疏"锚点"上，每个锚点存一份特征向量和解码用小网络的权重，解码端用小网络从锚点长出周围的高斯），目标是在**解码端不需要任何额外文件**（零边信息）的前提下，把码流压得比 HAC++ 更小、画质更好；当前最新主线是把码流做成**渐进式**的——传一半就能看，传完最好。

## 2. 核心创新点详述

### 2.1 解码端可复现的内容自适应量化 + 渲染敏感度监督（仓库代号 I2+I6，论文中联合报告）

**它是什么**：压缩要先把浮点属性四舍五入到格点上（量化），步长取多大直接决定体积和画质。常见做法把每个锚点的步长存进码流，很占体积。本项目的做法是一个公式：步长由锚点局部密度、预测的各向异性、预测的偏移能量、有效掩码比例四个量乘算得出——这些量**编码端和解码端都能从已解码数据算出同样的值**，所以码流里完全不带步长表。再配一个小的复杂度网络按锚点调节步长粗细；训练时用"渲染敏感度"（这个位置渲染错了对画质的伤害，由训练期梯度统计得到）监督这个网络，该信号只在训练时使用，解码路径不变。

**验证状态**：
- 主操作点（4-28 场景、110k 步、λ0.004、含 MLP 量化）登记行 `phg_main/…_110k_dim50_l0p004`：**28.8235 dB @ 5.4852 MB**；HAC++ 论文参考点（登记行 `baseline/hacpp_paper`）28.311 @ 6.9462——**PSNR 高 0.51 dB，体积小约 21%**。
- 干净消融（期刊版第二轮总解析，v1.3）：三组干净对照 +0.017 / +0.066 / +0.095 dB，均值 +0.059 dB——机制有效但幅度不大，论文口径为 I2+I6 联合报告。
- **口径分歧待办**：渲染敏感度监督单独的价值在不同批次记录不一致（论文稿声明低码率区去掉它损失 0.42 dB；期刊版第二轮解析判定直接对比只差 0.021 dB、价值主要来自四个结构统计量；CSV 登记行 `phg_db_ablation` 在 110k λ0.002 配置下 I6-off 反而更高更小）。统一口径前，I6 不作为独立贡献主张。

### 2.2 混合精度 MLP 权重量化

**它是什么**：解码端的小网络权重传统按 32-bit 浮点计入码流。逐网络实测后选定：复杂度和形变网络用 8-bit，其余（不透明度、协方差、颜色、特征网格）用 16-bit——8-bit 给不透明度会直接掉画质、给特征网格会破坏熵模型反而增大属性体积，给复杂度/形变则几乎无影响。

**验证状态**（CSV 组 `phg_mlp_quant_ablation` 等）：
- 4-28 110k：5.6471 → 5.4852 MB，PSNR 28.8250 → 28.8235（变化 <0.002 dB）；
- playroom 110k：4.3819 → 4.2231 MB，PSNR 30.7310 → 30.7288；
- 16-bit 全量零画质损失（ΔPSNR 0.0000）即省 0.139 MB；**均匀 8-bit 不可取**（实测反升属性码率）。

### 2.3 训练侧锚点稀疏化（第三方 GaussianSpa 的锚点版改造，论文中如实交代为基础措施）

**它是什么**：锚点数量是体积的大头。先训练后剪枝的问题是幸存锚点没机会在最终预算下重新训练。本做法在训练中用 ADMM 投影（一种交替约束的优化方法）把锚点数逐步压向预算，幸存锚点带着预算继续训练到收敛；预算和乘子不进码流。

**验证状态**（CSV 组 `phg_spa`，playroom 30k λ0.002）：
- 锚点预算 50%：体积 4.1831 → **1.0835 MB（−74%）**，代价 −1.23 dB；
- **同锚点数对照：训练侧稀疏 29.639 dB 对编码后 topk 剪枝 24.120 dB，高 5.52 dB 且体积更小**——这是"预算要进训练、不要进编码器"的核心证据；
- 低码率工作点：playroom 110k Full SPA 29.8908 @ 1.1292 MB（论文口径 0.96 MiB @ 29.90，出处：论文稿实验章）。

### 2.4 渐进分层码流（2026-09 当前主线，证据链最完整）

**它是什么**：把属性按量化精度分成粗到细的多层：基层传全部锚点的粗步长版本（能看），增强层只传修正量（变好）。码流设计保证**在任何层边界截断都是合法且可独立解码的前缀**——像渐进式 JPEG。配套三个机制：
- **分字段粗化档位**：不同属性字段用不同的粗化倍率（特征/偏移 8 倍起步、缩放 2 倍起步并在对数域保护），消除了"粗化过头画质骤降"——同样字节量下最粗层画质 +3.4 dB（出处：变更记录 09-25 条目，15.75 MB @ 25.24 dB 对统一 16 倍层的 14.06 MB @ 21.89 dB）；
- **细层编码用已解码的粗层符号当上下文**（条件编码：已知前文时后文的概率分布更尖、编码更短）：每场景省 **1.93–2.33 MB**（出处：渐进方向现状报告 20260924 §2）；
- **零边信息契约实测**：量化步长由解码端重算，特征/偏移字段与编码端 100% 一致、缩放字段 99.999% 一致（同报告 §4）。

**验证状态**（真实码流实测，出处：渐进方向现状报告 20260924 §3，格式 `c25_layered_v1`）：
- 1-78 λ0.0005 三点：16 倍粗层 **14.06 MB @ 21.89 dB** → 4 倍层 25.70 MB @ 26.36 → 满精度 37.92 MB @ 26.93，逐层校验锚点通过；
- 2-06 与 1-78 λ0.004 各一条曲线，管线跨场景成立。
- **如实说明的代价**：静态查表编码器满精度 37.9 MB，对 HAC++ 的学习式熵模型同画质点约 21.4 MB（约 1.75 倍）——这是 §4 结构性结论的直接原因。

### 2.5 锚点重摆放（MiniSplatting 式深度重初始化，第五组件，如实按场景报告）

**它是什么**：锚点数量之外，锚点**摆在哪**也限制画质。在停止增长的迭代处，对训练相机渲染深度图、反投影回表面、体素化后作为候选锚点追加——预算不变，让新锚点和旧锚点竞争名额。

**验证状态**（出处：论文稿实验章与 3366 实验改写，CSV 有对应登记）：
- playroom 30k SPA 0.85：30.2210 @ 1.8594 → 30.4202 @ 1.9051 MB（**+0.199 dB @ +2.5% 体积**）；
- 4-28 110k：28.7359 @ 5.449 对基线 28.7477 @ 5.5137（−0.012 dB）；
- drjohnson 30k：29.3146 @ 2.0021 对 29.3899 @ 2.0379（−0.073 dB 且体积 −1.8%）；
- playroom 全预算扫描 BD-PSNR ≈ +0.124 dB、BD-rate ≈ −8.6%。
- **结论口径：场景相关的摆放机制，不主张普遍增益**——论文里正负结果一起报。

### 2.6 次模覆盖选择（有正信号，未达及格线）

**它是什么**：把"从 68 万锚点里挑子集"的打分目标从"每个锚点独立打分、求和排序"换成"保留集合盖住的**像素总量**最大"（重复覆盖不加分），用贪心求解。动机：逐点打分会重复挑覆盖同一片区域的锚点。

**验证状态**（CSV 组 `ph1v3`、`bdrate`）：
- 干净重叠区（27.50–27.73 dB）同码率对比：对自身最优非次模臂**体积 −25.7%**（登记行 `bdrate/rd_submod_vs_hacpp_1-78`）；
- λ0.004 两种子均为正（对干净复跑基准约 +0.11 dB；对后来确认崩溃的旧基准 +0.521 dB 不可用，登记行 `fill178_base_r085_lam0004_s42` 已替换该基准）；
- 六格总平均 **+0.107 dB，未达 +0.15 及格线**。
- **定位：预算最紧时的专用组件 + 负结果素材，不是全码率通用方法。**

### 2.7 渐进感知量化（仓库代号 B3，进行中，跨场景模式刚确认）

**它是什么**：渐进码流的隐患是：模型训练时只为最终精度优化，粗层（用户最先看到的画面）画质没有保障。本做法在训练损失里加一项对齐惩罚，按预设权重把粗层画质拉起来。

**验证状态**（CSV 组 `curve/layered_corrected_all`、`b3gen_*`）：
- 1-78 λ0.004：最粗层 **+0.916 dB**（修正协议）；λ0.0005：最粗层 +0.259 dB，且惩罚权重 0.01 时全层 +0.083 dB、最细层还省 4.2 MB——两个场景过预先写定的判定标准；
- 泛化复测（2-06、4-10）：最粗层 +0.117 / **+0.195（过 0.15 门）**，中间层省 2.4–4.1 MB，但**全层使用的画质代价（−0.375 至 −0.517 dB）超出容差**；
- **跨场景模式一致：基层收益稳定、增强层省字节、全层使用超容差**——使用范围收窄（例如只在基层施加）的判定是当前待办。

## 3. 与 HAC++ 的对比：主结果与口径

HAC++（Hash-based context model + Anchor Coding++，本领域公开最强的锚点式压缩方法之一）是唯一在本仓库复跑过实测对比点的外部方法（同场景 1-78、同 30k 步、同三档 λ、同随机种子 42）。

| 对比点 | 我方 | HAC++ | 差距 |
| --- | --- | --- | --- |
| 4-28 大场景 110k（主表） | 28.8235 dB @ 5.4852 MB | 28.311 @ 6.9462（论文参考点） | **+0.51 dB，小 21%** |
| 1-78 同画质平价点 | 27.8622 @ 15.2430（登记行 `ph0a_base_r100_lam0002_s42`） | 27.841 @ 20.03 | **画质持平，体积省约 24%** |
| 1-78 同体积最近点 | 27.6946 @ 13.9042 | 27.841 @ 20.03 | 体积小 30.6%，画质低 0.146 dB |
| DB-playroom 110k | 30.7288 @ 4.2231 | 30.9313 @ 4.5635 | 画质低 0.20 dB，体积小 7.5% |
| 1-78 60k 步 | 27.9492 @ 12.5009 | 27.63 @ 16.34（λ0.008） | 两轴同时占优（**训练步数不对等，只能作参考**） |

**必须交代的三条口径**：
1. **BD-rate（两条 RD 曲线间的平均码率差，行业标准指标）目前不可辩护**：我方满精度最高点低于 HAC++ 最低点，BD 数字全靠外推；CSV 里三套数字并存（base +1.5% / −25.3% / 次模 −34.2%），重算完成前一律不进论文，改用逐点对比表述；
2. 我方管线含训练侧稀疏化与锚点重摆放（后者改造自第三方 MiniSplatting），HAC++ 不含，对比时需说明；
3. 与文献调研方法（HAC、ContextGS、Smol-GS 等）的对比因切分/分辨率/体积口径不同，只作趋势级参考（出处：3366 实验改写 §3.3 的原话声明）。

## 5. 已判定关闭的方向（负结果台账，防止重复尝试）

**2026-09-28/29 新关闭的三条**（CSV 组 `enh123`，10 行；判定门全部在实验前写死，基线与生产码流同构）：

1. **把"残差是否非零"的标志概率从静态查表换成 25 KB 小网络**：净省 −0.98%（门 ≥10%），码流更大，关闭。教训：分组频率统计表已贴近该流的条件熵，25 KB 权重吞掉全部毛收益。
2. **增强层学习式上下文**（用小网络按已解码符号预测每道是非题的概率，替代"组×粗值桶"静态表）：五个最大字节流探针全败（最好的一个净省 +6.4%，门 15%；最差的一个权重比流本身大 13 倍）——**该方向第三次证负，永久关闭**。此前的"过门"记录（09-25 的 S4 判定）经同构基线复核确认为对弱基线的假阳性。结论：生产复合条件表在全部大流上已贴近条件熵。
3. **基层粗化从 8 倍提到 16 倍**（想把渐进曲线起点压进 7 MB）：无任何配置同时满足"起点 ≤7 MB 且画质落差 ≤1.5 dB"——最粗层画质落差 3.09 dB。**结构性发现：起点下限不由属性字节决定，而被约 6–7 MB 的固定几何负载（锚点坐标等）钉死。**

**更早关闭的方向**（出处：方向全景报告 20260923 §1.6 及各阶段报告，此处列名字和判定数字）：码率折扣选择（−0.035 dB）、比特预算分配（−0.113 dB）、每比特敏感度（−0.082 dB）、敏感度加权次模（加权从未生效）、背景特征码本（省 4.6% 体积但 −2.06 dB）、λ 自适应预算、Morton 序渐进、层级信息作熵模型输入、缩放字段换分布（条件编码 8.04 bit/符号已低于边际熵 8.54）、语义先验（BD-PSNR ≈ −0.10 dB）、层级上下文（+0.003 dB）、条件熵编码 P0-1（最多省 2.30%）、向量量化 I5（最好情况持平、其余 −4.6 至 −5.8 dB）。

**这批负结果收敛出的结构性结论**（出处：enh123 判定报告 §6）：静态条件表架构内的信息提取已经到顶；与 HAC++ 在满精度段 3–6 MB 的差距**不能靠在现有架构内换概率模型消除**，只能换编码架构（会破坏"可截断、零边信息"这两个主贡献约束）或接受差距、靠训练侧组件和 12 MB 以下独占区讲故事。**剩余提升空间收敛为一条：几何编码 / 锚点表示本身（未立项）。**
