## 1. 这个方向在做什么（给非专业读者）

我们的压缩对象是三维场景：约 68 万个采样格点（锚点），每个带一组数字，
量化后熵编码成约 20 MB 的文件。**渐进式传输**就是把这个文件设计成
"传一半就能看，传完最好"——像渐进式 JPEG。

两种做法：

- **选择式**：给锚点排重要性，重要的先传。先收到的部分画面不完整（缺锚点的位置是窟窿）。
- **分层式**：所有锚点都传，先传每个数字的粗糙版（画面完整、略糊），后续字节不断送修正值。

## 4. 机制验证与工程发现

1. **零边信息契约实测 100% 成立**：量化步长由解码端从已解码数据重算
   （feat/offsets 100%、scaling 99.999% 与编码器实际所用步长一致）。
   渐进文件不需要任何额外附信。S1 时代"feat 步长恢复率 0.6%"的告警正式撤销
   （当时是恢复方法不对）。
2. **盘上属性文件不可信**：`attributes.pth`（编码时写入）与解码模型张量在
   少数行差异巨大（scaling 为 log 值，最大差 21——解码端做了边界裁剪）。
   **渲染实验永远以解码模型张量为准**；本实验曾因此三次渲染报废。
3. **校验锚点机制**：任何分层渲染实验先渲满精度层，不达已知质量即整批作废。
   该机制在本轮两次拦截了坏数据（k 系数缺失、art 污染）。
4. **粗化过头画质骤降**：16×/8× 层画质崩塌（5–22 dB）——scaling 是 log 值，粗化直接
   破坏几何。**可用渐进区间从 4× 层开始**；更粗的层需对 scaling 单独保护
   （已写进 S4 设计）。
5. **真实字节轴上静态编码器仍贵**：满精度 37.9 MB 对学习式编解码器 21.4 MB
   （约 1.75×）。条件化收回 2.3 MB；剩余差距靠 S4 学习式条件头收敛
   （见 §6）。同画质对比选择式暂无体积优势——论文表述必须带着这个口径。
