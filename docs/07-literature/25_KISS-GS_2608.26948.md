> 一句话定位：把 3DGS 压缩拆成"重建 → 剪枝 → 图像化编码 → 可选量化感知微调"四个独立阶段，每个阶段的省体积收益单独计量（归因实验是它的主卖点）；编码端做得复杂，解码端只用浏览器自带的图像解码器，靠"更少的高斯 + 把属性排成平滑图像交给图像编码器"在率失真上压过 HAC++。

## 一学：问题与洞察（创新从哪来）

### 它认定的主要矛盾

作者提出的核心问题是"归因鸿沟"（attribution gap，第 1 节）：现有 3DGS 压缩方法把多种减体积手段（剪枝、量化、熵编码、训练期损失）揉在一个系统里，"this obscures where gains actually originate, creating an attribution gap"——看不出每个百分点的收益来自哪一步，导致两个后果：方法之间没法公平比较，组件没法跨流水线复用。

第二个矛盾是"训练-格式耦合"（第 1 节）：锚点类方法（指 Scaffold-GS/HAC/HAC++ 一系）把表示结构改得太深，"This training-format coupling effectively locks the codec to a particular 3DGS training pipeline"——压缩和某一种训练管线绑死，新重建方法出来，压缩方案就得重做。

第三个矛盾是部署：.ply 文件太大，浏览器、移动端、AR/VR 需要"小文件 + 简单解码"。作者引用 3DGS.zip 综述（引用 [1]）把存储缩减分成两类——compaction（减少高斯个数）和 compression（减少每个高斯的比特数）——自己再加第三类 adaptation（用编码感知的训练或微调把参数推向利于量化的形态），并把这三类做成流水线的三个显式阶段（第 1 节、图 2）。

### 支撑观察（直觉 / 数据 / 失败实验）

- 分类框架来自 3DGS.zip 综述（引用 [1]，第 1、2 节）：compaction 和 encoding 两类已各有一批方法，这是"拆阶段"主张的分类学依据。
- 单靠剪枝就能减一个数量级：Mini-Splatting（引用 [7,8]）已证明，第 1 节用它论证"compaction alone can already yield large gains"。
- HAC++ 是 3DGS.zip 排名最高的可复现方法（第 4.2 节），作者重算它作为"最强整合方法"的参照——这是"简单格式能否匹敌复杂方法"这个问题的出题依据。
- Deep Blending 上"压过的 HAC++ 超过未压缩的基线"（Playroom 30.63 对 30.42 和 30.09，Dr. Johnson 29.60 对 29.48 和 29.43，第 4.5 节）：作者用这个观察反推——HAC++ 在该数据集的优势来自 anchor 表示本身而不是压缩技巧。这是全文最诚实的一处观察，也是作者承认自身边界的地方。
- 图 1：分阶段收益 15.7×（剪枝）、6.6×（编码）、2.2×（微调），Mip-NeRF 360 上合计 228.4×。

### 显然的路为什么没走

- **没走"更强的学习式熵模型/上下文模型"**（HAC、HEMGS 一系的主流路线）：作者的核心取舍是编码端可以复杂、解码端必须简单——图像解码器硬件加速、浏览器里到处都有，而自定义熵解码器每个平台都得移植。所以它干脆不做逐高斯的熵编码，把统计建模整个外包给 WebP 图像编码器（第 3.5 节、第 5 节）。
- **没走"改表示结构"**（anchor、三平面、hash 网格）：为了保住"解码 = 图像解码 + 确定性反缩放/查表"（第 5 节），全文保留标准 3DGS 参数化（均值、四元数、尺度、SH、不透明度，第 3.1 节明确写"relies on no MLPs, hash grids, or anchor structures"）。代价是 Deep Blending 上输给锚点表示（第 5 节自己承认）。
- **没把量化感知训练当默认**：SOG 原方法把致密化、平滑正则、量化耦合在一起，作者把它拆开（第 3.3 节），SOG-XT 纯训练后编码就能打；微调（RQ3）作为独立可选项单独评测——这是刻意用消融回答"适应到底值多少"。

## 二学：机制（洞察怎么变成方法）

### 核心流程

四个阶段（图 2，各阶段训练步数：30k / 10k / 0 / 4k；各阶段后体积：基准 783 MB → 47.1 MB → 7.13 MB → 3.23 MB，图 2 标注。注意图 2 的基准写 783 MB，而图 1 图注和图 9 标注写 738 MB，两处不一致；按 228.4× × 3.23 MB 反推应是 738 MB，图 2 疑为笔误）：

**阶段 1：重建（第 3.1 节，30k 步）**。输入：任意实现产出的标准 3DGS .ply。主实验用 gsplat MCMC 重建（引用 [17]）默认参数跑 30k 迭代。输出：.ply。设计要点：压缩对训练管线零假设，高斯数量决定率失真工作点。保留原始训练管线的尺度/不透明度非线性映射，"因为映射后的取值适合均匀量化"（第 3.1 节）。

**阶段 2：剪枝 POPSpa（第 3.2 节，10k 步后处理）**。它不是新剪枝目标，是"把已发表的剪枝组件拼成一个可替换的强模块"。四个子步骤：
1. 有效秩正则（式 1，贯穿精修阶段）：抑制针状高斯。
2. 第一轮剪枝：用 GaussianPOP（引用 [20]）的移除误差判据。对每个高斯 k，ΔSE_k = ‖C_render − C′_render‖²——删掉它前后渲染像素颜色之差的平方和，对全部训练视角累加；用单遍算法高效算出全部高斯的分数，删掉分数最低的固定比例（第 3.2 节）。
3. 优化-稀疏交替精修：把 GaussianSpa（引用 [47]）训练期的方案搬到训练后，跑 5k 迭代，让幸存高斯通过重新分配不透明度和几何来补回质量；此阶段同时加有效秩正则（第 3.2 节）。
4. 第二轮剪枝（重算 ΔSE_k）+ 5k 微调。合计 10k 步。
输入：30k 步的 .ply（实验里用 320k 高斯的过参数化模型，目标剪掉约 80%）；输出：紧凑 .ply（第 4.3 节）。

**阶段 3：编码 SOG-XT（第 3.3–3.5 节，零训练步）**。输入：紧凑后的高斯集合；输出：.sogxt 容器（一组 8 位图像 + YAML 元数据）。编码器不需要相机参数和渲染器（第 3.5 节）。逐步骤：
1. **PLAS 排序**：把 N 个高斯排进 ⌈√N⌉×⌈√N⌉ 的 2D 网格（PLAS 是保空间局部性的并行分配算法，SOG 原方法引入，第 3.3 节）。位置的贡献：位置做符号对数映射后 16 位量化，拆成高字节/低字节两个 8 位平面；高字节承载粗结构、低字节是细节残差，作者的贡献是把这次拆分暴露给排序优化——PLAS 同时跑两个字节平面（高字节权重强、低字节权重弱），得到的排列作用于其余全部属性（第 3.5 节）。
2. **球谐直流项** f_dc：直接存 8 位图像（第 3.5 节）。
3. **球谐交流系数**（48 个原始切片 → 码本）：k-means 聚成 K = S² 个中心，S 取 √(N/8)、截断到 [8, 256]、向下取 8 的倍数，码本上限 256×256 = 65,536 项——作者说这是"再大 PSNR 也不涨的点"（第 3.3 节）。与 .sog 的词典序排序不同，SOG-XT 用 PLAS 把码本中心本身也排成局部平滑的 2D 网格；每个高斯的分配结果存成两个 8 位通道 (u, v)，作为索引指向这个网格（第 3.3 节）。码本中心做 100 级 min-max 量化；每个中心含 15 个非直流系数 × RGB = 45 个数，排成 3×5 块存一张 RGB 图（第 3.5 节）。
4. **PRAS 协方差平滑**（第 3.4 节，详见下文）：四元数与尺度在量化前重选代表。
5. **标量字段量化**：尺度做对数映射 + 8 位；不透明度做反 sigmoid 映射 + 8 位；四元数靠 PRAS 后可做 100 级量化（q = 99），没有 PRAS 时要 255 级才质量相当（第 3.5 节）。
6. **打包**：每通道 min-max 均匀量化，min/max 以 float32 写进 YAML 元数据（示例容器里全部元数据占磁盘总量的 0.2%，图 3）；高斯数补齐到边长为 8 的倍数的方格，多出的格子存默认值并记录活动掩码，解码时丢弃（第 3.5 节）。图像用浏览器可解码的 8 位格式（解码脚本读 WebP，附录 6.9）。
示例容器（图 3）：256,000 个活跃高斯补齐到 262,144，总 4.12 MB，折合每高斯 129 比特。构成：位置 849.5 kB（20.6%）、旋转与尺度 1.37 MB（33.3%）、颜色 1.69 MB（41.1%）、不透明度与掩码 200.7 kB（4.9%）、元数据 0.2%；颜色里 SH 交流码本本体占 721.4 kB（17.5%），UV 索引占 446.1 kB（10.8%）。

**PRAS 的机制**（第 3.4 节）：协方差矩阵到 (四元数, 尺度) 的映射是一对多的，同一协方差对应 6 × 4 × 2 = 48 个等价参数化——三个主轴半径可按 3! = 6 种排列指派到坐标轴（配合 90° 旋转补偿）；特征向量翻向 2³ = 8 种符号组合中只有 4 种满足 det(R) = 1；每个旋转矩阵又对应 q 和 −q 两个四元数（双覆盖，附录 6.5 配图解）。PRAS 做粗到细优化：先把浮点四元数和对数尺度映到 8 位代理网格；模糊半径按指数递减序列迭代，每个尺度上对当前代理做低通滤波得到空间平滑的目标网格；对每个高斯，遍历其等价类内全部 48 个候选，选与平滑目标逐通道绝对差（ℓ1 距离）最小的代表。因为搜索空间严格限制在等价类内，渲染结果（协方差）逐比特不变，只消除了"人工方差"——即同一几何因参数选取任意性带来的网格不平滑（第 3.4 节）。

**阶段 4（可选）：编码感知微调（第 3.6 节、附录 6.2，4k 步）**。每个训练步：当前高斯属性 → 量化图像张量（SOG-XT 的编码前半段）→ 从这些张量重建高斯集合 → 渲染 → 渲染损失穿过整个往返反传，取整用直通估计器（引用 [2]）。离散结构（活动掩码、PLAS 排序、SH 分配、码本布局）在开始时定死不再变；训练中 SH 分配固定、码本中心值从当前 f_rest 系数重算。损失是标准渲染目标（ℓ1 与 SSIM 加权，λ_SSIM = 0.2）加量化图上的掩码 ℓ1 全变差平滑项（四元数权重 1e−2，其余 1e−4，附录 6.2），微调中在初始、0.6、0.8 进度处重跑 PRAS。输出格式与不微调完全一致，解码器不变（第 3.6 节）。

### 关键公式（按原文抄，注明编号）

式 (1)（第 3.2 节，有效秩正则，来自 Hyung et al. 引用 [14]）：

$$\mathcal{L}_{\text{erank}} = \sum_k \lambda_{\text{erank}} \max(-\log(\text{erank}(\Sigma_k) - 1 + \epsilon), 0) + s_3$$

（txt 抽取此处为乱码 LaTeX 源码，已按 PDF 第 6 页渲染图核对转录，以 PDF 为准。）各项含义：对有序尺度 s1 ≥ s2 ≥ s3，协方差归一化特征值 p_i = s_i² / Σ_{j=1}^{3} s_j²；有效秩 erank(Σ) = exp(−Σ_{i=1}^{3} p_i · log p_i)（引用 [38]，即特征值分布的香农熵的指数）；λ_erank 是权重；ε 是防止对数发散的小量；末项 s_3 直接惩罚最小尺度（最薄的方向）。整体效果：压掉 erank ≈ 1 的针状高斯（容易过拟合训练视角），偏好 erank ≈ 2 的盘状高斯（利于表面重建）。

式 (2)（第 3.2 节，GaussianSpa 的稀疏化目标）：

$$\min_{\mathbf{a},\,\mathbf{\Theta}} \mathcal{L}(\mathbf{a}, \mathbf{\Theta}), \quad \text{s.t. } \|\mathbf{a}\|_0 \leq \kappa$$

a 是不透明度，Θ 是除不透明度外的全部高斯参数，κ 是高斯数量预算。求解在重建优化步和稀疏化步（逐步压低可牺牲高斯的不透明度）之间交替。GaussianSpa 原文在训练期做，本文把它当训练后精修用 5k 迭代。

式 (3)（附录 6.6，HAC++ 的损失，作者用它解释重算实验）：

$$\mathcal{L} = \mathcal{L}_{\text{Scaffold}} + \lambda \frac{1}{N(D_a + 6 + 3K)}\left(\mathcal{L}_{\text{entropy}} + \mathcal{L}_{\text{hash}}\right)$$

λ 控制率失真权衡；高 λ（低码率端）下延长训练只会进一步压缩、不回质量，低 λ（高码率端）下质量与迭代数基本无关（附录 6.6）。

### 信号设计（重点）

| 问题 | 答案 |
| --- | --- |
| 信号是什么（重要性/复杂度/敏感度/显著度…） | 剪枝阶段：逐高斯移除误差 ΔSE_k（删掉该高斯后训练视角渲染像素的变化量）＝重要性信号。编码阶段：2D 属性网格的局部平滑度（图像可压缩性的代理量），由 PLAS 排序和 PRAS 构造。微调阶段：量化往返后的渲染损失梯度 |
| 哪一端算得出（编码端/解码端/仅训练期） | 三种信号都只在编码端算得出：ΔSE_k 需要全部训练视角和渲染器；平滑度构造在排序阶段；微调需要训练视角。解码端不做任何统计重算 |
| 有无侧信息 | 有。每通道量化范围（float32 写 YAML，示例容器占 0.2%，图 3）、活动掩码、SH 码本本体（721.4 kB，占 17.5%，图 3）都随文件传输；但没有学习式侧信息网络 |
| 训练期还是编码期 | ΔSE_k 在编码期（训练完成后对训好的场景算）；平滑度构造在编码期；微调在编码期做、可跳过。与多数竞品不同，它的率失真主控量是高斯数量而不是熵损失权重（第 3 节开头） |
| 和渲染质量的距离（直接测质量还是代理量） | ΔSE_k 直接测训练视角的渲染变化（贴近质量但只覆盖训练视角）；图像平滑度是间接代理；微调的往返渲染损失是直接信号但开销大（图 4：512k 高斯时微调 441 秒对编码 34 秒） |

### 与码流组织相关的细节（压缩类论文必填）

- **无渐进分层，一个文件一个画质档**：SOG-XT 容器是单一固定质量的文件。率失真曲线靠 7 个独立的高斯预算点拼成（64k 起逐级翻倍，第 4.3 节），每个点都要回到阶段 2 重新剪枝再重新编码——换画质档位的代价是重跑整条流水线，不是截断文件。
- **文件布局**：一组按字段命名的图像文件（active_mask、opacities、scales、means_bytes_0/1、quaternions、f_dc、f_rest_labels、f_rest_centroids）+ container_meta.yaml（网格边长、码本边长、图像编码器名、各字段量化范围；附录 6.9 的参考解码脚本逐字段读入）。
- **可截断性**：没有。容器必须整体解码才能渲染；不存在"解码前缀得到低画质版本"的机制。
- **解码端重算哪些量**：反量化（从元数据读 min/max 线性映射）、确定性反变换（exp 还原尺度、sigmoid 还原不透明度、符号对数还原位置、3×5 拆块还原 45 通道）、UV 索引查 SH 码本。全部是逐字段固定运算，没有从已解码数据推导统计量的机制。
- **侧信息清单**：量化范围（float32，占 0.2%）、活动掩码（276 B，图 3）、SH 码本（占 17.5%）——都写进文件；另需知道各字段用哪种量化级数（写死在解码器里）。
- **填充与掩码**：高斯数补齐到 8 的倍数边长方格（PLAS 要求方形网格），补齐位置用固定默认值 + 活动掩码丢弃；附录 6.8 的"w/o grid mask (prune to square)"行证明掩码方案比按不透明度再剪掉一批要划算（体积多 3,344 B 换 PSNR 高 0.1150 dB，表 6）。

## 三学：证明与包装（创新怎么立住）

### 实验口径

- **体积的计算方式**：文件在磁盘上的真实字节数（图像容器实际大小，图 3 明确写 "on-disk size"，并给每高斯 129 比特的折算）。这与 HAC++/我们"各字段比特数求和换算 MB"的计算方式不同——它把 WebP 编码器的实际压缩效率也算进去了，两边数字不能直接混比。
- **数据集与协议**（第 4.1 节、附录 6.7）：21 个场景 4 个数据集（Tanks and Temples 2 个、Mip-NeRF 360 九个、Deep Blending 2 个、Synthetic NeRF 8 个）；训练分辨率 Mip-NeRF 360 室外 4× 下采样、室内 2×，其余原分辨率；测试统一长边 1600 px（PIL 双三次重采样）；PSNR、SSIM、LPIPS（VGG 骨干，图像保持 [0,1] 区间不用 [−1,1]）；真实数据集每第 8 张图留出做验证，Synthetic NeRF 用指定测试划分；背景色 Synthetic NeRF 用白色、其余黑色。
- **对照设定**：质量基准 INRIA-Q = INRIA 3DGS 训 40k 迭代（凑齐与自家流水线相同的预压缩预算 30k+10k，第 4.2 节）；压缩基准 HAC++ 由作者重算，跑 44k 迭代（30k+10k+4k 算力对齐，第 4.2 节、附录 6.6）；其余文献方法用 3DGS.zip 综述收集的自报数字（表 3 带 † 号者）。
- **率失真点**：7 个高斯预算，最小 64k（Synthetic NeRF 16k），逐级翻倍；过参数化模型 320k（Synthetic NeRF 80k）；未剪枝上限 T&T 与 Mip-NeRF 360 为 3000k、Deep Blending 2048k、Synthetic NeRF 640k（第 4.3 节）。

## 四学：原文关键段翻译（深读层必填）

### 方法节核心段（选 2 段）

> **原文（第 3.4 节）**："Combined, this results in 6·4·2 = 48 distinct parameter combinations within an equivalence class that describe a single Gaussian. To exploit this symmetry, we propose Parallel Representative Assignment Smoothing (PRAS). Similarly to PLAS, PRAS employs coarse to fine optimization over 2D parameter grids. First, to ensure comparable magnitudes during optimization, the floating-point quaternions and log-scales are mapped to 8-bit quantized proxy grids. The algorithm then iterates over a sequence of exponentially decreasing blur radii. At each scale, a low-pass filter is applied to the current proxies to generate spatially smoothed target grids. For every primitive, PRAS evaluates all candidates within its equivalence class and assigns the representative that minimizes the sum of absolute channel differences, i.e. the ℓ1 distance, to the smoothed targets. Because the search space is strictly restricted to valid equivalence classes, PRAS effectively removes artificial variance to improve the compressibility of scale and quaternion grids while leaving the resulting 3D covariances and grid coordinates unchanged."
>
> **译文**：合并起来，一个等价类内有 6×4×2 = 48 种不同的参数组合，它们描述的是同一个高斯。为了利用这种对称性，我们提出并行代表指派平滑（PRAS）。与 PLAS 类似，PRAS 在 2D 参数网格上做粗到细的优化。首先，为了让优化中各量幅度可比，把浮点四元数和对数尺度映射到 8 位量化的代理网格。然后算法在一串指数递减的模糊半径上迭代。在每个尺度上，对当前代理施加低通滤波，生成空间上平滑的目标网格。对每个高斯，PRAS 评估其等价类内的全部候选，选出与平滑目标逐通道绝对差之和（即 ℓ1 距离）最小的代表。因为搜索空间被严格限制在合法等价类内，PRAS 实际上消除了人工方差，提高了尺度和四元数网格的可压缩性，同时保持所得 3D 协方差和网格坐标不变。

> **原文（第 3.3 节）**："Like .sog, SOG-XT decouples encoding from reconstruction and compaction entirely, operating as a pure post-training step on any compacted scene. SOG-XT retains the PLAS-based grid layout for all attributes but replaces the 48 raw SH slices of SOG [27] with vector quantization: k-means clustering reduces the high-dimensional SH representation to a compact codebook, with only per-primitive cluster indices stored. Rather than sorting these centroids lexicographically as in .sog, SOG-XT sorts the 2D cluster centroids with PLAS, yielding a codebook that is itself locally smooth in 2D. Cluster assignments are stored as two 8-bit image channels (u, v) indexing the PLAS-sorted centroid grid. This deliberately caps the SH codebook at 256 × 256 = 65,536 entries, which was the point where increasing the codebook size no longer improved PSNR in our experiments."
>
> **译文**：与 .sog 相同，SOG-XT 把编码与重建、剪枝完全解耦，作为纯训练后步骤作用于任何剪枝后的场景。SOG-XT 保留基于 PLAS 的网格布局用于全部属性，但用向量量化替换 SOG 的 48 个原始球谐切片：k-means 聚类把高维球谐表示压缩成一个紧凑码本，每个高斯只存它的簇索引。SOG-XT 不像 .sog 那样按字典序排列这些中心，而是用 PLAS 排列 2D 簇中心，得到一个自身在 2D 上局部平滑的码本。簇分配结果存成两个 8 位图像通道 (u, v)，用来索引 PLAS 排序后的中心网格。这有意把球谐码本的上限设在 256 × 256 = 65,536 项——在我们的实验中，这是继续增大码本不再提升 PSNR 的位置。

### 主结果表述段（选 1 段）

> **原文（第 5 节）**："The payoff is substantial: KISS-GS reaches single-digit megabytes at vanilla 3DGS reconstruction quality. With 319× size reduction on Tanks and Temples in PSNR and 228× on Mip-NeRF 360, it sets a new benchmark for 3DGS compression on these two real-world datasets. A pipeline built around a simple image-based encoding format can exceed the strongest published baselines on the main real-world benchmarks while keeping deployment simple. SOG-XT reconstructs standard 3D Gaussian Splatting attributes through standard image decoding and small, deterministic rescaling and reshaping operations. This keeps implementation effort low and makes decoders easy to port across languages and platforms. Optional encoding-aware fine-tuning improves rate-distortion without changing this decoder. Deep Blending remains the main boundary, where anchor-based learned representations better absorb capture inconsistencies than the standard-splat reconstructions used as input to KISS-GS."
>
> **译文**：回报是可观的：KISS-GS 在达到原始 3DGS 重建质量的前提下进入个位数兆字节。凭借 Tanks and Temples 上 PSNR 的 319×、Mip-NeRF 360 上 228× 的体积缩减，它在这两个真实数据集上为 3DGS 压缩设立了新基准。一个围绕简单图像编码格式搭建的流水线，能在主要真实场景基准上超过已发表的最强基线，同时保持部署简单。SOG-XT 通过标准图像解码加上小的、确定性的缩放和整形运算重建标准 3DGS 属性。这把实现工作量压得很低，解码器容易跨语言、跨平台移植。可选的编码感知微调在不改变这个解码器的前提下改善率失真。Deep Blending 仍是主要边界：面对拍摄条件不一致的采集，基于锚点的学习表示比 KISS-GS 使用的标准泼溅重建吸收得更好。

| 对期刊版的威胁度 | 中高 | 撞我们的一条主张：它把"压缩与训练解耦"立成大旗，且以真实文件体积在两大真实数据集上声称超过 HAC++（我们期刊版的底座与对比基线），审稿人可能拿它问"为什么还要锚点表示 + 学习式上下文"。没撞的两条：它没有渐进码流（一个文件一个画质档，换画质档要重跑流水线），也没有零侧信息契约（量化范围和码本写进文件）。它的第 5 节自认"锚点表示更擅长吸收拍摄不一致"，反而支持我们把锚点路线用在自采无人机数据上 |

## 对 DCCA-GS 的可借鉴点

1. **PRAS 等价类代表选择**（第 3.4 节）：在 48 个等价 (四元数, 尺度) 参数化里挑网格最平滑的一个，渲染结果逐比特不变。它是一个编码端计算、解码端零开销、不改任何渲染结果的规范化步骤——完全符合我们的零侧信息契约。用到我们 scaling/rotation 字段的编码前处理：先做等价类规范化，再做分字段粗化档位，预期旋转/尺度字段的粗化可以更激进而不掉画质。验证实验：在 150 视角无人机数据上，对 scaling 和 rotation 字段单独开关规范化，测各画质档位的码长与 PSNR 变化。这是本文最值得马上试的一条。
2. **分阶段归因阶梯图**（图 1 的做法）：把"剪枝贡献 / 量化贡献 / 熵编码与条件建模贡献 / 层间条件化贡献"做成一张逐级标注倍数的率失真图，放进期刊版实验节。审稿人问"收益来自哪一步"时一图回答，也顺便回应 KISS-GS 式的归因质疑。
3. **按体积惩罚排序的逐组件消融表**（表 2/6 的格式）：每行报关掉一个组件后的码长增量（字节数）和 ΔPSNR/ΔSSIM/ΔLPIPS，按码长惩罚从大到小排。我们可对渐进分层、复合条件表、层条件上下文、B3 对齐训练逐行开关做一张同格式表。
4. **部署成本证据**（附录 6.1 的解码基准）：它给了解码毫秒数和峰值内存来支撑"部署简单"的主张。我们的渐进码流卖点之一是"前缀即低画质版本"，应补一组"截断到各画质档后前缀解码时间"的数据，把可截断性从机制主张变成部署数字。

## 与 DCCA-GS 正面对比

| 问题 | 它的做法 | DCCA-GS 的做法 | 差异与启示 |
| --- | --- | --- | --- |
| 量化怎么定 | 每通道 min-max 均匀量化，各字段固定级数：位置 16 位拆高低字节平面、四元数 100 级（靠 PRAS）、SH 码本中心 100 级、尺度/不透明度/f_dc 8 位；量化范围以 float32 存 YAML 元数据（占 0.2%，图 3） | 解码端可重算的内容复杂度量化 × 训练期渲染敏感度监督，共享一个 8→32→3 小 MLP 按分组定量化参数，零侧信息；B3 阶梯对齐量化训练 | 它用固定的量化级数 + 外置范围元数据，简单但与内容无关；我们把量化步长做成内容自适应且解码端能重算。它的四元数 100 级这条线说明：先消人工方差再量化，比加量化级数划算——这正是可移植到我们字段预处理的思路 |
| 熵编码上下文 | 自己不做熵编码：属性排成平滑图像后交给 WebP 图像编码器，统计建模全部外包；SH 交流系数用 k-means 码本 + UV 索引查表 | 二值分解区间编码（零标志→符号→幅度逐位是非题）+ 层条件熵编码（细层用已解码粗层作上下文）+（贡献组×粗值幅度桶）复合条件表 | 它赢了实现简单和跨平台移植，我们赢了码率与内容的匹配精度。它的表 2 显示图像编码本身贡献巨大（关掉 WebP +3.03 MB），说明"把属性整理得适合现成编码器"是一条真实的收益来源，我们的笔记里应把 WebP 视为它的"熵编码层"来理解它的数字 |
| 渐进/可截断 | 无。一个文件一个固定画质档；率失真曲线由 7 个独立高斯预算点拼成（第 4.3 节），换画质档要回到剪枝阶段重跑流水线再重新编码 | 单文件渐进分层码流：基层传全锚点粗量化值，增强层逐层补精度，任意画质档都是文件的连续字节前缀，bit-exact 验证 | 这是两篇论文最直接的哲学对立：它用"多个独立文件"换简单，我们用"单文件前缀截断"换部署体验。它完全没做渐进；这提醒我们：它的每个画质档文件都很小（1.3–25 MB），"多文件多画质档"的部署成本在它的场景里不高，我们要论证单文件渐进在流式/弱网/渐进加载场景的不可替代性，而不是笼统说它不行 |
| 侧信息 | 有少量非学习式侧信息：量化范围（0.2%）、活动掩码、SH 码本本体（17.5%，图 3）都随文件传输 | 零侧信息契约：解码端能重算的才可以用，否则写进码流；分组频率统计表（静态频率统计，每组存中位数、零占比、幅度进位占比）随码流传输 | 它证明量化范围这类侧信息的代价确实很小（0.2%），但 SH 码本占 17.5% 不算小——向量量化的代价是码本本身。我们的条件表同属"统计随码流走"，差异在于：它的码本是 65,536×45 的自由参数集合，我们的条件表是按贡献组聚合的少数统计量，且我们禁止任何解码端不可重算的参数 |
| 训练-压缩关系 | 完全解耦：压缩是纯后处理（10k 剪枝 + 0 步编码），接受任何标准 .ply，编码器不需要渲染器；微调可选（4k 步） | 训练期耦合：B3 阶梯对齐量化训练、GaussianSpa 式剪枝（SPA）、渲染敏感度监督都发生在训练/精修期，与码流契约绑定 | 它的主张是解耦换来可替换性和归因清晰；我们的主张是耦合换来码率收益。值得注意：它的 POPSpa 也是训练后 10k 步精修（含优化-稀疏交替），说明"训练后精修"两边都在用，真正的分歧点是量化与熵编码要不要进训练环。它的敏感性分析（图 5）显示微调只值 2.2× 且不是脆弱最优——这个数字可以反过来支撑我们"训练期对齐值不值得"的论证：值得，但要把收益讲清楚 |

（另注：两篇论文的体积计算方式不同——它报真实文件在磁盘上的字节数，我们与 HAC++ 一致按各字段比特数求和换算 MB。它的 WebP 压缩效率计入结果，我们的计算方式不计入任何外部编码器的压缩效率。引用对方数字时必须先换算或注明来源。）
