> 一句话定位：这篇在 HAC 式锚点压缩框架上做了两件事来压锚间冗余——按锚特征余弦相似度（而不是空间邻近）建一对一的"根-叶"链接，叶锚用已解码根特征做条件熵编码（COHS）；再把锚特征拆成"哈希网格查询的共享分量 + 单独编码的个体分量"（SFA）。对比 HAC 平均省 41.87% 码率（Table II），但换码率点要重新训练、码流里带 3.74% 的结构侧信息，没有渐进分层。

## 方法要点

底座是 HAC：锚点表示 + 二值多分辨率哈希网格做熵模型上下文 + 高斯分布似然 + 率失真联合训练（第 IV-A 节）。CRP-GS 加两个模块：

- **训练**：前 30000 迭代正常训练，第 30000 迭代起启用 COHS 再训 10000 迭代（早期锚特征不稳定，相似度检索没有意义）。启用时对每个锚在全体锚里按余弦相似度取前 M=10 个候选，跑锚依赖更新把锚分成叶锚（有链接指向自己的根）、根锚（被至少一个叶指向）、自由锚（无链接、也不被指向）：阈值从 τ=1 按步长 Δτ=0.05 递减到 τmin=0.8，每轮里未链接、未当过根的活跃锚在自己的候选里找相似度≥τ、同样未链接、不是根的锚，取相似度最高的做自己的根；一个锚只能当一次根，所以是一对一链接。训练期依赖更新共做两次（第 V-A 节），每次用当前最新的锚特征重算候选池再重建链接。
- **条件熵模型（式 4，本文核心公式）**：叶锚特征的均值 µ 由 [已解码（量化后）的根特征；根位置；叶位置] 拼接过 MLP 预测，标准差 σ 只从哈希网格上下文特征预测——根的对应关系只影响均值，方差仍由空间上下文决定。根锚、自由锚的特征及全部非特征属性（scale、offset）共用 HAC 式基础熵模型（式 5）：均值方差都从哈希网格上下文预测。
- **SFA（式 6）**：锚位置（量化后）查询上下文二值哈希网格得共享特征 fs（维度 Ds = ⌊ρD0⌉），与单独熵编码的个体特征 fi（维度 Di = D0 − Ds）拼成聚合特征 fa（维度与原锚特征一致），替换 Scaffold-GS 的锚特征参与高斯属性生成（式 7 继承 Scaffold-GS）。共享特征本身不做熵编码（第 IV-C 节："the shared feature is not directly entropy-coded"），它的成本藏在哈希网格里。
- **编码/解码顺序**：先根锚、再自由锚（两类共用基础熵模型），最后叶锚（条件叶熵模型）；组内按存储的锚序号处理。每个根锚编码完后，其量化解码特征被缓存，作为它对应叶锚编码时的条件——编码端和解码端用同一个量化后的根特征，条件严格一致。锚位置（几何）用标准点云编解码器压缩（第 V-C 节）。
- **损失（式 8）**：L = L_Scaffold + λ_m·L_m + λ_e·(L_entropy + L_hash) / (N(D_i + 6 + 3K))，λ_e 乘整个分式（已对照 PDF 第 8 页核对）；失真项 L_Scaffold 是 Scaffold-GS 的 SSIM/L1 加缩放正则，L_m 是锚掩码正则，率项按每锚编码元素数 N(D_i + 6 + 3K) 归一化（特征 D_i 维 + scale 6 维 + offset 3K 维）。

## 支撑观察（论文报告）

- Fig. 3（第 IV-B 节）：在 Mip-NeRF360 Bicycle 场景训练出的锚集里均匀抽 10000 个查询锚，按余弦相似度阈值 0.7 / 0.9 / 0.95 找对应锚，查询锚与对应锚的欧氏距离（按场景锚集包围盒对角线归一化）的累计分布曲线直到约 0.5（场景空间跨度的一半）还在增长——相当一部分特征高度相似的锚在空间上离得很远。
- Fig. 4（第 IV-C 节）：同一个训练好的模型，把共享特征 fs 置零渲染，画面出现结构缺失和局部不一致；把个体特征 fi 置零渲染，只剩粗糙但全局一致的低频布局。作者据此说 fs 主要装场景级的低频外观，高频细节仍在个体特征里。
- 只用一层根-叶依赖的理由（第 IV-B1 节）：多跳依赖会让量化噪声、锚掩码或上一层解码不准传导到下游所有锚的概率预测，解码器要跟更长的依赖顺序，"make partial or random access less flexible"。
- 训练期在线检索候选、更新链接，但最终码流只存掩码和链接向量，部署端不需要任何特征检索（第 IV-B1 节 bitstream format 段）。

## 码流组织

- **渐进层划分：没有。** 单档码流，换码率靠改 λ_e 重新训练一个模型（λ_e 从 1×10⁻⁴ 到 4×10⁻³，第 V-A 节），Fig. 5 的 RD 曲线上每个点对应一次独立训练；不存在可截断码流。
- **文件布局（第 IV-B1 节）**：码流里比 HAC 多两样结构数据——活跃锚掩码 m ∈ {0,1}^{N0}（N0 是掩码前锚数，按锚序号存 0/1）和链接向量 L ∈ ({1,…,Na} ∪ ∅)^{Na}（Na 是保留的活跃锚数；非空项存所选根的活跃序号，空项用哨兵值 −1）。解码器由 m 和 L 确定性恢复根/叶/自由划分；候选集 C 和训练期中间依赖指派不进码流，部署不需要在线候选检索、全对特征搜索或依赖更新。
- **侧信息**：掩码 0.03 MB（0.60%）+ 链接向量 0.16 MB（3.14%）= 0.19 MB（3.74%），相对 4.99 MB 的示例码流（Table V）；已计入全部 RD 数字。
- 解码端几乎不重算：划分从码流元数据读出，熵模型参数（µ、σ）由网络从哈希网格特征/根特征前向算出。

## 实验口径

- 指标：PSNR 为主（RGB 空间），辅 SSIM、LPIPS；体积 = 熵编码后码流总文件大小，单位 MB（第 V-A 节）。
- BD 协议（第 V-A 节）：先删被支配的 RD 点，剩余曲线用保形 PCHIP 插值拟合（率轴取对数文件大小）；BD-rate 在公共 PSNR 区间上积分对数文件大小，BD-PSNR 在公共对数大小区间上积分 PSNR；没有有效公共区间就记"–"且不计入平均。
- 数据集：Mip-NeRF360、Tanks&Temples、DeepBlending、BungeeNeRF。基线 13 个方法：原始 3DGS、Scaffold-GS、剪枝类（EAGLES、LightGaussian）、向量量化类（Compressed3D、Navaneet et al.）、熵编码类（HAC、HAC++、HEMGS、Morgenstern et al.）、自回归类（ContextGS）、渐进类（PCGS，AAAI 2026）。没比 CAT-3DGS（引用了但表里没有）。
- 训练配置（第 V-A 节）：PyTorch，单张 RTX 3090；30000 迭代稳定期 + 10000 迭代 COHS 期；候选池 M=10、τ_min=0.8、Δτ=0.05、依赖更新两次；SFA 共享比例 40%（HAC 的 50 维锚特征拆成 20 维共享 + 30 维单独编码）；λ_m=5×10⁻⁴，λ_e∈[1×10⁻⁴, 4×10⁻³]；初始量化步长 f_i 为 1.0、l 为 0.001、o 为 0.2。Ours-lowrate 用 λ_e=4×10⁻³（重码率惩罚），Ours-highrate 用 λ_e=1×10⁻⁴（重保真）。

## 其他关键数字

- 共享比例扫描（Fig. 7a）：共享特征比例 80% / 40% / 0% 三档，40% 最好；论文解释高比例 "overshare features and reduce distinctiveness"，低比例吃不到共享表示的好处。
- 码流构成（Fig. 8）：CRP-GS 特征占 31.2% 对 HAC 41.4%，锚占 9.0% 对 HAC 19.5%，Hash 占 CRP-GS 码流 31.1%；对应 31.25 dB / 4.99 MB 对 HAC 31.16 dB / 7.25 MB（txt 抽取的饼图部分标签不完整，完整构成以 PDF 图为准）。
- 运行时（第 V-C 节 Runtime 段）：解码 30.257 s 对 HAC 29.186 s；渲染 15.4 ms/帧 对 HAC 11.0 ms/帧（+4.4 ms，约 +40%），原因写明是 SFA 渲染期查哈希网格加拼接。
