> 一句话定位：把视频编码的两件套——预测编码和率失真优化——搬进 3DGS：少量锚点基元负责预测，大多数"耦合基元"只存 8 维残差嵌入；训练损失里直接加熵估计出的码率项，让基元在训练期就长成好压的形状，T&T 平均从 434.38 MB 压到 9.60 MB（Table 1）。本文是端到端一次训练，训练即量化感知（均匀噪声模拟取整），不存在 coarse-to-fine 量化感知渐进微调流程。

## 问题与洞察

### 它认定的主要矛盾

两条，都在第 1 节：

1. 基元间冗余没人管。原话："these methods independently compress each 3D Gaussian and neglect the striking local similarities of 3D Gaussians evident in Figure 2, thereby inevitably leaving significant redundancies among these 3D Gaussians"——现有方法逐个独立压缩每个高斯，无视相邻高斯属性高度相似这个事实，基元之间的冗余全留下了。
2. 两段式训练。原话："the optimization process in these methods solely centers on rendering distortion, which overlooks redundancies within attributes of each 3D Gaussian"——训练只管渲染失真，压缩是训完后的独立步骤，每个高斯参数内部的冗余（值分布是否集中、哪些维度好压）在训练时从没被优化过。第 2.2 节结尾把这两点合并重述："optimize 3D Gaussians merely by minimizing rendering distortion, and then independently compress each 3D Gaussian"。

### 支撑观察（直觉 / 数据 / 失败实验）

- 图 2（第 1 节）：统计每个高斯与其 20 个最近邻（欧氏距离最小）在各属性上的平均余弦距离，密度、颜色、尺度、旋转都集中在 0 附近——相邻高斯属性高度相似，这是预测式编码可行的直接证据。
- 图 1（第 1 节）：同期压缩方法在 T&T 上每基元比特数从几十到几百、模型 9.6–47 MB，渲染质量却挤在 23.2–23.7 dB，说明"逐基元独立量化"这条路收益已经到顶。

### 显然的路为什么没走

- 显然路 A：做更狠的剪枝加更细的向量量化（同期方法的做法）。没选，第 2.2 节给出的理由是这类方法优化只看渲染失真、压缩时又逐个处理，两类冗余都消不掉。
- 显然路 B：学 Scaffold-GS 用锚点直接"派生"耦合基元、完全不存残差。它试了：Table 5 的 "w.o. Res. Embed." 变体在 Train 场景只有 20.50 dB / 5.75 MB，比带残差嵌入的 21.49 dB / 5.51 MB 差约 1 dB，结论原话是"不加区分的派生难以捕捉耦合基元的独特特征"（第 4.3 节）。所以最终选"预测 + 残差补偿"，不是纯派生。
- 显然路 C：训练完再做量化加熵编码（两段式）。没选，把熵估计的码率直接写进训练损失端到端优化。

## 机制

### 核心流程

结构（第 3.1 节，图 3）：每个锚点基元 ω 存位置 µω、协方差 Σω 和 32 维参考嵌入 fω；每锚点挂 K=10 个耦合基元，每个只存 8 维残差嵌入 gk（维度设置在第 3.4 节）。

训练期（端到端一次训练，训练完即得最终基元）：

1. 基元间预测（第 3.2 节，图 4）：fω 与 gk 通道拼接得预测特征 hk。几何属性把锚点做仿射变换"翘曲"过去：平移 tk、缩放 Sk、旋转 Rk 各由一个小网络从 hk 预测（式 3），作用到锚点的 µω、Σω 上（式 2、4）。外观属性（颜色、不透明度）用 hk 加上相机位姿生成的视角嵌入 ε 预测（式 5）。
2. 熵估计即码率模型（第 3.3 节，图 5）：对标量 Σω、参考嵌入 fω、残差嵌入 gk 做标量量化（式 6）；训练时量化不可导，用均匀噪声模拟取整得到可导近似（式 7）。fω 的概率用超先验参数化的高斯建模（式 8），码率按负对数似然算（式 9）；f̃ω 再当上下文去建模 Σω 的分布（式 10）和 gk 的分布（式 11，g 另配自己的超先验），各自的码率见式 12，每组基元总码率见式 13。量化步长：sf、sg 固定为 1，sΣ 可学习、初值 0.01（第 3.4 节）。
3. 率失真联合优化：损失 = λ·码率 + 渲染失真（式 1），λ 取 {0.001, 0.005, 0.01} 得三个码率点（第 3.4 节）。量化动在训练前向里（加噪声），锚点数量由 Scaffold-GS 式自适应控制管理（第 3.4 节）。所谓"熵约束正则"的全部机制 = 式 13 求和出 R，乘 λ 放进式 1，与渲染失真一起端到端最小化，没有额外的显式正则项。

编码期（第 3.4 节）：fω、Σω、gk 按学到的概率分布算术编码；锚点位置单独用点云编码器 G-PCC 压；网络权重也进码流（图 8 把它画为码流组件之一）。

解码期：解出锚点与残差嵌入，跑同一套预测网络恢复全部耦合基元的几何与外观属性，直接泼溅渲染。编码 6.27 s、解码 4.46 s（Table 7）。

### 关键公式（按原文抄，注明编号）

优化目标（式 1，照 txt 抄）：

> Ω∗, Γ∗ = arg max_{Ω,Γ} L = arg max_{Ω,Γ} λR + D

txt 抽取为 arg max；按上下文应是极小化 λR + D（CompGS++ 的式 (1) 就写作 arg min），疑为抽取或排版问题，原文公式以 PDF 为准。λ 是权衡码率与失真的拉格朗日乘子，{Ω, Γ} 是锚点/耦合基元集合。

标量量化与可导近似（式 6–7）：

> ˆΣω = Q(Σω/sΣ), ˆfω = Q(fω/sf), ˆgk = Q(gk/sg)
> ˜Σω = δΣ + Σω/sΣ, ˜fω = δf + fω/sf, ˜gk = δf + gk/sg

Q 为标量量化，{δ} 为均匀分布的量化噪声。式 7 第三项的噪声 txt 写作 δf，按上下文应为 δg，疑为抽取笔误，以 PDF 为准。

超先验熵模型（式 8–9）：

> p(˜fω) = N(τf, ρf), with τf, ρf = Ef(ηf)
> Rfω = Eω[−log p(˜fω) − log p(ηf)]

Ef 为参数预测网络，ηf 为从 fω 抽取的超先验；超先验自身的概率用分解熵瓶颈（Ballé 等 [1]、[2]）估计。ηf 是要编码传输的，其码率含在 Rfω 里。

上下文条件熵（式 10–12）：

> p(˜Σω) = N(τΣ, ρΣ), with τΣ, ρΣ = EΣ(˜fω)
> p(˜gk) = N(τg, ρg), with τg, ρg = Eg(˜fω ⊕ ηg)
> RΣω = Eω[−log p(˜Σω)],  Rgk = Eγk[−log p(˜gk) − log p(ηg)]

即 f̃ω 的量化值同时充当协方差和残差嵌入熵参数预测的条件（⊕ 为通道拼接）。每组基元码率（式 13）：Rω,γ = Rfω + RΣω + Σ_{k=1..K} Rgk。

### 信号设计（重点）

| 问题 | 答案 |
| --- | --- |
| 信号是什么（重要性/复杂度/敏感度/显著度…） | 没有显式的重要性或敏感度分数；用熵模型估计的每基元码率作为"压缩代价"信号，与渲染失真共同构成训练目标 |
| 哪一端算得出（编码端/解码端/仅训练期） | 概率分布由超先验网络加上下文给出，解码端持有相同网络与超先验（超先验随码流传输），熵解码可用 |
| 有无侧信息 | 有：超先验 ηf、ηg 是侧信息，其码率计入总码率（式 9、12） |
| 训练期还是编码期 | 训练期作损失正则（与两段式方法的分界）；编码期只做算术编码，无额外决策 |
| 和渲染质量的距离（直接测质量还是代理量） | 码率项是代理量；失真项 D 直接用渲染损失（第 3.3 节："the distortion item D is provided by the rendering loss [17]"） |

## 实验与结果

### 实验口径

- 数据集与协议：Tanks&Templates、Deep Blending、Mip-NeRF 360，遵守 3DGS 协议（3DGS 指定的场景与初始点云，每 8 视图取 1 个测试，第 4.1 节）。
- 体积口径：模型大小 MB，含 fω/Σω/gk 的算术编码码流、G-PCC 压的锚点位置、以及网络权重（图 8 的码流构成里三者并列出现）。
- 对比对象：3DGS 原版加四个同期压缩方法（Navaneet、Niedermayr、Lee、Girish），全部按各自默认配置重训；每个方法跑 5 次独立评测取平均以消随机性（第 4.1 节）。
- 指标：PSNR/SSIM/LPIPS 加训练/编码/解码/每视图渲染时间（Table 7）。

### 主结果（注明表号）

- T&T 平均：23.70 dB / 9.60 MB（3DGS 为 23.72 dB / 434.38 MB），压缩比 45.25×–73.75×；同档对比方法最低也要 17.65 MB（Table 1、第 4.2 节）。
- Deep Blending：29.69 dB / 8.77 MB，比 3DGS 的 29.54 dB 还高 0.15 dB，压缩比 75.94×–110.45×（Table 2）。
- Mip-NeRF 360：27.26 dB / 16.50 MB（3DGS 788.98 MB，89.35×）；单场景 Stump 从 1149.30 MB 到 6.56 MB，175.20×，论文把这归因于该场景内在的局部相似性强（Table 3、第 4.2 节）。
- 复杂度：训练 37.83 min、编码 6.27 s、解码 4.46 s、渲染 5.32 ms/视图（Table 7）。

### 消融设计（注明表号）

- 渐进叠加：Table 4 在 3DGS 上先加混合基元结构，Train 257.44→48.58 MB、Truck 611.31→30.38 MB；再加率失真优化，Train 48.58→8.60 MB（再省 82.30%）、Truck 降 65.08%。两个组件各自的贡献拆得干干净净。
- 替换实验：Table 5 用 Scaffold-GS 式纯派生替换残差嵌入，Train 掉 0.99 dB（20.50 对 21.49），证明"预测加残差"优于"纯派生"。
- 超参扫描：Table 6 扫每锚点耦合基元数 K=5/10/15，PSNR 22.04/22.12/21.90 dB，K=10 最优；K=15 反而掉，解释是耦合太多预测变不准。
- 码流构成分析：图 8 三个码率点上锚点基元每基元 128.26/102.1/80.65 bit，耦合基元仅 15.36/9.11/6.52 bit（约锚点的 1/8–1/12）；正文结论是耦合基元数量远多于锚点但总码流占比与锚点接近（第 4.3 节）。（占比图中三组件的百分比抽取后与组件标签的对应关系不明确，此处只引单位比特数。）
