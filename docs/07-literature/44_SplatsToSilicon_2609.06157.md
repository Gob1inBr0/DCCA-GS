> 一句话定位：这篇把散在表示/算法、GPU 运行时、专用硬件三个社区的 3DGS 效率研究放回同一条"投影—排序—混合"执行路径，用五个工作量计数追踪每项优化到底省了什么物理工作、省下的工作有没有传导到最终时间，并补做复现测量和受控 GPU 剖面；它不提出新的压缩或加速方法，但给出一套核查效率声明的归因方法和评估原则。

## 问题与动机

原话（第 1 节）："Existing studies pursue efficiency through representation and algorithm design, GPU runtime optimization, and architectural support, but their reported gains correspond to different points along the rendering and update paths."压缩论文报文件大小，运行时论文报局部加速比，硬件论文报特定阶段的帧率——三个数字测的不是同一段路。模型大小只描述存储成本，关联记录数和像素求值数只描述每帧工作，局部加速比只覆盖被计时的那一段执行，所以"没有任何单一指标能刻画端到端系统性能"（第 1 节原话）。

支撑观察：

- 证据覆盖审计（附录 B，Fig. 9）：在审计的 59 篇适用工作中，质量与端到端性能联合报告的占 98.3%；在此基础上要求工作量证据降到 69.5%，再要求分环节计时降到 54.2%，再加显存/流量是 57.6%（Fig. 9b）。分指标看（Fig. 9a）：质量、表示规模/高斯数覆盖 100.0%，端到端延迟/帧率 98.4%，功耗/能耗 85.0%，训练/在线更新 77.5%，工作量计数和分环节计时各只有 69.4%，显存/流量 64.5%。多数论文只报两头（质量+总时间），中间"工作量怎么变"这一层大面积缺失。
- 瓶颈会随优化移动（第 2.2 节）：多项跨平台研究把像素级混合认定为推理时间的主要来源（引 [14][33][34]）；一旦专用硬件加速了光栅化，排序及其 DRAM 流量会成为下一个主要成本（引 [36]）。训练侧另有梯度原子更新冲突、参数/梯度/优化器状态占显存、超出显存后主机-设备传输主导迭代时间。"当前瓶颈在哪"取决于场景、平台和已做过的优化，不能套固定结论。
- 反例（第 6.1 节，Fig. 8）：gsplat 相对 Graphdeco 官方实现把每视角关联记录中位数减少约 42%，但独立测得的完整前向时间只降 4%，DRAM 流量反而升 19%——上游计数大幅下降不等于端到端变快。

论文的做法定位：不做第三份按时间线罗列方法的分类综述（摘要指出已有综述覆盖压缩、应用、硬件加速，引 [26]–[32]），而是建立一套跨社区通用的记账语言，把每个研究放回同一条路径上定位（第 2.3 节）；拒绝跨论文数值归一（附录 C.1 明确：只在同一来源内部条件匹配时直接比较数值，不跨论文归一，数据"既不支持跨论文排名也不支持回归"，代价是给不出"谁最快"的总榜）；不把"计数下降"当结论，而是追问传导链：减少是否到达下游执行（第 6.1 节标题 "Workload Reduction Must Reach the Backend"）、每阶段粒度是否匹配（6.2）、加速后瓶颈移到了哪（6.3）。

## 分析框架（方法要点）

1. **执行路径**（第 2.1 节，Fig. 2）：标准 GPU 实现走瓦片化路径——可见性筛选选出当前视角的高斯，投影算出屏幕空间足迹和深度；每个足迹展开成"高斯-瓦片"关联记录，按瓦片分组、按深度排序；像素线程遍历自己瓦片的有序列表，求值高斯响应、不透明度，做前后向 alpha 合成。前向三阶段：Projection（可见性处理 + 屏幕投影 + 足迹构建）、Sorting（关联记录生成 + 按瓦片分组 + 深度排序）、Blending（像素级求值 + 有序合成）。可微的 Backward 路径把图像空间损失传回高斯参数并从大量像素汇总梯度，Update 阶段再做参数与密度控制更新。
2. **五个工作量计数**（第 2.4 节，Fig. 2）：Nresident（渲染内存池里存的高斯数，乘每高斯字节数决定属性显存；层级/流式系统里不在受测内存池里的高斯不算）→ Nactive（经帧选择、可见性剔除、投影足迹测试后留下、至少生成一条关联记录的高斯数；被投影拒绝但仍花了投影工作的输入不计入）→ Npair（展开产生的高斯-瓦片关联记录数，一个活跃高斯可产生多条；决定写入、排序工作量和后续读取）→ Neval（像素线程执行的高斯求值/贡献测试次数，被拒候选也算，因为测试已经跑了）→ Nblend（通过测试、真正更新像素颜色和透射率的贡献数）。同帧同后端下 Nblend ≤ Neval；理想无损预筛选应保持 Nblend 不变；理论下界是 Neval = Nblend，预筛选自身的工作要另算。相邻计数之比随场景、视角、分辨率、瓦片配置、剔除策略和后端语义变化，所以减少一个计数不保证后续计数按比例下降。
3. **三问归因**（第 2.3 节）：对每个研究回答"优化发生在哪（第一个被影响的操作）""什么物理工作量变了（表示大小、每帧工作、数据移动、同步，以及被保存下来的深度序/图像/梯度/优化器数据/更新掩码如何流经后续阶段）""怎么实现（消除/重组/重映射/重用）"。第 3 节（算法，含表示压缩、视角与尺度自适应激活、屏幕空间工作、动态场景）、第 4 节（GPU 运行时，含空间划分与列表组织、协作调度与同步、大规模数据摆放）、第 5 节（架构）都用这套问题组织，逐项登记进 Table 1/2/3。

测量补强（附录 C）：受控瓦片实验——固定场景与实现，只动瓦片大小（8/12/16/24/32 像素），从具体化的关联列表和逐像素候选列表收计数，测阶段时间和列表不均衡（Fig. 6a–c）；固定测量群体画计数与内核时间的关系——bicycle/bonsai/truck/drjohnson 四场景，30K 与 7K 高斯、800px 与更高分辨率、瓦片 8/16/32（Fig. 7）；同输入跨后端——同一模型同一视角集跑六个后端（Graphdeco、gsplat、FlashGS、StopThePop、Speedy-Splat、Faster-GS），比活跃高斯数、关联记录数、内核时间占比、无剖析器完整前向延迟和 Nsight Compute 的 DRAM 流量（Fig. 8）。测量用 NVIDIA RTX 3090（附录 C.2）；完整前向延迟在不挂剖析器时采集，内核占比与流量用 Nsight Compute replay 分开测。工具链开源：GSPROF v0.4.1，MIT 协议（附录 C.4）。

关键公式（第 2.1 节；全篇只有这三个基础公式，框架主体是第 2.4 节的计数定义）：式 (1) Σ_i = R_i S_i S_i^T R_i^T——协方差用尺度阵 S_i 和旋转阵 R_i 参数化。式 (2) Σ′_i = J_i W Σ_i W^T J_i^T——W 是相机变换，J_i 是高斯中心处透视投影的局部雅可比；屏幕空间协方差决定足迹以及该高斯能影响到的瓦片和像素。式 (3) C(p) = Σ_i T_i(p)α_i(p)c_i，T_i(p) = Π_{j<i}(1 − α_j(p))——像素 p 上各高斯按前到后合成；合成结果依赖顺序；贡献测试可以拒掉弱候选，累积不透明度达到阈值后遍历可提前终止。

### 信号设计

| 问题 | 答案 |
| --- | --- |
| 信号是什么（重要性/复杂度/敏感度/显著度…） | 五个工作量计数（Nresident/Nactive/Npair/Neval/Nblend）+ 内核时间占比 + DRAM 流量 + 完整前向/迭代延迟。是渲染路径各环节的物理工作量计数，不是质量或重要性的代理量 |
| 哪一端算得出（编码端/解码端/仅训练期） | 渲染或训练执行时在 GPU 上测得（计数取自具体化的高斯-瓦片列表和逐像素候选列表，附录 C.2），与训练无关 |
| 有无侧信息 | 不适用——不是压缩论文；配套 GSPROF 工具与证据包开源（MIT，附录 C.4） |
| 训练期还是编码期 | 都不是；是对推理与训练路径的剖面测量 |
| 和渲染质量的距离（直接测质量还是代理量） | 与质量分开度量：计数解释时间和流量，质量另行检查（Table 4 单独给出五个后端相对 Graphdeco 的最大逐视角 PSNR/SSIM/LPIPS 差）；第 7.1 节主张在质量约束下做效率比较 |

## 实验口径

- 文献语料：检索冻结于 2026-08-20，来源覆盖 CVPR/ICCV/ECCV/SIGGRAPH/TOG/NeurIPS/ICLR/ASPLOS/HPCA/MICRO/DAC/DATE/ICCAD 及 arXiv 等（附录 A）。定量收录必须能识别受影响的工作量或资源量、对比基线、输入与配置、质量设置、计时的操作范围，缺项记"不可用"。
- 数值比较规则（附录 C.1）：只在同一来源内部条件匹配时直接比较；报告值、由表格算术推导的值、综述自测值分开登记。
- 自测口径（附录 C.2/C.3）：RTX 3090；每个场景-视角结果只对同一来源在参考瓦片尺寸下的对应结果归一；计时采集前先检查输出一致性和计数不变量；计数是"实现相关"的，因为各后端剔除与求交语义不同。

## 对照实验与关键数字

- 受控单变量：固定场景与实现只动瓦片大小（8–32 px），得到"细瓦片升 Npair、粗瓦片升 Neval、Nblend 几乎不变，完整 GPU 时间在两端之间取最小"的粒度权衡，且瓦片列表不均衡在各尺寸下都存在（第 4.1、6.2 节，Fig. 6a–c）。
- 固定输入换实现：同一模型同一视角集跑六个后端（Fig. 8），把"实现差异"从"输入差异"里剥出来；质量差异只用这些视角另查（Table 4，附录 D）。
- 同源内配对散点：渲染加速比对存储压缩比（Fig. 4a）、高斯数减少（4b）、活跃高斯减少（4c）、关联记录减少（4d）各画一板，每点只与同源基线比，同类减少量对应的加速比可差数倍（Fig. 4 说明）；附录 C.1 列出覆盖方法，含 HAC++。
- 传导链分解（第 6.1 节）：gsplat 关联记录中位数减 42%，完整前向只快 4%、DRAM 流量升 19%；减少确实传导到了基数排序（其内核流量中位数从 0.58 GB 降到 0.34 GB），但 gsplat 把位置、不透明度、球谐系数等属性收集进紧凑数组，各通用索引内核合计每视角中位数搬运 0.47 GB、约占 gsplat 总 DRAM 流量的 27%，属性准备抵消了排序的收益。
- 压缩方法的报告口径（第 3.1 节）：文件大小、解码后显存、高斯数、解码时间需要分开测量；Table 1 给 HAC++ 登记的工作量是"编码字节+显存内属性字节"，代价是上下文构建与解码。
- 局部加速与端到端（第 6.3 节）：局部加速会改变整个任务的成本分布；引 Faster-GS——光栅化优化后 Adam 参数更新成为主要瓶颈；占比上升不等于绝对成本上升，需要完整迭代计时。

## 论文声明的贡献与规律（引言末段三个规律照抄 + 自行归纳）

1. "The system benefit of an upstream reduction depends on the balance between the downstream computation or data movement it eliminates and the processing it adds."——上游减少的系统收益取决于它消除的下游计算/数据移动与它新增的处理之间的平衡。
2. "Different stages favor different granularities, and changing granularity redistributes overhead across stages."——不同阶段偏好不同粒度，改粒度会把开销在各阶段间重新分配。
3. "Local acceleration changes the cost distribution of the complete task; further optimization therefore requires reassessing which computation, transfers, or updates actually limit performance."——局部加速会改变整个任务的成本分布，继续优化前要重新确认什么真正在限制性能。
4. [综述框架，自行归纳] 五计数加三问的归因语言，把算法/GPU 运行时/硬件三个社区的工作放进同一条路径比较。
5. [测量，自行归纳] 复现测量与受控剖面把计数联系到阶段时间和显存流量，识别出属性准备这类被帧率指标掩盖的流量来源。
6. [工程，自行归纳] 四条评估原则（质量约束、输入可溯源、计时口径一致、持续运行测量）加开源 GSPROF 证据包。
