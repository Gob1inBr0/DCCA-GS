> 一句话定位：把动态 3DGS 序列的传输做成 DASH 式可分级流——每个 GOP 首帧训一个带多分辨率渲染监督的帧内锚点（一个模型同时服务 540p/720p/1080p 三档），后续帧用"KNN + 双边 + 轻量 transformer"三选一的帧间预测编残差，每个重建帧内部再按"不透明度×体积"重要性排序切成 10%–100% 的高斯前缀精炼单元，三种可分级结构统一映射成 MPEG-DASH 的表示与子表示，客户端按带宽选档。它省的不是单帧体积（单位高斯码率很高，Table I），省的是"传输时不必发完整流"。

## 方法要点

- 输入是动态场景的高斯帧序列 {G_t}，每个高斯 g_i = {x_i, s_i, q_i, α_i, c_i}，即中心、尺度、旋转、不透明度、球谐系数（式 1，第 II.A 节）。
- 帧内锚点（每个 GOP 首帧 t=a，第 II.B 节）：高斯模型在原始场景分辨率训练，但渲染损失在目标分辨率集合 R={540, 720, 1080} 每档各算一遍加权求和（多分辨率损失 L_MR，式 3：每档 λ_r 加权，β 平衡 L1 与 SSIM）；同一个帧内表示在多个目标分辨率下渲染和监督，不为三档分辨率分别训练 PLY 模型（第 II.B 节原话："we do not train separate PLY models for 540p, 720p, and 1080p; instead, the same intra Gaussian representation is rendered and supervised at multiple target resolutions."）。可分级帧内包"通过控制传输的高斯子集和增强信息"生成；三档高斯数 278127（I540）→ 292580（加 I720）→ 348060（加 I1080，Table II），高档是低档高斯集的扩集，靠加高斯升档，不是给同一批高斯补精度；"增强信息"具体是什么，论文未报告。
- 帧间预测与选择（第 II.C 节，在重建的 1080p 高斯域进行）：对 P 帧每个目标高斯，三个预测器候选——KNN 特征迁移、双边预测、transformer——各自给出属性估计（式 5）；编码端逐高斯选属性 L1 误差最小的那个（式 6），用选中的预测形成残差（式 7）；预测器索引作为侧信息传输（第 II.C 节原话："The predictor index p*_i is transmitted as side information so that the decoder can reproduce the same prediction."），解码端靠它复现同一个预测。transformer 预测分支（式 8-15）：参考帧中目标高斯的 K 个近邻各转成 token（PCA 域球谐压缩信息 + 相对几何），经仿射门控、嵌入、单头注意力（带傅里叶相对位置偏置）、前馈块后输出目标高斯的 PCA 域球谐预测，用 L1 损失训练（式 15）。注意：贡献与摘要称 transformer 用于跨质量层和时间预测，但方法节只给出时间方向（前帧预测当前帧）的机制，跨质量层预测如何做没有展开，也没有对应实验。
- 残差量化与熵编码（第 II.C 节，继承 InterGS-Lite [18]）：球谐残差用矢量量化；不透明度、尺度、旋转残差用标量量化加熵编码；量化步长如何定、熵编码上下文是什么，本文未报告（细节在参考文献 [18]）。
- 时间层（第 II.D 节）：GOP 内分基层时间层（7 帧 GOP 示例为 I₁→P₃→P₅→P₇，帧率减半，式 17）和 B 层增强（B₂,B₄,B₆，用最近前一重建锚点做 P 式前向预测，不是真双向预测，第 II.D 节自述："For simplicity, these B-layer frames are not coded with true bidirectional prediction."，式 18）。帧重建 = 预测 + 重建残差（式 16）。
- 帧内精炼单元（第 II.E 节）：帧重建后对每个高斯算重要性分数 ρ_i = σ(α_i)·exp(s_{i,x}+s_{i,y}+s_{i,z})（式 19-20；3DGS 存 logit 不透明度和 log 域尺度，先 sigmoid、再 exp 还原成体积；免训练闭式公式，灵感来自 RAP [19] 但未采用其前馈网络），按 ρ 降序得排序 π，按百分比取前缀子集（式 21），前缀互相嵌套 G̃¹⁰⊂G̃²⁰⊂…⊂G̃¹⁰⁰（式 22）；实验用 10/20/30/50/100 五档（Table I）。精炼百分比只作用于时间帧的精炼单元，帧内锚点始终全额传输（Table I 标题写明 "after the full intra anchor"）。ρ 只用到已解码的尺度和不透明度，解码端拿到重建帧后原则上能重算，但排序由哪端计算、排序表是否进码流，论文未报告。
- DASH 打包映射（第 II.F 节）：GOP 当时间片段；空间层、时间层、精炼单元暴露成可选择的表示/子表示；manifest 记录包类型、时间层、精炼百分比、字节大小、每高斯比特数、高斯数、预测器元数据、依赖关系。所需带宽 R_bw = 8·B_GOP/T_GOP，T_GOP = 4/30（30fps、4 帧 GOP），B_GOP 为所选操作点的传输字节数（式 23）。能否在任意字节位置截断且逐比特一致（bit-exact），论文未报告。
- 解码（第 II.G 节）：按 manifest 里的依赖图解码；低带宽客户端先解码紧凑帧内表示快速启动；要进入全分辨率时间链，先解码完整质量的帧内锚点，之后各帧用与编码端相同的重建参考帧加传来的预测器索引复现预测；帧内渲染只用已收到的重要性前缀，单元到得越多画质越高。论文不涉及剪枝。
- 组件来源：时间预测整体搬 InterGS-Lite [18]（同一第一作者的先前工作），重要性分数用零训练闭式公式（灵感来自 RAP [19]），打包沿用 MPEG-DASH 结构 [16]；自己新写的只有多分辨率渲染损失（式 3）和 transformer 预测分支（式 8-15）。

## 实验口径

- 数据：MPEG 通用测试条件中的三个前向视角动态序列：bartender semitracked、cinema semitracked、breakfast semitracked（第 III 节）。
- GOP 结构：4 个显示帧 {0,1,2,3}，组织为 I₀（可分级帧内锚点）、B₁、P₂（基层时间层）、B₃（第 III 节）。
- 指标：RGB-PSNR、SSIM、LPIPS；带宽按式 (23) 换算（30fps、4 帧 GOP），单位 Mbps；体积单位 MB。
- 没有和任何外部方法比数字：引言把 G-PCC/V-PCC 称为"标准化锚点"（其引文 [10]-[12]），实验节没有给出对比数据；也没有与 InterGS-Lite 原版（去掉 transformer 分支）的对比。
- 没有消融表（Table I、II 是同一码流在不同层组合、不同精炼档下的操作点扫描）：transformer 预测分支没有"只用 KNN+双边"对照；多分辨率渲染损失没有"只用 1080p 损失训练"对照；重要性排序没有与随机排序、按体积排序的对照（第 III 节只有 "importance-ordered refinement units provide stable bandwidth-quality scalability" 的定性结论）。
- 训练配置：KNN 邻居数 K、transformer 参数量、λ_r 与 β 的取值、训练迭代数、编码/解码耗时，均论文未报告。
- Fig. 1-3：三个序列从 10% 到 100% 精炼档，PSNR/SSIM/LPIPS 全部单调变好；100% 档每时间帧精炼高斯数：bartender 421.7k、cinema 363.4k、breakfast 893.1k（图例数字）。
- 正文补充数字（第 III 节）：空间档从 13.80 MB 到 21.75 MB 时 PSNR 从 30.45 dB 升到 34.12 dB；加时间层与精炼档后从 23.46 MB 到 38.82 MB 时 PSNR 从 22.86 dB 升到 32.34 dB、LPIPS 从 0.365 降到 0.164。
