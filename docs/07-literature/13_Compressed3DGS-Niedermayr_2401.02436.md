> 一句话定位：对训好的 3DGS 做"敏感度感知向量聚类 + 量化感知微调 + Morton 序熵编码"，真实场景压缩最高 31x（Table 8：bicycle，1450.277→47.147 MB）、平均 26x，平均只掉 0.23 PSNR（第 6.3 节），还附带一个硬件光栅化渲染器拿到最高 4x 渲染加速。

## 一学：问题与洞察（创新从哪来）

### 它认定的主要矛盾
3DGS 场景几百 MB 到 GB 级，低显存设备（手机、头显）放不下；同时 Kerbl 的软件光栅化管线没法和 VR/AR 里既有的多边形硬件光栅化共存（第 1 节）。它把两个问题一起解：压缩表示 + 硬件光栅化渲染器。在压缩一侧，它的核心判断是：SH 系数和协方差参数占了存储大头且"highly redundant"（第 1 节），但冗余不均匀——"While a slight change in one parameter of a Gaussian can cause a significant difference in the rendered image, a similar change in another parameter or the same parameter of another Gaussian can have low or no effect"（第 4.1 节）。所以量化不能一刀切，要按参数对渲染的敏感度分级。

### 支撑观察（直觉 / 数据 / 失败实验）
1. Fig. 3（Playroom/Truck/Garden 三场景）：SH 向量敏感度直方图呈现长尾，只有不到 5% 的 SH 向量敏感度显著高于其余（第 4.1 节："For a small percentage of all SH coefficients (< 5%), the sensitivity measure indicates a high sensitivity"）。这是"各参数敏感度差异大"的直接证据。
2. 附录 E：最多 15% 的高斯颜色参数敏感度为 0（对训练图像完全无贡献），可直接剪掉（Table 3 里的 Pruning 步）。
3. 两个引用来的旁证：Li et al. [15] 在体素 NeRF 上发现只有少量体素对训练图像贡献显著；本文在 3DGS 上观察到类似行为（第 4.1 节）。
4. 失败实验（第 6.5 节 Limitations）：尝试对位置做格点量化、甚至把格点约束嵌进训练，均因显著画质损失失败——位置不能压，这是它方法的边界。

### 显然的路为什么没走
1. 对所有属性做均匀标量量化：均匀量化没有"哪些参数不能碰"的概念，而 Fig. 3 证明少量参数极敏感。它选 VQ + 敏感度豁免：高敏感向量不聚类、原样进码本。
2. 位置压缩：这是同类工作（含后来的锚点式方法）都绕不开的问题，它试了且失败（第 6.5 节），所以它的压缩只覆盖 SH 和形状参数——这也解释了为什么后续锚点式方法（含我们）都从"改表示、隐式管理位置"下手。
3. 压缩完不补偿：聚类必然丢信息，它没有止步于此，而是接量化感知微调把信息找回来（Table 3 显示 QA finetune 把 PSNR 从 25.781 拉回 26.746），这是"量化+训练"组合拳，而不是单纯后处理。

## 二学：机制（洞察怎么变成方法）

### 核心流程
输入是 Kerbl 训好的场景（Mip360/T&T/DB 用官方重建，NeRF-Synthetic 自己训，第 6.1 节）。三步流水线（Fig. 2）：
- 第一步 编码期·敏感度感知向量聚类（第 4.1 节）：对每张训练图像做一次反向传播，得到每个参数的敏感度。SH 系数（按向量整体）和"归一化协方差"（形状）分别聚成两个码本，默认各 4096 条（第 6.2 节）。敏感度超过阈值 βc 的 SH 向量、超过 βg 的形状向量不参与聚类，原样加入码本（豁免）。形状先重参数化 s = η·ŝ（η=‖s‖₂，式 (7)），聚类在归一化协方差上进行，每个高斯只存码本索引加标量 η。聚类结束后对码本条目做特征分解，拆回 4 个四元数 + 3 个尺度标量（第 4.1 节）。顺带：零敏感高斯（最多 15%）直接剪掉（附录 E）。
- 第二步 编码期·量化感知微调（第 4.2 节）：聚类后微调 5000 步。用 Min-Max 的 k-bit 伪量化（前向按移动平均的 min/max 做 round，反向直通不量化），除位置外全部压到 8-bit；位置用 16-bit float（再低质量掉得多）。量化位置：opacity 在 sigmoid 后、scale/rotation 在各自归一化前、尺度因子 η 在指数激活前。微调对象是位置、opacity、η 以及两个码本的条目（码本条目按累积梯度更新）。min/max 这两个重标定量以全精度存储。
- 第三步 编码期·熵编码（第 4.3 节）：高斯按位置沿 Z 序（Morton 序）重排，让空间相干的属性（颜色码本索引、η、位置）在字节流上连续，再用 DEFLATE（LZ77 + Huffman）做熵编码和游程编码；两个码本索引按码本大小压到实际需要的位宽。
- 解码期：解压 + 查码本，没有任何网络。渲染用 WebGPU 硬件光栅化（第 5 节），每高斯两个三角形，99% 置信区间裁剪。

### 关键公式（按原文抄，注明编号）
注意：txt 双栏抽取导致公式本体与编号错位，以下编号-公式对应按上下文判断，以 PDF 为准。

式 (3)，敏感度定义（第 4.1 节）：

S(p) = (1/N) · Σ_{i=1..N} (1/P_i) · Σ (∂E_i/∂p)

各量含义：p 是任一场景参数；N 是训练图像数；P_i 是第 i 张图的像素数；E 是图像能量，定义为所有像素 RGB 分量之和（"E is the total image energy, i.e., the sum of the RGB components over all pixels"），E_i 即第 i 张图的能量。梯度幅值大 = 对该参数的变化敏感。对每张训练图一次反向传播即可得到所有参数的敏感度。txt 中该公式内层求和号的范围在抽取中丢失（按文字应为对第 i 张图所有像素求和），原文公式以 PDF 为准。

式 (4)，向量敏感度取分量最大值：S(x) = max_{d∈[1..D]} S(x_d)。
式 (5)，敏感度加权聚类距离：D(x, c_k) = S(x)·‖x − c_k‖₂²。
式 (6)，敏感度加权质心更新：c_k = (1/Σ_{x_i∈A(k)} S(x_i)) · Σ_{x_i∈A(k)} S(x_i)·x_i，A(k) 是分到第 k 个质心的向量集合。用批量聚类（每次随机子集，移动平均衰减 λd = 0.8，高斯 800 步、SH 100 步，batch 2^18/2^20，第 6.2 节）。
式 (7)，形状归一化：Σ̂ = (R·Ŝ)(R·Ŝ)^T = (1/η²)·Σ，其中 s = η·ŝ、η = ‖s‖₂、Ŝ = diag(ŝ)。聚类在 Σ̂ 上做，附录 F 证明 k-Means 质心保持归一化形式，并用除以 trace(Σ) 重整防止浮点误差。

附录 E 的两个实现细节值得注意：(a) 计算敏感度时不做颜色 clamp——Kerbl 的实现把负 SH 颜色 clamp 到 0 且反传梯度置零，会让这些 SH 系数的敏感度被错误置零；(b) 阈值 βc = 6×10⁻⁷、βg = 3×10⁻⁶。

### 信号设计（重点）
| 问题 | 答案（含与我们 I6 的对照） |
| --- | --- |
| 信号是什么（重要性/复杂度/敏感度/显著度…） | 渲染敏感度：图像能量 E（RGB 总和）对每个参数的梯度幅值，按图像平均（式 (3)）。与我们 I6（训练期渲染损失对各属性的梯度 EMA）同属一阶梯度类敏感度；差别在两处：它用图像能量而不是渲染损失，它在压缩时一次性算而不是训练期全程累积 |
| 哪一端算得出（编码端/解码端/仅训练期） | 仅编码端：需要全部训练图像和可微渲染器的反向传播，逐图 backward。解码端无法重算——和我们 I6 一样，这正是梯度类信号共同的死穴，也是我们被迫做 I2（解码端可重算公式特征）的原因 |
| 有无侧信息 | 敏感度数值本身不进码流，算完即弃。高敏感向量"原样进码本"只是表示内容多占码本条目，不是额外侧信息。与我们一致：I6 的 EMA 也不进码流 |
| 训练期还是编码期 | 编码期（场景训完后的压缩阶段，耗时见 Table 6：敏感度计算平均 8.05s，整条流水线里微调占 70%）。我们 I6 在训练期。注意时机差异带来信号质量差异：它拿的是收敛场景上的精确梯度，我们拿的是训练过程中的 EMA 近似 |
| 和渲染质量的距离（直接测质量还是代理量） | 代理量：一阶梯度只在小扰动意义下反映质量影响，不直接测 PSNR。我们 I6 同为代理量 |
| 信号用在哪 | 它：VQ 码本分配——三处用法（超过阈值 βc/βg 的向量豁免聚类、式 (5) 加权聚类距离、式 (6) 加权质心），外加零敏感剪枝。我们 I6：监督 AQM 输出的量化步长乘子（Q 乘子）。同一个信号，它喂给"码本分配"，我们喂给"步长调节" |

### 它与我们主创新的异同（总结）
相同点：都认定"参数对渲染的敏感度差异大、量化应按敏感度分级"；都不把信号写进码流；都以真实场景数据集 + 对 3DGS 基线的压缩率为主要证据。
不同点：(1) 信号计算时机——它编码期在收敛场景上精确算，我们训练期用 EMA 近似；(2) 信号去处——它的敏感度直接决定码本内容（豁免+加权），我们的敏感度只做训练目标去训练一个解码端可重算的 MLP（I2），量化时真正起作用的是公式特征而非梯度；(3) 表示改动——它不改表示（位置原样存 16-bit），我们用锚点+offset 改表示；(4) 它的敏感度豁免要求"哪些向量豁免"隐含在码本内容里（豁免向量直接作为码本条目），不违反零侧信息，但码本会变大（Fig. 7：color 码本占压缩后体积的比例随场景波动明显）。

## 三学：证明与包装（创新怎么立住）

### 实验口径
- 体积口径：压缩后整个文件（量化 + 码本 + DEFLATE 熵编码后）的大小，MB。基线是 Kerbl 官方重建场景的未压缩表示。注意两点：含 DEFLATE 收益（后来 Papantonakis 的附录指出这部分约占 2x，且不对应 VRAM 占用）；Fig. 7 显示压缩后体积大头是位置坐标和码本索引。
- 数据集与协议：Mip-NeRF360（9 景）、Tanks&Temples（2 景）、Deep Blending（2 景）、NeRF-Synthetic（8 景自训）；对每景对比压缩前后 PSNR/SSIM/LPIPS。
- 训练/压缩配置：码本 4096，βc = 6×10⁻⁷、βg = 3×10⁻⁶，QAT 5000 步，位置 16-bit、其余 8-bit（第 6.2 节）。压缩总耗时约 5–6 分钟，约为重建时间的 10%（第 6.3 节）。

### 主结果（注明表号）
- Table 1：真实场景平均 640.31 MB → 23.73 MB（25.77x），PSNR 26.58 → 26.56（平均掉 0.23，第 6.3 节称 0.5 dB 内人眼不可分辨）。分数据集：Mip360 795.26→28.80 MB（26.23x，PSNR 27.21→26.981）、T&T 421.90→17.28 MB（23.26x）、DB 703.77→25.30 MB（27.81x）。
- Table 8（附录逐场景）：最高压缩率 bicycle 1450.277→47.147 MB（30.761x，PSNR 25.171→24.970）；garden 1379.993→46.565 MB（29.636x）。
- Table 2（渲染）：1080p 下 bicycle 在 RTX A5000 上 184→414 FPS（2.25x），Bonsai 93→321 FPS（3.45x）；RTX 3070M 上 bicycle 122→296 FPS。约 2x 来自压缩数据带宽减少、其余来自硬件光栅化（第 6.3 节）。
- Table 6/7：压缩流水线中 QAT 微调占 70% 时间（平均 213.30s）；压缩表示让渲染 preprocess 从 1.46ms 降到 0.28ms（5x）。

### 消融设计（注明表号）
- Table 3（garden 场景，逐级累加，最值得学的一张表）：baseline 1379.99 MB / 27.179 PSNR → +Pruning 1217.25 → +Color Clustering 278.41（PSNR 掉到 25.941，同时省 4.9x）→ +Gaussian Clustering 164.15（25.781）→ +QA Finetune 86.69（PSNR 回升到 26.746，体积再省近一半）→ +Entropy Encode 58.40 → +Morton Order 46.57。每个组件的体积收益和质量损失一次看全，且展示了"聚类丢分、微调找回"的补偿关系。
- Table 4（码本大小）：1024–8192 四档，平均误差几乎不变（28.47–29.06 MB，PSNR 差异在 0.05 内），但大码本降低最大误差，默认 4096。
- Table 5（敏感度阈值）：扫 βc、βg。去掉 SH 豁免阈值（βc 一栏无阈值行）PSNR 掉到 −1.47；去掉形状豁免阈值（βg 一栏无阈值行）掉到 −0.83。证明敏感度豁免主要保护的是 SH 系数的质量。
- 值得学的对照设计：把"压缩各阶段"做成增量瀑布（每级同时报体积倍数和 ΔPSNR），以及给关键超参各留一张单参数扫描表。

### 讲故事方式
主线一句话：参数敏感度天差地别，所以量化和聚类都要看敏感度行事。最有力的图是 Fig. 3 的敏感度直方图——一张图立住"敏感度长尾、<5% 极敏感"的全部前提，后面的豁免机制都是它的自然推论；最有力的表是 Table 3 的增量瀑布。我们写论文时"信号存在性证据（分布图）+ 增量消融瀑布"这个组合值得照搬。

## 对 DCCA-GS 的可借鉴点

1. 用它的敏感度定义做我们 I2/I6 的"标准真值"标定（对应我们的主要问题）。我们的困境：I6 的梯度 EMA 解码端算不到，I2 的公式特征与敏感度实测相关性 |r|<0.005。这篇给出了一个更干净、可比对的敏感度协议：收敛场景上、全训练集、逐图一次 backward、按式 (3) 平均、且不做颜色 clamp（附录 E）。建议跑一个离线诊断：分别算"式 (3) 敏感度 vs 我们 I2 公式特征（局部密度/各向异性/offset 能量/掩码激活比例）"和"式 (3) 敏感度 vs 我们 I6 的 EMA"的相关性。若公式特征对式 (3) 的相关性依然接近 0，可以下结论"解码端可重算特征与梯度敏感度本质弱相关"，I2 的定位就该从"预测敏感度"改为"独立复杂度信号"；同时检查我们 I6 实现是否踩了 clamp 置零的坑（若渲染损失反传经过 clamp，低激活区域的梯度 EMA 会被系统性低估）。
2. 敏感度信号喂"码本/分配"而不是只喂"步长"。它证明敏感度对 VQ 分配有效（Table 5：去掉豁免最多掉 1.47 PSNR）。我们底座 HAC++ 的 feat/offsets 量化虽非显式码本，但训练期存在等价的分配自由度（残差幅度分布、Q 乘子本身即分配）；可做一个对照实验：把 I6 的 EMA 信号从"监督 AQM"改为（或同时）调制 offset 残差的保留/裁剪策略，看同码率下收益是否大于纯步长路线。这不需要改码流契约。
3. "高敏感不压、直接原样存"的豁免原则：这是敏感度信号最直接的用法（宁可多花码本条目也不伤质量）。我们 AQM 的 Q = Q0×(1+tanh(q))×(1+tanh(complexity)×α) 的步长下界，可以照这个思路校准——对极敏感锚点，AQM 应收敛到"接近不量化"的步长下界，而不是均匀缩小。
4. 口径警示：它的 26x 含 DEFLATE 约 2x 的收益（Papantonakis 附录指出），且位置占压缩后体积大头（Fig. 7）仍未压缩。和 HAC++ 系的 total_MB 口径对比时必须注明，不能拿 47 MB（bicycle）直接和我们的 total_MB 数值比。
