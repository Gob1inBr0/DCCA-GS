> 一句话定位：把量化直接做进 3D-GS 训练（整数潜码+decoder，STE 端到端训练），配上由粗到细的渐进分辨率训练和训练期影响剪枝，存储省 10-20 倍，训练时间和渲染速度反而更快，质量基本持平（Table 1）。

## 问题与洞察

### 它认定的主要矛盾
3D-GS 训练和存储两头都贵：每个高分辨率场景百万级高斯、存储超 1GB，训练峰值显存"almost 20GB of GPU RAM"（第 1 节）。而对训后压缩路线，它在第 2 节给出批评："While pruning can be often a good compression strategy, these method may require a lot more training to reach a competitive performance as an unpruned network"——训后剪枝或量化需要额外的大量再训练才能恢复性能。它的回答是把压缩成本摊进正常训练：量化感知训练、训练期剪枝，不做独立的压缩阶段。

### 支撑观察（直觉 / 数据 / 失败实验）
- 第 1 节/第 4.1 节：颜色（SH）和旋转（协方差）属性占全部属性内存的 80% 以上；100 万高斯的全属性 FP32 向量约 236MB。
- Fig. 3（第 4.1 节）：不量化时 opacity 直方图集中在 0 和 1 两端——大的正梯度把错误高斯的 opacity 饱和到 1，这些高斯剪不掉、渲染出 floaters；量化后 opacity 分布更均匀、异常梯度更少。这是"量化 opacity 当正则"的核心证据。
- 第 4.3 节：高 opacity 不等于有贡献——被遮挡时透过率 T=0，光栅化里毫无作用；scale 极小的高斯只影响极少像素。所以 3D-GS 原版的 opacity reset 剪不干净。
- 第 4.2 节：训练早期就让高斯去拟合精细特征，优化落进不好的极小值，产生删不掉的 floaters（作者直觉，未给独立实验，Table 3 与 Fig. 7 间接支撑）。

### 显然的路为什么没走
- 训后剪枝/量化：第 2 节明确批评其恢复成本，选择量化感知训练一体化。
- 更强的压缩工具（可学习概率模型、Gumbel 退火、复杂 decoder）：第 4.1 节说会明显拖慢训练、增加运行时显存，刻意不用，保持"量化几乎零额外开销"。
- 全属性量化：位置、scale、0 阶 SH"对初始化敏感，量化后大幅掉点"（第 4.1 节），保留不量化。
- 3D-GS 原版 opacity reset：只删透明高斯，删不掉被遮挡和极小的高斯（第 4.3 节），改成 influence 剪枝。

## 机制

### 核心流程
三条机制都发生在训练期，端到端一体（Fig. 2）：
1. 属性量化（第 4.1 节）：每个可量化属性维护整数潜码 q（训练中用连续近似 q̂），前向经 STE 取整后过 decoder D 得到属性（Eq. 6），潜码和 decoder 一起按 3D-GS 原流程训练；潜码初始化用 decoder 逆变换 q̂ = D^{-1}(a)（补充材料 Eq. 1）。训后潜码取整并熵编码存储，解码端载入时先过一遍 decoder（一次性成本）。
2. 渐进训练（第 4.2 节）：渲染分辨率从 0.3 倍按余弦日程升到 1.0，占前 70% 迭代（30K 中的前 21K），之后全分辨率训完。
3. 影响剪枝（第 4.3 节）：rasterization 过程中顺带累计每个高斯的权重 W（Eq. 7），跨 N 次迭代累计以覆盖全部训练视图；每 5000 迭代（直到 25000）剪掉权重最低的 15%，训练继续。无恢复微调阶段，靠"每次只剪 15%+继续正常训练"兜底。

量化的字段：高阶 SH（color）、旋转、opacity 三个属性。不量化：位置、scale、0 阶 SH（base band）。位宽：txt 未给出具体量化位宽数字，只说明潜码为整数、训后熵编码；补充材料 Table 1 给出潜码维度——color 16、rotation 8、opacity 1，decoder 学习率 1e-4。位宽数字论文未报告。

### 关键公式（按原文抄，注明编号）
- 量化前向（Eq. 6）：`a = D(STE(q̂))`。q 是 l 维整数潜码，D 是把潜码映射回属性的 decoder（线性层或 MLP），STE 让取整操作直通梯度。
- 训练损失（Eq. 5）：`L = (1−λ)L_1 + λ L_SSIM`，λ=0.2（沿用 3D-GS）。
- 影响权重（Eq. 7）：`W_{i,p} = α_i T_i = α_i Π_{j=1}^{i-1}(1-α_j)`，`W_i = Σ_p W_{i,p}`。p 是像素，T_i 是到第 i 个高斯为止的透过率；T=0（被完全遮挡）的高斯权重为 0。权重在光栅化时顺带算出，"no computational overhead"（第 4.3 节）。
- 不透明度正则（重点说明）：论文没有独立的 opacity 正则损失公式。第 4.1 节原文："Quantization acts as a soft regularizer as it requires more gradient updates to increase the opacity value from one quantization bin to the next higher bin, thus preventing opacity saturation."——正则效果来自量化本身的台阶结构：opacity 每升一个量化档需要更多次梯度更新，单个大梯度无法把它直接推饱和。即"正则"是量化机制的副作用，不是显式加进损失函数的项。

### 信号设计（重点）

| 问题 | 答案 |
| --- | --- |
| 信号是什么 | influence：渲染贡献权重 W_i = Σ_p α_i·T_i（Eq. 7），跨多次迭代累计，衡量高斯对全场景渲染的实际作用 |
| 哪一端算得出 | 训练期在编码端算（rasterization 时顺带累计），解码端不算 |
| 有无侧信息 | 无（只用于决定剪谁，不进码流） |
| 训练期还是编码期 | 训练期：每 5000 迭代执行一次剪枝直到 25000 迭代，量化潜码全程参与训练 |
| 和渲染质量的距离 | 代理量：统计混合贡献而非删后质量变化；与 LightGaussian 的 Eq. 3 相比少了体积项、无恢复微调，靠小步剪枝+继续训练控制损伤 |

## 实验与结果

### 实验口径
数据集：Mip-NeRF 360（9 场景）+ Tanks & Temples（2）+ Deep Blending（2）共 13 场景，每 8 张取 1 张测试（第 5.1 节）。存储=全部量化与非量化参数之和（decoder 是否计入未明说）；训练/渲染显存报峰值 GPU RAM；FPS 统计渲染全部相机。3D-GS 数字同时引原文报告值和自己重跑值（标 *）。三个版本：EAGLES（30K 迭代）、EAGLES-Small（更多剪枝）、EAGLES-Fast（21K 迭代，渐进训练结束点）。

### 主结果（注明表号）
- Table 1：Mip-NeRF 360 上 27.23 PSNR/54MB/131 FPS/21m34s 训练，对比 3D-GS* 27.45/745MB/110 FPS/23m20s——存储约 14 倍压缩、质量掉 0.22dB、训练还更快；Tanks & Temples 上 29MB vs 430MB、227 FPS vs 157 FPS。
- Table 2：Deep Blending 上 29.86 PSNR，反超 3D-GS* 的 29.55（+0.31dB），52MB vs 656MB。
- Table 3：Bicycle 场景 1254MB→104MB、高斯 5.31M→2.26M，PSNR 25.13→25.04（几乎持平）。

### 消融设计（注明表号）
- Table 3：四步渐进消融（+Quantization → +Progressive → 致密化间隔 175 → +Pruning），三数据集各一场景，同时报高斯数/显存/FPS。量化一步把三场景属性从 220/452/1046MB 压到 6/12/28MB（约 20-30 倍）；剪枝一步把 Train 场景从 29MB/0.64M 高斯/202 FPS 压到 21MB/0.46M/234 FPS 且 PSNR 微升。
- Table 4：渐进训练的滤波器类型消融（None/均值/高斯 5×5/7×7/15×15/降采样）：降采样省训练时间最多（9m49s vs 13m27s），15×15 高斯滤波掉 PSNR（23.17 vs 23.34）。
- Fig. 8：渐进缩放系数敏感性：降到 0.3 都不掉 PSNR 但高斯数减少，再低才掉——给出安全边界。
- Table 5：训练/渲染峰值显存：Bicycle 训练 17.4G→10G。
