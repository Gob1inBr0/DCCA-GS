### 0.2 清单条目怎么读（§4 的每一行）

每篇论文在 §4 里是一行，五个字段固定：

```
| arXiv 编号（链接到摘要页） | 提交日期（月-日） | 英文原题（不改译） | 一句话中文说明 | 标记 |
```

- 一句话说明不超过 40 个汉字，只写"它做什么、怎么做"，不写评价和空话；说明里出现的数字都来自摘要。
- 标记：**★** 表示与 DCCA-GS 的压缩、码流或剪枝方向直接相关；空白表示一般相关。标 ★ 的论文在 §3 都有卡片，点击 ★ 可直接跳到卡片。

### 0.3 重点卡片怎么读（§3）

只有标 ★ 的论文才写卡片，每篇半页以内，固定四行：

- 第一行：编号 · 短名 · 一句话定性；括号里是会议接收信息，arXiv 备注没写就标"预印本"。
- 它做什么：问题和做法，2-3 句，说清输入输出和关键机制。
- 结果：只抄摘要里确实出现的数字；摘要没给数字就写"摘要未给数字"。
- 与 DCCA-GS 的关系：一句话讲清是竞品、可借鉴还是值得知道，撞了或不撞我们哪条主张。

### 0.4 分类目录

沿用上期全量深读简报的 12 类，逐月可比：压缩与内存优化 / 表示渲染与加速 / 动态4D / SLAM与大场景 / 稀疏视角与前馈 / 生成与编辑 / 语义分割与理解 / 人体头像Avatar / 驾驶与机器人仿真 / 材质光照与逆渲染 / 物理仿真与交互 / 其他。

### 0.5 收录与剔除规则

- **保留**：以 3DGS 或 3D 高斯（含 2DGS、4DGS 变体）作为场景或物体核心表示的论文。
- **剔除**（四类）：① 与泼溅无关的统计方法（高斯过程等）；② 纯 2D 高斯的图像处理（如人群计数）；③ 3DGS 只当对照基线或背景引用的论文；④ 命中词是"高斯混合分布"这类统计名词、并非泼溅表示的论文。
- 被剔除的论文在 §1 列出编号和一句话理由，方便核查，不进清单。

- 说明与卡片一律白话；技术术语正常用（熵编码、量化、剪枝、率失真、码流等）。

## 2. 本月值得注意的动向

### 2.1 压缩方向 6 篇，共同主题是"先回答该有多少高斯"

<a id="trend1"></a>

Budgeted-GS（[2610.03162](#card-budgeted)）从相空间最优传输推导"预算-误差定律"，给出可测量的高斯数量下界，训新场景前先估数量再按量训练；CompactSplat（[2610.13177](#card-compactsplat)，NeurIPS 2026）在前馈端按内容分配高斯数量，平坦区用放大调制的图元平铺；SCION（[2610.02322](#card-scion)，NeurIPS 2026）更进一步，批评主流 3DGS 连同它的压缩方法"把每个元素当独一份"，用可复用图元词表加实例摆放替代，1.2 MB 仍保持高质量。三篇路线不同，判断一致：高斯个数本身是主要的冗余来源之一。

### 2.2 "发布后的参数文件"开始被当作需要专门对待的交付物

<a id="trend2"></a>

GSCV（[2610.07795](#card-gscv)，MM Asia 2026）不依赖跨帧追踪信息，靠 Inter-PLAS 排序让相邻帧图像接近，把 GS 序列当高比特深度视频帧交给标准视频编码器压缩；FlyMark（[2610.11364](#card-flymark)）把版权水印免训练地写进已发布文件的零阶颜色参数，并明确把"被剪枝、被重量化、被转封装"当成威胁模型。接上期的渐进传输、跨平台一致解码、抗丢包，码流工程化方向 10 月继续有新工作加入。

### 2.3 剪枝开始建模"一起删会怎样"

<a id="trend3"></a>

SplatQ（[2610.13503](#card-splatq)，ICLR 2027 在审）批评逐高斯独立打分的 Top-K 剪枝：不考虑联合删除效应、没有区域预算控制。它把剪枝写成带区域配额的二次组合优化（QUBO），用模拟退火或相干伊辛机求解。上期总结"剪枝走向有保证和免渲染两端"，本月补上"联合选择"一条。

### 2.4 高斯泼溅被借去做音频编码

<a id="trend4"></a>

GS-Codec（2610.04651，NeurIPS 2026）把神经音频编码的瓶颈从码本量化换成"用一维高斯泼溅拟合波形潜变量"，全程没有任何量化器；再训一个小网络一步预测图元参数，免去推理时的迭代拟合。这是在我们的检索范围内，GS 表示第一次明确落到音频模态——表示方法被其他领域借用的信号。

## 3. 重点卡片（标 ★ 的 8 篇）

<a id="s3"></a>

### <a id="card-scion"></a>2610.02322 · SCION：用可复用图元词表替代逐高斯独立存储（NeurIPS 2026）

- 它做什么：砖块、草叶、树叶这类重复元素在 3DGS 里被拟合成几百万个互相独立的高斯。SCION 用一份紧凑的可复用图元词表，加轻量的世界坐标实例（平移旋转缩放的副本）在场景里摆放，对多视角拍摄做离散与连续参数联合优化；两级致密化（图元级与实例级）配合对抗损失保住共享图元上的细节。
- 结果：1.2 MB 时仍保持高质量；率失真优于现有高斯压缩方法；支持免重训练的实例级编辑与动画（摘要未给具体 PSNR/压缩倍数）。
- 与 DCCA-GS 的关系：同属"降冗余"但路线不同——它压的是元素级结构重复（词表+实例），我们压的是参数编码冗余（量化+熵编码）；对重复元素少的自采航拍场景收益存疑，但"结构冗余"主张与我们锚点式结构同向，审稿人可能引用它，值得精读划界。

### <a id="card-budgeted"></a>2610.03162 · Budgeted-GS：预算-误差定律先回答"该有多少高斯"（EG 2027 投稿预印本，单作者）

- 它做什么：把训练好的 3DGS 后处理成"因式分解树"——多分辨率的矩匹配聚合层级，几秒构建，一个画质参数按目标设备显存选层，城市级模型服务显存差别很大的 GPU。训新场景则反过来：先用可测的容量下界（由相空间最优传输推导的"预算-误差定律"）估计场景需要多少高斯，再直接按这个数量训练，避免先训大再剪的浪费。冗余图元的选择规则由覆盖定理给出证明。
- 结果：容量下界在 13 个公开场景按预登记协议验证；官方城市采集数据在单张消费级 GPU 上以 1920×1080、完整球谐实时渲染。
- 与 DCCA-GS 的关系："该有多少高斯"与我们的内容复杂度量化同题不同路（它靠相空间理论闭式估计，我们靠解码端重算的复杂度 MLP）；因式分解树是渐进分层的另一种实现，渐进码流主张轴需要划界（它按需选层渲染，不是单文件连续前缀码流）。威胁度中，值得精读。

### <a id="card-mobile4dgs"></a>2610.05289 · Mobile-4DGS：手机上统一实时渲染静态与动态场景（预印本，代码已开源）

- 它做什么：外观上用蒙特卡洛镜面能量聚合把高阶球谐残差压进一阶球谐，属性条件球谐增强的偏移量在推理前预烘焙；数量上用多视角 alpha 一致性做致密化与剪枝；动态上用二阶高斯运动、可学习时间支撑和动静二分表示，不需要运行时形变网络；播放时用"深度序证书"复用已提交的排序，减少重投影、排序与索引更新。
- 结果：摘要未给具体数字；声称明显降低存储与渲染开销，移动端实时渲染静态与动态场景。
- 与 DCCA-GS 的关系：移动端部署压缩的正面同类工作（上期 2606.30017 蒙特卡洛能量聚合的续作并扩展到 4D）；它的"推理前预烘焙"与我们的零侧信息契约立场相反（能重算的不存），对比点清楚。威胁度中低，可借鉴其球谐降阶聚合思路。

### <a id="card-gscv"></a>2610.07795 · GSCV：把 GS 序列交给标准视频编码器（MM Asia 2026，代码已开源）

- 它做什么：现有"视频编码器压 GS 序列"的路子要么需要跨帧追踪信息（多数场景没有），要么用随机性强的并行线性分配排序（PLAS）导致帧间图像不连贯。GSCV 提出 Inter-PLAS，让 I 帧、P 帧对应的 GS 排序图像彼此接近，大幅提高帧间相关性；再用高比特深度 GS 图像管线接入最新视频编码标准。
- 结果：明显优于 MPEG 视频与点云编码基线（摘要未给具体数字）。
- 与 DCCA-GS 的关系：同一"用现成编码器"路线（与上期 CoSAG、KISS-GS 的免学习方向同频），但对象是动态序列而非静态单场景；对我们静态单文件渐进码流不直接撞车，可在 4D 扩展的相关工作里划界。

### <a id="card-splatq"></a>2610.13503 · SplatQ：带区域预算的联合删除效应剪枝（ICLR 2027 在审）

- 它做什么：现有剪枝按独立重要性分数做全局 Top-K，既没有区域预算控制，也不看"删掉这批以后互相影响会怎样"。SplatQ 按空间邻近和外观相似把高斯分成限长的小块，把全局选择拆成子问题；块级保留配额做平滑防止预算过度集中；用代表性像素颜色对不透明度变化的响应构造联合删除效应的二次近似，连同单独响应与配额罚项写成 QUBO 目标，用模拟退火或相干伊辛机求解。
- 结果：5 个基准上整体重建质量、空间均衡和渲染速度超过现有剪枝方法；消融确认预算平滑改善局部细节、交互建模改善选择质量（摘要未给具体数字）。
- 与 DCCA-GS 的关系：我们的 SPA 剪枝是逐高斯独立打分，SplatQ 指的正是这类方法的软肋；若开源且免训练，可评估作为基础措施替换或增强 SPA。可借鉴，不撞码流主张。

### <a id="card-densif"></a>2610.13541 · 置信度感知致密化：固定预算下按渲染误差放高斯（预印本）

- 它做什么：3DGS-MCMC 用不透明度采样决定新高斯放哪，但已重建好的前景不透明度一直高，吃掉大部分预算，背景欠重建。本方法保持固定预算的渐进增长，改按图像误差放置：屏幕空间梯度大处多放，偏好学习置信度低的区域，并把对渲染贡献最小的高斯挪过去。
- 结果：24 个场景平均，在 100k 到 2M 的每一档预算上 PSNR、SSIM、LPIPS 都超过 3DGS-MCMC；100k 预算下无先验、无初始化阶段，收回 ConeGS 领先 3DGS-MCMC 的 1.05 dB 中的 0.84 dB；500k 起在所有固定预算方法中 PSNR、SSIM 最高。
- 与 DCCA-GS 的关系：训练期按渲染误差分配预算，与我们的渲染敏感度监督思路相通；对固定预算下的紧凑训练（对应我们的基础措施环节）有直接参考价值。可借鉴。

### <a id="card-compactsplat"></a>2610.13177 · CompactSplat：前馈端按内容分配高斯数量（NeurIPS 2026）

- 它做什么：前馈 3DGS 通常每像素固定放一个或多个高斯，平坦区域浪费。CompactSplat 用纹理引导的空间划分加层级采样，把高斯按内容分配：复杂区域放密，平坦区域用放大调制的大图元平铺；推理时还支持动态稀疏控制，不重训网络即可在画质与内存之间切换。
- 结果：RealEstate10K、DL3DV、ScanNet 上稳定超过先前方法，用明显更少的高斯达到高保真重建（摘要未给具体数字）。
- 与 DCCA-GS 的关系：前馈赛道，不撞逐场景优化的压缩；但"按内容分配高斯数量"与我们的内容复杂度量化同题，且其推理时免重训的画质-内存切换与渐进思想可对照。可借鉴其分配准则的设计。

### <a id="card-flymark"></a>2610.11364 · FlyMark：写进参数本身的免训练水印（预印本）

- 它做什么：训练好的 3DGS 场景发布后就是一份可复制、可剪枝、可重量化、可转封装的参数数组；现有水印绑定训练管线、学习解码器或渲染图，工具不在了证据也就没了。FlyMark 免训练，把密钥消息用抖动量化索引调制写进文件已有的零阶颜色参数（只做无彩度位移，几何与高阶外观参数逐位不变）；载体方向取自一份公开的果蝇神经连接组（有版本、免逐场景调参）；提取只需锥细胞查询、取整和多数投票。
- 结果：模型域威胁模型下，合成与真实场景达到高比特准确率与视觉保真度，错误密钥 cleanly 分离（摘要未给具体数字）。
- 与 DCCA-GS 的关系：码流交付的版权保护配套，与压缩正交、可叠加；它把"被重量化/转码"当威胁模型，说明发布后工具链会反过来要求压缩方法保持参数可定位性。值得知道。

## 6. 已知局限

<a id="s6"></a>

1. **窗口不完整（先行版）**：arXiv 对 10-10 及以后提交的论文在执行日（10-13）尚未公布，本报告实际只覆盖 10-01 至 10-09 公布的 68 篇。11 月初重跑全月窗口覆盖本文件后，本条作废。
2. **只查 arXiv 一源**：未覆盖 IEEE Xplore、CVF Open Access、Springer 等正式发表渠道；从未挂 arXiv 的论文不在本报告范围内（与上期相同）。
3. **检索式只覆盖三种叫法**："gaussian splatting / 3d gaussian / 3dgs"。标题或摘要只写 "Gaussian primitives"、"splatting" 而不含上述词的论文会漏（与上期相同）。
4. **未读正文**：一句话说明与卡片只基于 arXiv 摘要和元数据；摘要没给的数字一律不写。需要正文数字的论文应走精读流程（另立笔记文件）。
5. **元数据缺口**：arXiv API 不返回作者机构；代码链接只在摘要文本确实给出时才在卡片里写。
6. **会议信息可能滞后**：接收信息以 arXiv 备注字段为准，作者未更新备注的已接收论文会按预印本记录。
