## 1. 设计模式：这批论文反复用的招

### 模式一：上下文建模——把结构关系变成概率
- **谁在用**：HAC（哈希网格当上下文，Eq 3–6）、HAC++（哈希上下文 + 通道自回归 + GMM 融合，Eq 6–8）、ContextGS（锚点分级自回归，式 7–8）、CompGS/CompGS++（锚点基元预测耦合基元残差，式 2、9–12）、Smol-GS（哈希上下文挂到每高斯坐标）。
- **效果证据**：HAC++ Table III——去掉哈希上下文 BD-rate +63.3%，是最大单项；ContextGS Table 2 的 2×2 开关——强熵编码基线上只加锚点级上下文 18.67→15.03MB（−19.5%）。
- **本项目对照**：底座已用 HAC++ 哈希上下文。ContextGS 的上下文全部由已解码量现算（解码端可重算成立），但其完整版带超先验 ẑ（新增码流字段）；零新增字段的嫁接版只能取式 8 的细层分支。

### 模式二：训练期塑造可压表示（率失真/正则进训练，而不是训后补压缩）
- **谁在用**：CompGS（熵约束正则端到端，式 1、6–13）、CompGS++（率约束优化模块）、SOG（2D 平滑正则 + 训练期排序）、EAGLES（量化感知训练，量化台阶兼做 opacity 正则，Fig 3）、Mini-Splatting（增密阶段关 SH）、GaussianSpa（预算约束写进训练目标，式 5–6）。
- **效果证据**：SOG Table 3——同一套压缩管线，不排序直接压 21.98dB/71.7MB，排序+平滑训练后 25.37dB/34.3MB：**排布（可压性）是训练出来的，不是压缩器给的**。EAGLES Table 2：量化感知训练让 Deep Blending 反超 3DGS（29.86 对 29.55）。
- **本项目对照**：I2/I6 属于这个家族（训练期监督）。

### 模式三：重要性/敏感度信号驱动的分级预算
- **谁在用**（两条信号路线）：
  - 前向贡献类：LightGaussian global significance（Eq 3：命中×不透明度×透过率×体积归一）、EAGLES influence（Eq 7：α·T，零开销顺带统计）、Mini-Splatting 重要性采样（附录 E）、GaussianSpa 不透明度 a（+乘子 λ）、Compact3DGS 可学习掩码激活（Eq 5–8）；
  - 反向梯度类：Niedermayr 敏感度（式 3：图像能量对参数的梯度幅值）、Speedy-Splat Ũ=(∇g I)²（式 20–21，Hessian 的标量重参数化）、我们的 I6（渲染损失梯度 EMA）。
- **效果证据**：Niedermayr Table 5——去掉 SH 敏感度豁免阈值掉 1.47dB；Speedy-Splat Table 4——同管线同终数只换分数 +0.65dB；LightGaussian Table 3——分数三因子逐项加回 28.16→30.67，逐项都有增量。
- **本项目对照**：I6 属于反向梯度类，与 Niedermayr 最像（同为一阶梯度）；梯度信号解码端算不到，因此蒸馏进解码端可重算的 MLP（I2）。

### 模式四：控制量直接进码率项，不加额外 loss
- **谁在用**：HAC++（掩码乘进码率 Eq 11，对照"额外 mask loss"）。
- **效果证据**：HAC++ Table III——换成额外 mask loss 要多花 9.6% BD-rate，且权重要逐码率点手调。
- **本项目对照**：SPA 目前按固定比例调度。

### 模式五：选择性压缩——压最不敏感的，保护高敏感的
- **谁在用**：LightGaussian（只对显著性最低 60% 的 SH 做 VQ）、Niedermayr（高敏感向量豁免聚类，式 5–6）、Compact3DGS（残差 VQ 只在最后 1K 迭代启用控成本）、Papantonakis（20 个码本 + half-float，位置不量化）。
- **效果证据**：LightGaussian Table 4——全属性 VQ 崩到 23.11dB，仅 SH×显著性选择后 31.16dB：选择比量化本身更重要。
- **本项目对照**：对应物是"每锚点 Q 乘子"（连续版的选择性精度）。

### 模式六：渐进调度——什么时候动什么，和动什么一样重要
- **谁在用**：HAC/HAC++（3k 稳定→3k–10k 加噪→10k 上哈希网格；每步只采 5% 锚点做熵训练）、EAGLES（分辨率 0.3→1.0 余弦爬升占前 70%）、Smol-GS（五阶段，率损失 20k 后才开）、Speedy-Splat（Soft 在 opacity reset 前、Hard 在增密后）、GaussianSpa（15k 开始/25k 删净/light tuning）、Papantonakis（SH 降阶在 15k，留半程补偿）、Mini-Splatting（15k/20k 两次简化）。
- **效果证据**：HAC++ Table XII——训练 40k/50k/60k BD-rate −17.5%/−25.6%/−32.9%，时间点本身就是变量；Speedy-Splat Fig 7——剪枝比例是全网格扫出来的（Soft 80%/Hard 30%），不是拍的。
- **本项目对照**：已有 I2 的 ramp；I6 目前全程开启。

### 模式七：锚点重排与复用——placement 和 reuse
- **谁在用**：Mini-Splatting（blur split + depth reinit 先铺好再删，Fig 2 诊断 + Fig 7 同数量曲线）、ContextGS（分级 + anchor forward 复用，Table 3：只分层不复用 15.54MB 反而比不分层 14.73MB 差，复用后 13.80MB）、Octree-GS（LOD，粗层锚点是细层子集，天然多档预算）。
- **效果证据**：Mini-Splatting Table 1——0.49M 高斯对 3DGS* 3.35M 画质持平（27.34 对 27.47）。
- **本项目对照**：depth-reinit 已移植并拿到 BD-rate −8.6%（我们自己的 SPA 预算曲线）；blur split 还没用。Mini-Splatting 的 blur split 判据：式(2)，S_i = 以最大贡献者身份覆盖的像素面积，阈值 θ_blur·H·W = 2×10⁻⁴·H·W；Table 3 单组件 PSNR 持平 27.47、LPIPS 0.216→0.195。我们完整版跨场景实验里 blur-split 的增益不稳定（playroom 换 seed 后波动）。

### 模式八：换表示 vs 表示内修补——路线之争要有正面回应
- **谁在用**：Smol-GS 对锚点系（含 HAC++）的四条批评：透明 offset 浪费、三因子坐标合成太绕、坐标普遍不压、特征 50 维过高渲染慢；它的答案是换表示（Table 2：Mip360 27.76dB/5.860MB 对 HAC++ 27.60dB/8.742MB；Table 4 消融显示属性量化贡献约 4 倍、坐标量化约 1.8 倍）。
- **效果证据（坐标不压的文献背书）**：ContextGS Table 4/5（位置熵编码时间翻倍、高码率反而变大）、Niedermayr 第 6.5 节（位置量化失败）、Papantonakis（量化后位置占 28% 成为新瓶颈）。
- **本项目对照**：mask 关闭的锚点/offset 比例、offset 能量分布这两个统计是 I2 的公式特征。

## 5. 口径警示（写论文对比时的坑）

- **各家 MB 不可直接比**：SOG 大改了致密化超参（压缩倍数混入高斯减少的贡献）；Niedermayr 含 DEFLATE（约 2x）且位置只压到 16-bit；Papantonakis 无熵编码无解码器网络（27x 全靠结构）；Speedy-Splat 的"压缩比"是高斯数不是 MB；Smol-GS 按 3DGS.zip 口径含 MLP 与哈希表。HAC++ 码流五项 vs 我们多 bit_bounds/header_bits。
- **两条信号分类轴**（related work 定位表用）：训练期 vs 编码期；前向贡献 vs 反向梯度。I6 在"训练期 × 反向梯度"格子里，独一份的是"解码端可重算蒸馏"这一步。
- **引用谨记**：Compact3DGS（2408.03822）作者是 Joo Chan Lee 等，不是 Hanson；叫 CompGS 的有两篇（Liu 2404.09458 / Navaneet VQ 版），引表时用编号区分（详见 90 文件第 2 节）。

### 6.2 逐模式要点

**模式二**：SOG 证明"可压性是训练出来的"。我们的证据形态目前是消融式（去乘子 −0.41dB），缺 SOG 式同管线对照（I6 监督开/关各训一次）。方案 C 的 −2.06 dB 是模式二的反面：训后聚类特征（从未被塑造成"可共享"）崩，训练期加码本一致性正则才是合规变体。

**模式四**：HAC++ 证伪"额外 mask loss"（+9.6% BD-rate + 逐点手调）。本周两个负结果踩中同一条线：R1/R2 把码率感知注入**选择算子**，SPB 改**监督目标**——都不是"乘进码率项"。反面印证：活下来的机制全部合规（乘子→Q 进似然、掩码→码率、预算进目标）。遗留问题：剪枝预算 κ 三档 λ 固定 r085，宽档不咬合（诊断结果见 §6.3 第 2 条）。

**模式六**：HAC++ Table XII 证迭代时长本身是大变量。我们的正面证据：Phase 0 咬合预算的调度修复让次模从"不可测"变成"+0.52dB 可测"。对负结果的复查：G-R1/R2/SPB/G1 全部在单一调度下测得（r085 + I6 全程开），机制可能依赖时机，但预注册判定对已测配置成立。

### 6.3 离线诊断结果（2026-09-17 已完成）

1. **A1 敏感度真值标定**（`scripts/sensitivity_groundtruth.py`）：真值敏感度长尾跨量级（vis 中位 4e-7、p99 9e-6）——值得分级；**秩口径下信号存在**——offset_energy Spearman +0.30，I6 训练后的乘子 logits 与真值 **−0.22~−0.30**（方向与监督映射一致，证 I6 确实把敏感度排序教进了网络）；density/aniso ≈0。旧内部结论 |r|<0.005 是 Pearson 被长尾 + 26% 零块埋没的伪象。论文叙事按"秩意义的敏感度代理 + 独立训练信号"双线写。
2. **decisions 曲线诊断**（`scripts/decisions_curve.py`）：三档 λ 的 bite_ratio 完全相同（post 全部 0.81%）——咬合深度与 λ 无关（κ 是固定比例调度），"宽档不咬合"假设不成立，**模式四的 λ 自适应预算方向关闭**（两分钟离线诊断替代了潜在的 12 GPU 小时）。
3. **wave3 队列**（等 wave2 八任务 ALL_DONE 后自动启动）：SOG 对照 I6-off 一臂 + B1（SPA 删净→冻结→微调收尾）post_window {5000, 10000} 两臂（对照 2000 即现有基线）。调度器已上线等待。
