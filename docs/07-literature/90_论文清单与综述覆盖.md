## 3. 两篇综述的分类学

### 2502.19457《Compression in 3DGS: A Survey》（Ali 等，2025-02）

- 分类维度：**结构化 vs 非结构化**（Table I / Fig. 1）。非结构化 = 不动高斯间组织关系，下分五类剪枝（尺寸 / 梯度 / 不透明度 / 空间 / 显著性打分）、量化（向量 / 标量）、熵编码；结构化 = 给高斯引入组织，下分锚点式（Scaffold-GS / HAC / ContextGS）、上下文自回归（ContextGS）、图式（SUNDAE / GaussianForest）、因式分解（F-3DGS / Radsplat）。
- 最有用的统计表：Table II / III（非结构化方法）和 Table IV / V（结构化方法），统一列 Mip-NeRF360、Tanks&Temples、Deep Blending 三个数据集的 SSIM / PSNR / LPIPS / 内存 MB / 对 3DGS-30k 基线的压缩比，表头注明"数字全部来自各自原论文"。压缩比口径 = 对 3DGS-30k 体积的比值（第 III 节）。
- 结论一行：结构化方法压缩比上限更高（Table IV/V：CompGS-lowrate 83× / 70× / 113×，ContextGS-lowrate 最高 188×），非结构化方法渲染提速更多（第 IV.D 节：ELMGS 超过 400–600 FPS）；第 VIII 节总结：structured 至多约 100×、unstructured 至多约 50×、FPS 至多提升 7×，没有全能方法。
- 另有 Fig. 7 / Fig. 10 的 PSNR-FPS 散点，FPS 统一在单张 NVIDIA A40 上测，可直接看"压缩是否牺牲渲染速度"。

### 2407.09510《3DGS.zip》（Bagdasarian 等，2025-03 v5）

- 分类维度：**compression（降文件大小）vs compaction（降高斯数量）**。compression 下分属性压缩（VQ、低比特、SH 精简）与结构化表示（八叉树、锚点、哈希网格、Z 序、tri-plane、SOG、RAHT）；compaction 下分 densification 与 pruning，都挂在原版 3DGS 的自适应密度控制（ADC）框架下讲。第 3 章按机制讲工具箱，第 8/9 章一页一方法小结，比 2502.19457 更细。
- 最有用的统计表：Table 1（compression 统一排名，排名公式 = PSNR/SSIM/LPIPS 各占 1/6 + 体积占 1/2，数据向原作者按统一协议征集）：ContextGS_lowrate 第一（rank 4.3）、HAC-highrate 第二（4.4）、CodecGS 第三（4.8）；原文结论：T&T 上体积进 10MB 的只有 HAC-lowrate、SOG w/o SH、ContextGS_lowrate，CodecGS 最小（T&T 7.8MB）。Table 2（compaction，指标换高斯数量）：Octree-GS 第一（rank 2.7）、Mini-Splatting 第二（rank 3.4）。Table 3 警告训练/评测分辨率不一致会掉 PSNR，复现对比时有用。
- 口径：第 4.1.3 节明确说缺数据的方法"进综述但不进表"。两篇综述都遵守"论文未报告数字就不写"，我们引用它们时同样只写表里有的数字。

## 4. 兜底检查：我们可能漏了谁

用两篇综述的方法列表与统计表交叉核对本轮 16 篇，以下 8 个被综述重点讨论但我们没收：

1. **Compact3DGS**（Lee 等，2311.13681，CVPR 2024）：体积掩码剪枝 + 哈希网格颜色场 + 几何码本 + 量化熵编码后处理；两篇综述统计表都收（2502.19457 Table II 记 Mip-NeRF360 48.8MB / 15×；3DGS.zip Table 1 收 Compact3DGS 与 Compact3DGS+PP 两档）。没细读的理由：3DGS.zip 第 8.3 节明确说 HAC 的 offset 掩码剪枝"leveraging the pruning strategy introduced by Compact3DGS"，机制已在我们底座里。注意 2502.19457 把这篇标成"Compact3D [20]"，与 3DGS.zip 里"Compact3D = Navaneet 2311.18159"撞名，查表时别串。
2. **RDO-Gaussian**（2406.01597，ECCV 2024）：端到端率失真优化 + 熵约束 VQ + 动态剪枝，可连续控码率；两篇综述都收表（2502.19457 Table II 记 Mip-NeRF360 23.5MB / 31×；3DGS.zip Table 1 rank 9.8）。没细读的理由：与 CompGS 的率失真路线机制重叠、时间不够；但它是"RD 目标 + 3DGS"最直接的参照，二轮兜底优先级最高。
3. **Taming 3DGS**（Mallick 等，SIGGRAPH Asia 2024）：梯度 / 像素覆盖 / 逐视角显著度 / 核心属性四因子全局评分控制增密；3DGS.zip Table 2 收为 compaction 方法（rank 4.8）。没细读的理由：主目标是限资源下高效训练，不直接优化码率或每元素比特。
4. **CodecGS**（Lee 等，2501.03399）：渐进 tri-plane 特征平面 + DCT + 标准视频编码器；3DGS.zip Table 1 排第三，T&T 上 7.8MB。没细读的理由：纯编码路线，表示形式（特征平面）与锚点路线不同，机制能不能搬进锚点框架要另行评估。
5. **MesonGS**（Xie 等，ECCV 2024）：训练后压缩管线——前向传播重要性剪枝、四元数转欧拉角、RAHT 变换、分块量化、八叉树压几何、LZ77 打包；3DGS.zip Table 1 收 c1/c3 两档（rank 12.6 / 12.0）。没细读的理由：每个组件都来自已收论文，纯工程组合。
6. **SUNDAE**（2405.00676）：图谱带限滤波剪枝 + CNN 神经补偿头（特征泼溅替代直接 GS）；两篇综述都提（2502.19457 Table IV 收 30% / 1% 两档；3DGS.zip 第 4.2.2 节）。没细读的理由：图信号处理路线小众，与锚点量化主线距离远。
7. **PUP 3D-GS**（Hanson 等，2406.10219）：二阶（不确定度）重建误差近似做剪枝打分；2502.19457 Table II 记 Mip-NeRF360 86.3MB / 9×。没细读的理由：与 Speedy-Splat 同组（UMD Hanson 等）同路线——纯剪枝评分、无量化熵编码，时间不够。
8. **EfficientGS**（Liu 等，2404.12777）：累积梯度分析停掉多余增密 + 冗余高斯剪枝；2502.19457 Table II 里 Mip-NeRF360 保真最高档（27.38dB，98.0MB / 8×）。没细读的理由：剪枝信号与 LightGaussian / Speedy-Splat 高度重叠。

另注：ELMGS（2410.23213）与 Trimming the Fat（2406.18214，编号取自 Speedy-Splat 参考文献 [2]，2502.19457 里引文不全）在 2502.19457 Table II/III 里也是重点对照方法（ELMGS-small 在 Deep Blending 55×、Trimming the Fat 在 T&T 48×），同属"剪枝 + 量化"组合路线，暂按与 EfficientGS 相同的理由不单列精读。

## 5. 落选说明

任务种子清单里三篇未进精读清单，逐篇核查依据如下：

- **TrimGS（2406.07499）**：实际标题《Trim 3D Gaussian Splatting for Accurate Geometry Representation》（Fan 等）。摘要明说目标是"从图像重建精确 3D 几何"，trim（剪掉）是为了去掉冗余或不准的高斯、让高斯尺度保持小，从而几何更准；摘要全文没提压缩、存储或文件大小，只声明几何精度和感知质量提升。结论：目标是几何精度不是体积，**不符合收录标准，不补读**。它对"重要性 = 对渲染的贡献"这一信号的用法，我们已从 LightGaussian / GaussianSpa 拿到同类机制。
- **RadSplat（2403.13806）**：实际标题《RadSplat: Radiance Field-Informed Gaussian Splatting for Robust Real-Time Rendering with 900+ FPS》。摘要里剪枝的原话是"reducing the overall point count while maintaining high quality"，产出一句话是"smaller and more compact scene representations with faster inference speeds"——重要性剪枝服务的是实时渲染与推理速度；标题里的 robust（鲁棒性）来自用 radiance field 当先验和深度引导，不是来自剪枝；全篇没有量化、熵编码或码率目标，3DGS.zip 的两张统计表都没收它（2502.19457 把它归在因式分解类，Table I）。结论：目标是渲染效率不是码率，**不补读**。
- **Octree-GS（2403.17898，编号更正见第 2 节）**：实际标题《Octree-GS: Towards Consistent Real-time Rendering with LOD-Structured 3D Gaussians》（Ren 等）。LOD 分级的目标：按观察视角从多分辨率锚点层级里选合适层级、按需累积细层高斯，保证大场景下视角一致 + 实时渲染；摘要没提压缩。但按"把高斯/锚点数量当优化对象"的字面标准它算符合：3DGS.zip 把它收进 compaction 统计表且排第一（Table 2，rank 2.7；Deep Blending 上 112K 高斯，对照 3DGS-30K 的 2,975K；综述第 4.2.3 节还给出判断：Octree-GS 和 Mini-Splatting 是最省高斯、同时 PSNR 仍有竞争力的两个方法）。**建议补读**。最值得学的一点：粗层锚点是细层锚点子集的层级组织，同一模型天然自带多档锚点预算，可按视角/需求取用——这对我们"按内容复杂度分配锚点预算 + 训练期控制锚点数量"的思路有直接参考价值；注意它省的是数量不是每元素码率（无量化 / 熵编码），与我们的压缩目标只重叠一半。

## 6. 时间窗口与覆盖度结论

种子清单时间范围 2023-11 至 2026-09。两篇综述分别截稿于 2025-02（2502.19457 v1）和 2025-03（2407.09510 v5），方法覆盖到 2024 全年、勉强摸到 2025 年初（2502.19457 收了 ELMGS 2410.23213 和 GoDe 2501.13558；3DGS.zip 收了 CodecGS 2501.03399）。我们 16 篇里 2024-11 以后的 5 篇——HAC++（2501）、GaussianSpa（2411）、Speedy-Splat（2412）、CompGS++（2504）、Smol-GS（2512，v3 2026-06）——已逐词检索确认两篇综述都没提，其中 GaussianSpa 和 Speedy-Splat 正是剪枝路线最新的代表作、Smol-GS 是 2026 年的压缩工作，这批的"新度"比综述更新，不存在被综述覆盖代替的问题。缺口在另一头：2025 下半年到 2026 年的其他剪枝 / 压缩工作，两篇综述都没覆盖——综述未覆盖，建议用引用列表再兜一轮。从已收论文的参考文献里已确认的候选：HEMGS（2411.18473，混合熵模型，Smol-GS 引用）、BOGausS（2504.01844，2025，Smol-GS 引用）；另可顺着 CompGS++（2504）和 Speedy-Splat v3（2025-08 更新）的引用列表把 2025 下半年之后的增量补齐。
