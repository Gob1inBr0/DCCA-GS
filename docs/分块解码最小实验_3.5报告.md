# 方向一 3.5 最小实验报告（分块解码）

日期：2026-08-20；5090（A100 32GB）

## 输入

- bitstream：`runs/mlp_quant_sens_cd8_rest16_110k/b8/bitstreams`
  （4-28，110k，FQ+RSS+MLP 量化 8/16-bit，254,921 anchors，5.4852 MiB）

  （`--legacy-complexity-8dim` 兼容旧 8 维公式输入 bitstream）

## 做法 A 结果（Morton 序连续切块 + 视锥裁剪）

| K | 几何可见块占比 | 光栅化精确可见块占比 | 实际可见锚点占比 | PSNR 损失 | 解码时间下降上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4 | 1.000 | 1.000 | 0.959 | 0 dB | 0% |
| 16 | 1.000 | 1.000 | 0.959 | 0 dB | 0% |
| 64 | 1.000 | 1.000 | 0.959 | 0 dB | 0% |

- 完整解码：12.1 s，峰值显存 1420 MiB（不含光栅化）。
- 渲染：culled 与 full 图像逐像素一致（PSNR 差 0 dB），验证裁剪无失真；
  渲染时间几乎无差别（K=16/64 约 0%，K=4 的 22% 是首次调用 CUDA 预热噪声）。

## 结论

停止条件“可见块解码时间下降 ≥50% 且 PSNR 损失 <0.1 dB”**未满足**
（解码时间下降上限为 0%），按文档判定关闭方向一。

原因：4-28 是无人机航拍场景，每个验证视角实际可见 95.4%~95.9% 的锚点，
Morton 连续切出的每个块在每个视角都至少有一个可见锚点，块级视锥裁剪
无法减少需要解码/渲染的锚点数；而做法 B 在 K=16 就付出 +7.2% 体积代价。

备注：若改用 2 的幂对齐的 Morton 前缀（空间八分/十六分）或基于空间网格
（而非 Morton 连续区间）分块，可见块占比可能改善，但这超出本次最小实验
范围；在无人机宽视场场景下收益预期仍然有限。
