## 1. 问题与定位（Abstract + §1）

**一句话定位**：在 HAC++ 的锚点-哈希熵编码框架上，做“解码端可复现的内容自适应
压缩”（DCCA-GS）——模型文件更小，解码完全自包含、bit-exact。

要讲的三个点：

1. 3DGS 效果好，但几何/协方差/不透明度/外观逐基元显式存储，场景一大体积线性涨；
   航拍和室内多视角的部署瓶颈就是存储和带宽。
2. HAC++ 已经用“锚点 + 哈希网格条件熵模型 + 算术编码 + G-PCC”把压缩率做得很高，
   是我们的参照基线；我们不换表示、不改主链路。
3. 我们的三个改动都落在“码率控制的自由度”上：量化步长（FQ+RSS）、模型载荷
   （MLP 量化）、锚点数量（SPA）。

提案锚点：Abstract 前两句、§1 第二段（“three surfaces”）。

## 2. 基线（§2.1）

一句话讲清：HAC++ = 结构化锚点 + 多分辨率哈希网格上下文 + 条件熵模型 +
整数 CDF 算术编码 + G-PCC 几何；训练、编码、解码走同一条条件模型路径，
这是 bit-exact 可复现的基础。

提案锚点：§2.1 全部，重点是 mask-aware 概率分解和 mlp_grid 输出
（mean/scale/mixture/基础 Q logits）。

## 3. 创新点一：解码端可复现的内容自适应量化（FQ+RSS）（§2.2）

**讲法**：这不是两个独立创新，是同一个复杂度网络的两半——FQ 决定“步长怎么算”，
RSS 决定“步长应该是什么”。

### 3.1 FQ：步长由解码端重算，零侧信息

- 量化步长 `Q = Q0 × (1 + tanh(z) × α)`，`z` 来自小网络
  `mlp_complexity`，输入是 4 维结构描述符：锚点密度、预测缩放各向异性、
  预测偏移能量、有效掩码比例。
- 这 4 个量解码端全部可重建（锚点坐标 + mlp_grid 输出 + 已解码掩码），
  所以步长不进码流，编码/解码算出来完全一致。
- 关键参数：`Q0 = (1, 0.001, 0.2)`（feat/scaling/offsets）、`α = 0.35`、
  20,000 迭代启动、之后 10,000 迭代 ramp，训练用 STE。

### 3.2 RSS：同一个网络的训练目标

- 累积每锚点渲染损失梯度范数的 EMA，有界归一化后作为目标乘子，
  监督 `mlp_complexity` 逼近“渲染敏感度最优的步长”。
- 只影响训练，编码/解码仍走 FQ 公式路径，码流零新增字段。

### 3.3 为什么必须放在一起讲

- 高码率下 RSS 约 +0.1 dB；SPA 低码率下是关键：去掉 RSS，PSNR 掉 0.42 dB。
- 消融里 FQ 单独（无 RSS）反而有害（−0.29 dB），FQ+RSS 联合 +0.13 dB——
  所以提案按联合设计报告，不在低码率点单独讨论 FQ。

提案锚点：§2.2 全文 + §3.4 Table 4 的交互证据。

## 4. 创新点二：混合精度 MLP 权重量化（§2.3）

**讲法**：解码 MLP 既参与熵模型又参与渲染，是体积里“可压缩且无风险”的一块。

- 做法：per-output-channel 对称量化 + 静态算术编码整数索引；压缩后载荷
  计入报告体积。
- 为什么是混合位宽：逐 MLP 敏感性消融显示，grid/opacity 对 8-bit 敏感
  （grid 8-bit 会让熵模型变差、属性码率反而增加约 0.25 MiB），而复杂度/
  形变网络 8-bit 几乎无损。推荐配置：complexity/deform 8-bit，其余 16-bit。
- 效果：5.65 → 5.49 MiB，质量几乎不变（Table 5）。

提案锚点：§2.3 + §3.5 Table 5。

## 5. 创新点三：训练侧锚点稀疏 SPA（§2.4）

**讲法**：和编码端 top-k 剪枝的区别，是“剪完还让幸存锚点继续训练”。

- 机制：soft score `a = mean(mask)`；每 100 步 ADMM 更新
  `z = TopK(a + u, κ)`、`u = clamp(u + a − z, ±1)`；
  预算 `κ = round(max(N_ref) × ratio(t))` 线性斜坡（1.0 → 目标比例），
  锚定历史最大锚点数避免“每轮减半”的几何塌缩；
  增广损失 `ρ/2·‖a − z + u‖²` 进训练，SPA 状态不进码流。
- 效果：体积 −74%、PSNR −0.84 dB，定义的是一个低码率工作点；同锚点数下
  比编码端 top-k 高 5.5 dB。

提案锚点：§2.4 + §3.4 Table 4。

## 6. 实验协议与主结果（§3.1–§3.2）

**协议一句话**：解码后的真实码流评估，1600 宽、test_every=8，
体积按解码必需载荷计（MiB）。

- 4-28（Table 1）：1200 训练图、150 验证视角。110k + MLP 量化达到
  **28.82 dB / 5.49 MiB**；HAC++ 论文同场景 28.31 dB / 6.95 MiB——
  质量 +0.51 dB、体积 −21%。SPA 点 28.30 dB / 3.77 MiB。
- Deep Blending（Table 2）：高码率点 playroom 30.73 dB / 4.22 MiB、
  drjohnson 30.04 dB / 6.85 MiB；SPA 低码率点 29.90 dB / 0.96 MiB、
  28.76 dB / 1.55 MiB，进入综述方法没覆盖的亚 1 MiB 区间。

提案锚点：§3.1、Table 1、Table 2。

## 7. RD 行为与消融（§3.3–§3.4）

**RD（Table 3 + Fig. 1）**：λ 从 0.001 到 0.004，playroom 体积 5.80→3.01 MB、
drjohnson 9.63→4.76 MB，PSNR 几乎不变（30.62–30.73 / 30.04–30.09）；
开 SPA 后曲线延伸到 0.95–1.26 MiB 区间，说明码率可以连续切换。

**消融（Table 4，playroom 110k / λ=0.002）**：

- SPA 是省体积主导项：4.38 → 1.13 MiB（约 −74%），代价 −0.84 dB；
- SPA 下 RSS +0.42 dB；FQ 无 RSS −0.29 dB；FQ+RSS 联合 +0.13 dB；
- 非 SPA 下 RSS 也 +0.064 dB，FQ+RSS 几乎无变化（+0.002 dB）。

提案锚点：§3.3 Table 3 / Fig. 1、§3.4 Table 4。

## 8. 体积账与可信度（§3.5 + 分析）

- 体积构成：feat/scaling/offsets 属性约占 82.8%，hash + 边界/头部合计
  <0.5%，说明码率都花在内容属性上；MLP 在 32-bit 口径下只占 5.9%，
  量化后整包 5.65 → 5.49 MiB。
- 编码效率（实际码流比特 / 模型交叉熵）≈ 1.0，说明算术编码器已贴紧熵模型；
  KL 审计给出 scaling 至少 0.49 bit/符号的模型侧冗余下界。
- 所有码流通过独立解码验证：符号、量化步长、整数 CDF 不匹配数为零。

提案锚点：§3.5 Table 5、Abstract 末尾的定量分析句。

## 9. 结论（§4）

收尾三句话：

1. DCCA-GS 保留 HAC++ 主链路，把三个码率自由度做成可复现/训练侧的改动：
   FQ+RSS、MLP 量化、SPA。
2. 质量/体积：4-28 上 28.82 dB / 5.49 MiB，优于 HAC++ 同场景参考点；
   SPA 打开亚 1 MiB 低码率区间。
3. 解码自包含、bit-exact，压缩比最高约 111×。

提案锚点：§4。

## 附录 A：评审追问备查（对应提案细节）

### A.1 FQ 与原版 HAC++ AQM 的关系（§2.2）

```text
原版 AQM:  q = Q0 × (1 + tanh(r))，r = MLP_q(f^h)   # 哈希特征预测
DCCA-GS:   q = Q0 × (1 + tanh(z) × α)，z = mlp_complexity(4 维结构描述符)
```

保留“MLP 重算步长、零侧信息”的框架，升级的是输入（解码端可重建的 4 维
描述符）和目标（RSS 渲染敏感度监督）。

### A.2 消融交互（Table 4，供追问）

| 对比 | 发现 |
| --- | --- |
| FQ 单独（无 SPA） | +0.002 dB，几乎无贡献 |
| RSS 在 SPA 下 | +0.42 dB，低码率关键 |
| FQ 在 SPA 下（无 RSS） | −0.29 dB，反而有害 |
| FQ+RSS 联合（SPA 下） | +0.13 dB |

结论：FQ 与 RSS 联合报告，避免低码率 SPA 工作点上的孤立 FQ 结论。

### A.3 体积口径

报告体积 = 解码必需载荷：G-PCC 锚点坐标 + 特征/缩放/偏移算术流 + 掩码 +
哈希参数 + 压缩后的 MLP 载荷 + 边界/头部；不包含检查点与调试数据。

### A.4 已记录的负结果（Abstract 末尾）

- 跨锚点/邻居条件熵增益 <2.3%（P0 系列），关闭；
- 残差编码无收益，关闭；
- 敏感度侧信息与解码端可重算输入的相关性 ≈0（约 0.0086），关闭。

这些负结果说明：熵模型输入侧和编码器本身都已接近饱和，进一步压缩的
空间主要在表示侧（锚点数、步长、模型载荷），这也是三个创新点的选点依据。
