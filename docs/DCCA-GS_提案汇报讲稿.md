# DCCA-GS 提案汇报讲稿（Markdown 版）

> 对应提案：3366-DCCA-GS（Decoder-Reproducible Content-Adaptive Compression
> for Anchor-Based 3D Gaussian Splatting）· 汇报时长约 4–5 分钟
> 本文件是 IEEE 提案的口播稿，并在“创新点”和“附录”里把 FQ/RSS 与 HAC++
> 自适应量化（AQM）的关系写清楚，供口播、评审追问和书面材料复用。

## 开场

各位老师好。我今天汇报的提案是 DCCA-GS：面向锚点式三维高斯泼溅的解码端可复现
内容自适应压缩。一句话概括：我们在 HAC++ 的锚点-哈希压缩框架上做了三个改动——
解码端可复现的内容自适应量化（FQ+RSS）、混合精度 MLP 权重量化、训练侧锚点稀疏
（SPA）——让模型文件更小，而且解码完全可复现。

## 背景

先说明为什么做这件事。3DGS 渲染效果好，但它用大量高斯点把整个场景显式存下来，
几何、协方差、不透明度、外观逐基元存储，模型体积随场景规模快速增长。无人机航拍
和室内多视角采集恰好踩中这个痛点：场景大、细节多，存储和带宽是部署的主要瓶颈。
在已有压缩方法里，HAC++ 用哈希网格上下文加熵编码，压缩率很高，是我们整项工作的
参照。于是我们在 HAC++ 主链路上做增量，不改锚点生成和渲染管线。

## 创新点一：解码端可复现的内容自适应量化（FQ+RSS）

这个创新点由两部分组成，共用同一个复杂度网络，是一个联合设计。

第一部分是让量化步长（quantization step）随内容自适应。统一量化对平坦区域和
细节区域用同一个步长：平坦区域可以量化得粗一点来省码流，细节区域需要更细来保
精度。我们的关键设计是**解码端可复现**：步长根本不传输，而是由解码端也能重建的
四个结构量——锚点密度、预测缩放、预测偏移、有效掩码比例——经过一个小网络直接
算出来。码流里只带这个规则，编码和解码用同样的输入、同样的规则，所以算出的步长
完全一致，零侧信息。

用原版 HAC++ 的话说，FQ 改的是**量化步长的生成方式**：原版 AQM 用 MLP 从哈希
特征预测步长修正量，我们保留这个框架，把输入换成解码端可重建的 4 维结构描述符，
并叠加内容复杂度乘子。

第二部分是让这个网络的训练目标更“懂”渲染。我们累积每个锚点的渲染损失梯度范数，
做指数滑动平均，再经过有界归一化得到目标乘子，监督复杂度网络去逼近“渲染敏感度
最优的步长”。它只影响训练，编码和解码仍走 FQ 的公式路径，因此**不增加任何码流
字段**。

所以 FQ 与 RSS 必须放在一起看：FQ 定义“步长如何由解码端重算”，RSS 定义“步长
应该跟着渲染敏感度走”，二者共同决定同一套步长。高码率下 RSS 只带来约 0.1 dB 的
增益；但在低码率 SPA 场景下它是关键：去掉 RSS，PSNR 直接掉 0.42 dB。

## 创新点二：混合精度 MLP 权重量化

第二个改动在模型本身。解码 MLP 既参与熵模型，也参与渲染，我们按输出通道做对称
量化，再用静态算术编码压缩整数索引。位宽不是统一的：**复杂度网络和形变网络降到
8 位，其余网络保持 16 位**。这个选择来自逐 MLP 敏感性消融：8 位不透明度会直接伤
渲染，8 位网格会让熵模型变差、属性码率反而增加约 0.25 MiB，而复杂度/形变网络
8 位几乎无损。量化后的载荷计入报告体积。

## 创新点三：训练侧锚点稀疏（SPA）

第三个改动是训练侧稀疏。与编码端 top-k 剪枝不同，SPA 在训练中用一个 ADMM 硬预算
直接控制锚点数，预算锚定到历史最大锚点数并线性斜坡，让幸存锚点能在预算下重新
适应。在相同锚点数下，它比编码端 top-k 高 5.5 dB。我们如实说明权衡：SPA 定义的是
**低码率工作点**——体积省约 74%，PSNR 掉约 0.84 dB，不是免费提升。

## 实验结果

实验在 4-28 无人机场景和 Deep Blending（playroom、drjohnson）上做，评估统一用
解码后的码流，1600 宽、test_every=8，体积按解码必需载荷计。

**4-28 主场景**：110k 迭代加 MLP 量化，无 SPA 达到 **PSNR 28.82 dB、体积 5.49 MiB**；
HAC++ 论文同场景参考点是 28.31 dB、6.95 MiB——**质量高 0.51 dB，体积小 21%**。
开 SPA 后，110k 量化点降到 **28.30 dB、3.77 MiB**，体积再省约 31%。

**Deep Blending 泛化**：高码率点 playroom 30.73 dB / 4.22 MiB、drjohnson 30.04 dB /
6.85 MiB；SPA 低码率点 playroom 29.90 dB / 0.96 MiB、drjohnson 28.76 dB / 1.55 MiB，
进入现有综述方法没有覆盖的亚 1 MiB 区间。

**λ 扫描**：两个场景在 λ=0.001 到 0.004 之间体积平滑下降（playroom 5.80→3.01 MB、
drjohnson 9.63→4.76 MB），PSNR 几乎不变，说明码率可以连续切换。

**消融**：SPA 是省体积的主导因素（4.38→1.13 MiB，约 -74%，-0.84 dB）；RSS 在 SPA
下 +0.42 dB；FQ 没有 RSS 时反而有害（-0.29 dB），FQ+RSS 联合 +0.13 dB。所以 FQ 与
RSS 是联合设计的，在低码率点不单独讨论 FQ。

**分析**：编码效率（实际码流比特 / 模型交叉熵）接近 1.0，说明算术编码器已贴紧熵模型；
KL 冗余审计给出缩放字段至少 0.49 bit/符号的模型侧冗余下界；所有码流通过独立解码
验证，符号、量化步长、整数 CDF 不匹配数为零。

## 结尾

总结：DCCA-GS 在 HAC++ 基础上做三个改动——FQ+RSS 让自适应量化不再有传输负担、
且步长跟着渲染敏感度走，MLP 量化无损省体积，SPA 打开低码率区间。三点都不改
HAC++ 主链路，解码完全自包含。我们把它定位为面向存储与传输的可部署压缩方案。
以上是我的汇报，谢谢。

## 附录 A：FQ/RSS 与原版 HAC++ AQM 的关系（评审追问 / 书面补充用）

### A.1 一句话结论

原版 HAC++ 的自适应量化（AQM）是“可学习的量化步长预测器”：MLP 从哈希特征预测
每锚点步长修正量，编码端和解码端用同一套权重重算步长，零侧信息。DCCA-GS 的 FQ
保留这个框架，只升级输入与目标：输入换成解码端可重建的 4 维结构描述符；RSS 用渲染
梯度 EMA 监督复杂度网络，训练期生效、不写码流。两者共同构成一个联合创新点：FQ
决定步长的生成机制，RSS 决定步长的训练目标。

### A.2 步长公式

```text
原版:   q = Q0 × (1 + tanh(r))，r = MLP_q(f^h)
FQ:     q = Q0 × (1 + tanh(z) × α)，z = mlp_complexity(4 维结构描述符)
```

Q0 对特征、缩放、偏移分别取 1、0.001、0.2；α=0.35。编码/解码两侧用同一输入重算
步长，所以步长不进码流，零侧信息。

### A.3 为什么 4 维就够了

四个分量（局部锚点密度、预测缩放各向异性、预测偏移能量、有效掩码比例）全部可由
解码端从锚点坐标、熵模型输出和已解码掩码重建；早期设计中额外的图像侧统计量在公式
模式下恒为零，属于死输入，因此已从网络输入中删除。

### A.4 消融要点（供追问）

| 对比 | 发现 |
| --- | --- |
| FQ 单独（无 SPA） | 仅 +0.002 dB，几乎无贡献 |
| RSS 在 SPA 下 | +0.42 dB，低码率关键 |
| FQ 在 SPA 下（无 RSS） | -0.29 dB，反而有害 |
| FQ+RSS 联合（SPA 下） | +0.13 dB |

结论：FQ 与 RSS 联合报告，避免在低码率 SPA 工作点上单独讨论 FQ。

### A.5 体积口径

报告体积 = 解码必需载荷：G-PCC 锚点坐标 + 特征/缩放/偏移算术流 + 掩码 + 哈希参数 +
压缩后的 MLP 载荷 + 边界/头部；不包含检查点与调试数据。
