# 增强层学习式上下文编码：设计与探针协议（2026-09-28）

> 分支 `feat/enh-layer-learned-coder`（基于 44604a1）。
> 定位：渐进分层码流的下一个最大提升杠杆的探针设计。探针脚本
> `scripts/probe_ctx_v4.py`；逐阶段字节审计由 `c25_real_bitstream.py
> --stage-audit` 提供。表述遵守 AGENTS.md 命名原则：机制一律说它是什么。

## 1. 它是什么

现行生产编码器把每个量化残差拆成一串是非题（是否非零 → 符号 → 幅度逐位
延续），每道是非题的概率查一张静态条件表：行是"贡献组 × 步长档位"，列是
"已解码粗值所在的桶"。这张表在解码端可以重算（零边信息契约），代价是条件
粒度粗、且不随内容变化。

本方向要做的是：**基层（可截断契约覆盖的部分）保持静态表不动；增强层的
是非题概率改由一个小 MLP 给出**——输入全部是解码端在该时刻已经拿到手的
量（已解码粗值、组号、步长乘积、邻锚已解码值等），权重随码流传输。静态表
不是被删掉，而是被 MLP 在增强层替代；截断契约、解码端重算契约都不动。

## 2. 为什么值得做（已有证据）

- 满精度档实测：静态表版编码器比学习式上下文编码器（HAC++ 谱系）贵约
  3–6 MB（约 40%），是同字节下落后 HAC++ 0.5–0.9 dB 的主要来源
  （experiments.csv 已登记；组会汇报 20260928 §4）。
- "条件表细化到顶"的证负结论（步长档位×分组变细，±0.1% 噪声级）只在
  **静态表架构**下成立——换成学习式上下文后，条件粒度这个自由度重新打开。

## 3. 前两次失败的教训（本设计针对它们）

| 尝试 | 结果 | 教训 |
| --- | --- | --- |
| S4：MLP 直出（均值,宽度）替代条件表 | 接入生产后零增益 | 上下文只有（粗值,组,logQ），是静态表已有条件的子集，赢不了 |
| 探针 v3：offset 细化标志 MLP | 对"仅按组"简化表省 45.9%（过门） | 基线与生产不同构——生产表还按粗值幅度分桶，45.9% 高估了可兑现收益 |

结论（已入册负结果台账）：**门测量的参照基线必须与生产编码器同构**。

## 4. 探针 v4 协议（scripts/probe_ctx_v4.py）

1. **同构基线**：静态基线就是生产条件模型本身——同样的"组×步长档位×
   粗值桶"格子、同样的后备链（格子 → 贡献组 → 全局）、同样的几何尾拟合，
   在同一批决策上求值。
2. **划分**：锚点级 90/10（同一锚点的全部决策同侧），划分先于任何拟合；
   静态表与 MLP 都只在训练侧锚点上拟合，验证侧出数。
3. **比特数**：真实区间编码器输出（往返断言），不用理论 BCE 冒充。
4. **特征合法性**：每个特征必须能被解码端在编码该符号的时刻重算出来。
   按 2026-09-28 审计后的码流顺序（层主序、层内 feat→scaling→offset、
   锚点行主序），合法特征组：
   - base：本符号已解码粗值（含符号与绝对值）、logQ、贡献组嵌入、桶嵌入、
     步长档位嵌入；
   - spatial：按行主序先编码的相邻一至两个锚点、同列的已解码粗值；
   - crosscol：同一锚点内先编码的列的已解码残差与粗值；
   - crossfield：同一层里先编码字段（feat、scaling）的同锚点平均残差幅度。
   （由最终符号推出的累计量与解码端已解码值逐位相等，合法性成立。）
5. **两条决策流分开测**：flag = "是否非零"（全部符号各一道）；cont =
   幅度延续位（非零符号各 m 道）。哪个流剩余熵多、哪个值得换，由
   `--stage-audit` 的逐阶段字节账先给出。

## 5. 判定门（预登记）

- 主门：验证侧、真实比特、对同构静态基线的**净节省 ≥15%**（算上权重，
  权重按 4 字节/参数计）；
- 跨场景方向一致（1-78 与 2-06 同号才算稳定）；
- 同时报告生产表（全量拟合、略偏乐观）参照列，用于核对"训练侧拟合损失"。
- 不过门：静态表保留，学习式上下文方向**永久关闭**（第三次证负不再重试）。

## 6. 过门后的接入计划（不在本分支实施）

1. 码流格式升 v4：header 增加学习式条件头的层级清单；权重紧随 s5 blob
   的位置之后（同样在全部块数据之前，物理截断天然安全）。
2. `code_chunk`/`decode_chunk` 增加 stage-probs 提供方（静态表 | flag 头 |
   全决策头），编码端逐层训练、解码端逐层加载——沿用 S5 已验证的
   "训练在全部符号上、权重入文件"部署方式。
3. 独立前缀解码器（s5 分支已建 `c25_prefix_decode.py`）扩展消费 v4 blob；
   截断契约测试全档重跑。
4. 数字登记：先 experiments.csv 后报告；两场景 + 满精度逐位一致验证。

## 7. 明确不做

- 不重开"S4 直出概率"路线（上下文是静态表子集，已证无增益）。
- 不动基层与截断契约（s5 分支已验证的 v3 格式字节不动）。
- 不在探针过门前投入生产接入工程。

## 8. 执行顺序

1. 服务器对 1-78 λ0.0005 跑 `c25_real_bitstream.py --stage-audit`：拿到
   逐字段、逐层、逐阶段（是否非零/符号/幅度）的字节分布，定位 3–6 MB
   落在哪些决策流上（预期 offset/feat 的幅度延续位是大头）。
2. 对字节账最大的决策流跑探针 v4（flag 与 cont 各一轮，context=all）。
3. 用 `--context` 消融（去掉 spatial / crosscol / crossfield）归因每个
   特征组的贡献，决定接入时带上哪些。
4. 过门 → 按 §6 接入；不过门 → 关闭并入负结果台账。
