## 0. TL;DR

1. **方向成立**：锚点体积在现有架构里是现成的量（`get_scaling[:, :3]`，无需新 render、
   无需持久 buffer），作为"单位体积贡献"的惩罚项，物理直觉合理。
2. **但外部提案不能照搬**，三处硬伤：
   - "w_i = 1/s_i 进加权 L1"没有落点——我们的 ADMM（SPA）是**预算 top-k 选择**，
     不是逐锚点加权 L1，体积只能进**分数**；
   - "体积预算约束"与码率模型冲突——比特 ∝ 锚点数 × 每锚点固定位数，
     体积预算不省码流，只会破坏 κ-ramp；
   - 首推的除法公式 `s = Ã^α·Ĝ^β/Ṽ^γ` 在 Ṽ→0 处爆炸，会重演低预算坍缩（low-budget collapse）。
3. **推荐形式**：在现有凸组合上加**线性减法项**，
   `imp = (1−eff)·cov + eff·sens − γ·Ṽ`（clamp ≥0），新配置 `fusion_volume_weight`，默认 0。
   覆盖主导的 0.3 cap 原封不动；除法式只作消融对照。
4. **最便宜的第一步是预检**：报告 corr(覆盖面积, 体积)。若 > 0.9，体积没有边际信息，
   整个提案直接终止。

## 1. 背景与动机

现有融合分数只有两个二维量：覆盖面积（coverage area，锚点投影像素贡献）与
敏感度（render sensitivity，渲染损失梯度范数的 EMA）。外部提案（2026-09-08 对话）
建议加入第三个三维量——锚点体积（anchor volume），核心直觉：

- 覆盖面积大 → 影响范围广；
- 敏感度高 → 去掉损失大；
- **体积大而覆盖小 → "大而空"的锚点，信息密度低，应惩罚**。

即体积应作为分母/负项出现，保留"单位体积贡献大"的锚点。本文评估该提案
在**本仓库现有实现**上的可行性，并给出落地形式。

## 2. 现状：融合剪枝的真实结构

代码路径（`fusion_prune=True` 时）：

1. **覆盖面积**：`compute_contribution_areas`（`scaffold_gs/mini_splat.py:282`），
   采样相机上逐锚点累加像素贡献面积，每轮 `adjust_anchor` 在生长后刷新，
   存入 `mini_splat_importance`；
2. **敏感度**：`accumulate_sensitivity`（`scaffold_gs/hacpp.py:1152`），
   pre-quant 特征/缩放/偏移梯度范数的 EMA，三个 buffer 求和后 log1p + max 归一化；
3. **融合**（`hacplus/scene/gaussian_model.py:1687`）：
   `imp = (1−eff)·cov + eff·sens`，`eff = min(fusion_sensitivity_weight, 0.3)`——
   敏感度份额硬 cap 0.3，这是低预算坍缩修复（d3b4f49）的产物；
4. **SPA 选择**（`gaussian_model.py:1721`）：
   `scores = imp + 0.25·(a + spa_u)`，按预算 κ（从 1.0 ramp 到 `spa_ratio`）
   做 top-k 选择得到 z，u 更新；`spa_coverage_constraint` 开启时
   每个粗 cell 强制保留 top-1 再补齐。

**两个决定落点的事实：**

- SPA 是**固定预算的子集选择**：融合分数只决定"哪些锚点活"，不决定"活多少"。
  没有逐锚点幅度 × 权重的 L1 惩罚项 → 外部提案的 `w_i = 1/s_i` 加权式**无槽可插**，
  体积唯一正确的注入点是分数本身。
- **码率模型**：总比特 ≈ 锚点数 × (feat_dim + 6 + 3·n_offsets) + 哈希开销。
  体积不进码流、不影响每锚点位数 → 体积预算约束不省码流；
  κ 是计数预算，RD 曲线（率失真曲线）整条建立在"比特 ∝ 锚点数"上。
  **体积在本系统中只能是"固定预算下重分配质量"的信号，不是压缩信号。**

## 3. 锚点体积的定义：现成的量

锚点自带 per-anchor 尺寸参数 `_scaling` [N, 6]，其中 `get_scaling[:, :3]`
是该锚点子高斯（neural gaussian）的偏移网格尺度
（`gaussian_model.py:1350`：`all_xyz = anchor + offset * get_scaling[:, :3]`），
即锚点的"势力范围"。定义：

```text
V_i ∝ prod(get_scaling[i, :3])     （全局因子 voxel_size³ 常数，可省略）
```

实现上的关键优势：**现场从活参数读出**。

- 不需要新 render pass（对比"子高斯体积"要在覆盖渲染时顺带收集，留作 v2）；
- 不需要持久 buffer——无需加入 `sensitivity_*` 那套 reinit/append 的
  padding 名单，长度永远对齐，不存在静默回退风险；
- densify 后自动更新（体积随训练变化，与覆盖面积同节奏刷新）。

## 4. 外部提案逐条评估

| 提案选项 | 评估 | 结论 |
| --- | --- | --- |
| 1. 密度式分数 `s = Ã^α·Ĝ^β/Ṽ^γ`，`w=1/s` 进加权 L1 | 直觉对；但加权 L1 无落点；除法式有 Ṽ→0 爆炸与"小而废"奖励问题（见 §5.1） | **改造后采用**（减法式） |
| 2. 线性加权 `w_A·Ã + w_G·Ĝ − w_V·Ṽ` | 与现状最接近，单调安全 | **采用（即推荐形式）** |
| 3a. 体积作独立惩罚 `λ₂·Σ V_i·\|θ_i\|` | 同选项 1，无加权 L1 槽位；减法式即其分数级等价 | 并入选项 2 |
| 3b. 体积预算约束 `Σ V_i·1[保留] ≤ V_budget` | 与码率模型冲突（§2），把 top-k 变 knapsack 投影，破坏 κ-ramp | **否决** |
| 4. Pareto 非支配排序 | 实现复杂、与 top-k 管线不自然；三指标线性减法已够用 | 否决（不必要） |

另：提案实验表中"基线 `s = Ã·Ĝ`"描述有误，我们的基线是 **0.7/0.3 凸线性组合**，
消融以此为准。

## 5. 推荐方案：体积作线性减法项

### 5.1 为什么不用除法式

1. **除零爆炸重演低预算坍缩**。min-max 归一化后 Ṽ 有精确 0；即便加 ε，
   体积最小的锚点分数趋近 1/ε 被无条件保留，κ 固定时零和地挤掉高覆盖锚点。
   这与已修复的坍缩（敏感度主导 → 覆盖主导 cap 0.3）是**同一结构失效**：
   某单项主导分数 → 低预算下关键锚点被挤出。乘除法对尾部的放大远强于凸线性组合。
2. **cov 与 V 强正相关**（势力范围大 → 投影面积大概率大）。体积的边际信息
   恰是残差——"范围大但不显眼"的那批锚点。残差噪声主导，γ 必须给小；
   乘除法会放大这个噪声。
3. **方向性风险**：密度式无条件奖励体积趋零的锚点，制造"小而废"幸存者。

### 5.2 公式

在 `gaussian_model.py` 融合块（`imp = (1.0 - eff) * cov + eff * s`）处改为：

```python
# 锚点体积：现场计算，log1p 压尾 + 分位数截断归一化到 [0,1]
vol = torch.prod(self.get_scaling[:, :3], dim=1)          # [N]
v = torch.log1p(vol.clamp_min(0.0))
v = v / torch.quantile(v, 0.99).clamp_min(1e-8)
v = v.clamp(0.0, 1.0)

imp = ((1.0 - eff) * cov + eff * s - gamma * v).clamp_min(0.0)
```

- `gamma` = 新配置 `fusion_volume_weight`，**默认 0.0**（全部现有实验行为不变）；
- 覆盖主导 0.3 cap、SPA 选择、覆盖约束全部不动；
- 归一化用分位数截断（0.99）而非裸 max，防长尾单点把 Ṽ 压扁；
  与 cov 的 max 归一化口径差异在消融中观察即可，不追求完全一致。

### 5.3 与现有安全网的配合

- 覆盖约束（每粗 cell 强制留 1 锚点）与分数无关地兜底：
  体积惩罚即使剪过头，cell 内仍有锚点存活——这是加体积项比当年加敏感度项
  更稳的结构性原因；
- 体积不进码流、解码端不出现、不改布局——满足创新 B 的"零码流代价"前提。

## 6. 消融与判定规则

### 6.1 预检（最便宜的淘汰）

跑一次现有配置，导出 cov 与 V，报告 Pearson 相关：

- **corr(cov, V) > 0.9** → 体积无边际信息，提案终止，不写代码；
- 0.7 ~ 0.9 → 可做，γ 从小起步；
- < 0.7 → 残差信息丰富，值得做。

### 6.2 消融矩阵（1-78 开发场景，30k）

| 组 | 配置 | 验证什么 |
| --- | --- | --- |
| 0 | 基线（γ=0，即现状 0.7/0.3） | 对照 |
| 1 | γ = 0.05 | 小惩罚是否已够 |
| 2 | γ = 0.1 | 中间档 |
| 3 | γ = 0.2 | 惩罚上限（超过则风险大） |
| 4 | 除法式 `s = Ã·Ĝ/Ṽ^γ*`（仅 1 档） | 验证 §5.1 的坍缩论证（预期劣化，作为证据） |

指标：PSNR/SSIM/LPIPS、total_MB 双口径、训练时间；**重点盯 λ=0.004**
（上次坍缩发生的低码率档）。

### 6.3 判定规则

1. 组 1~3 相对组 0：同码率 PSNR +≥0.05 dB（至少在 λ=0.004 档不回归）→ 保留最优 γ；
2. total_MB 相对组 0 偏移 > ±1% → 实现有泄漏（κ 不变则大小应不变），先修实现再谈增益;
3. 全档无增益或 λ=0.004 回归 → 关闭该项（γ=0），避免复杂度；
4. 通过后按 `融合剪枝跨场景泛化报告` 的流程在 2-06/4-10 复验泛化。

   `scaling_activation`；导出/解码路径不涉及，无重算墙。

预计 diff ≈ 20 行 + 1 个配置项 + 1 个消融脚本参数。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 低预算坍缩复发 | 减法式（无奇点）+ `clamp_min(0)` + γ ≤ 0.2 上限 + 覆盖约束兜底 |
| cov–V 相关过高，白做 | §6.1 预检先行 |
| "小而废"锚点被奖励 | 不采用除法式；若消融组 4 劣化即作为证据记录 |
| 分数语义漂移（减法后 imp 可为负截 0） | 观测 `imp==0` 的锚点占比；过高（>20%）说明 γ 过大 |
| get_scaling 训练早期未收敛，体积噪声大 | 体积项可与敏感度同节奏在 `sensitivity_start_iter` 后启用（沿用现有门槛） |

**新增文献反例（重要）**：文献中体积的用法与本文方向相反——

3. 执行顺序锁死：fusionfix 判定 → corr 预检 → γ 网格。
