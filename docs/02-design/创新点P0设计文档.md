本文档回答两个问题：

1. P0-1：渐进式跨属性编码（progressive cross-attribute coding）怎么做，即用已解码的局部特征（feat）作为缩放（scaling）与偏移量（offsets）的熵模型先验。
2. P0-2：空间自适应上下文（adaptive spatial context）怎么做，即在确定性编码顺序下，用已解码的相邻锚点（anchor）改善熵编码。

本文档使用第一性原理方法：先拆到可验证的基本事实，再从基本事实重建方案。

## 1. 问题定义

### 1.1 要解决的问题

在现有 PHG 压缩框架下，用更少的码率达到相同的渲染质量，或者在相同码率下达到更高的渲染质量。

现有框架已经包含：

- 锚点位置由 GPCC 压缩；
- 哈希网格（`calc_interp_feat`）提供锚点级空间上下文；
- 局部特征使用通道内自回归上下文（`Channel_CTX_fea`，10 通道一组）；
- scaling 与 offsets 使用 `mlp_grid` 预测的高斯分布做算术编码；
- I2 内容感知公式量化调制量化步长（Q）。

现有框架缺少两项冗余利用：

1. **跨属性冗余**：scaling 与 offsets 由锚点局部特征经 MLP 生成，两者与局部特征高度相关。但当前编码 scaling/offsets 时，没有使用已经解码出来的局部特征作为先验。
2. **跨锚点空间冗余**：相邻锚点的属性通常相似。但当前只有位置相关的哈希网格上下文，没有使用“已解码的相邻锚点符号”作为自回归上下文。

### 1.2 成功标准

每一项创新必须满足以下全部条件：

1. 在解码后的码流上评估，而不是在训练态参数上评估。
2. 报告 RD 曲线（率失真曲线，rate-distortion curve）与 BD-rate（同质量码率节省百分比）。
3. 编码端与解码端 bit-exact（逐位一致）roundtrip 通过。
4. 所有旁路信息（side info）与新增模型权重计入码率。
5. 可复现：固定种子、固定代码版本、固定数据集。

### 1.3 硬约束

1. 解码端只能访问模型权重、解码出的锚点坐标、已解码的符号与旁路信息。
2. 编码端与解码端必须使用相同的编码顺序、相同的上下文选择规则、相同的量化规则。
3. 任何改动都必须同步修改训练、编码、解码、渲染四条路径中受影响的路径。
4. 码率口径必须统一：最终码率 = 属性码流 + 几何码流 + 模型权重 + 旁路信息。

## 3. 被剥离的不可靠假设

以下说法在本文档中不作为推理前提：

1. “HEMGS 的 40% 收益可以原样迁移到 PHG” — 基线、属性结构与训练方式不同。
2. “上下文越多越好” — 过远或无关的上下文会引入噪声，甚至升高码率。
3. “最近 20 个元素是全局最优” — 该参数来自 HEMGS，需要重新扫描。
4. “可以使用尚未解码的未来锚点作上下文” — 解码端无法获得，除非写入旁路信息。
5. “必须用 CNN 判断相邻锚点相关性” — 自回归 MLP + 确定性邻域选择已经足够。

## 4. 基本事实

### 4.1 信息论基础

1. 熵编码的实际码率可以无限接近 `Σ -log2(p(symbol))`。
2. 给定更好的上下文，条件熵下降，码率下降。
3. 量化是有损步骤，熵编码是无损步骤；上下文只影响无损部分。

### 4.2 3DGS 结构基础

1. 锚点属性包括局部特征（feat）、缩放（scaling）、偏移量（offsets）、掩码（mask）。
2. scaling 与 offsets 由局部特征经 MLP 解码得到，因此跨属性冗余是结构性的。
3. 解码端按 Morton 顺序重建锚点坐标，所有已解码锚点都可作为后续锚点的上下文。
4. offsets 有 mask 控制，上下文必须区分有效与无效偏移。

### 4.3 编解码路径基础

1. 当前 feat 解码已经是逐 10 通道的通道内自回归流程。
2. 当前 scaling/offsets 解码只依赖 `mlp_grid` 输出的高斯参数。
3. 编码端可以用 STE（straight-through estimator，直通估计器）量化 feat 来模拟解码端看到的 feat。

## 5. P0-1：渐进式跨属性编码

### 5.1 原理

scaling 与 offsets 是锚点局部特征经过 MLP 预测出来的。给定已解码的局部特征后，它们的条件分布比“只知道位置”更集中，因此条件熵更低。

当前代码已经具备实现前提：`decode_attributes` 先解码 feat，再解码 scaling/offsets。编码端按相同顺序执行即可。

### 5.2 技术设计

#### 5.2.1 新增属性上下文网络

新增一个小型 MLP `mlp_attr_ctx`：

```text
输入：concat(mean_scaling, scale_scaling, mean_offsets, scale_offsets, feat_decoded)
输出：mean_scaling_adj, scale_scaling_adj, mean_offsets_adj, scale_offsets_adj
```

其中 `mean_*` / `scale_*` 来自 `mlp_grid` 对当前锚点的预测，`feat_decoded` 是该锚点已经解码出的局部特征。

实现约束：

- `mlp_attr_ctx` 权重随 MLP payload 导出并计入码率；
- 编码端与解码端使用完全相同的输入构成；
- 训练、编码、解码三条路径都使用同一网络。

#### 5.2.2 编码路径

1. 按现有流程完成 feat 的 STE 量化与码流写入；
2. 用 `feat_q`（STE 量化后的 feat）模拟解码端看到的局部特征；
3. 计算 `mlp_grid` 的原始 scaling/offsets 熵参数；
4. 用 `mlp_attr_ctx` 生成调整后的熵参数；
5. 用调整后的熵参数编码 scaling/offsets。

#### 5.2.3 解码路径

1. 先解码 feat（现有逻辑不变）；
2. 计算 `mlp_grid` 的原始 scaling/offsets 熵参数；
3. 用 `mlp_attr_ctx` 生成调整后的熵参数；
4. 用调整后的熵参数解码 scaling/offsets。

#### 5.2.4 训练路径

`_estimate_rate_terms` 必须同步修改：估计 scaling/offsets 码率时，使用与编解码一致的 `feat_q` 作为 `mlp_attr_ctx` 输入。否则训练分布与编解码分布失配。

#### 5.2.5 配置

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `progressive_coding` | bool | `False` | P0-1 开关 |
| `mlp_attr_ctx_hidden` | int | `64` | 属性上下文 MLP 隐藏层宽度 |
| `mlp_attr_ctx_layers` | int | `1` | 属性上下文 MLP 层数 |

### 5.3 可选变体

1. **V1（推荐先做）**：只调整 scaling/offsets 的熵参数，不改 Q。
2. **V2**：把 `feat_decoded` 的统计量也加入 I2 公式输入，同时调整 Q。
3. **V3**：把 `feat_decoded` 用于 feat 自身的通道上下文初始化（与 P0-2 重叠，后做）。

### 5.4 离线验证

在训练好的模型上，对 scaling/offsets 分别计算：

```text
H_current = Σ -log2 p(symbol | mlp_grid 熵参数)
H_prog    = Σ -log2 p(symbol | mlp_grid 熵参数, feat_decoded)
```

停止条件：

- `H_prog` 相对 `H_current` 下降不足 3%，放弃 P0-1；
- 离线增益明显但编码后 BD-rate 无改善，放弃。

## 6. P0-2：空间自适应上下文

### 6.1 原理

锚点在空间上聚集，相邻锚点的局部特征、缩放、偏移量通常相似。使用已解码的相邻锚点符号作为上下文，可以降低当前锚点的条件熵。

当前框架已经有 I1 的位置层级上下文，但它只使用位置与哈希特征，不使用相邻锚点“已经编码出的符号”。P0-2 补的是真正的跨锚点自回归上下文。

### 6.2 技术设计

#### 6.2.1 确定性编码顺序

沿用现有 Morton 排序：

```text
anchor_int = round(anchor / voxel_size)
order = calculate_morton_order(anchor_int)
```

编码与解码按同一顺序逐锚点处理。

#### 6.2.2 上下文选择

**方案 A（先做）：前 k 个 Morton 相邻锚点**

对当前锚点 `i`，取已解码的 `i-k .. i-1` 锚点作为上下文。Morton 顺序下相邻索引通常对应空间相邻，实现简单、完全确定。

推荐先扫描 `k ∈ {8, 16, 32}`。

**方案 B（后做）：密度自适应选择**

参考 HEMGS：

1. 以当前锚点为中心，按半径 `R = radius_factor × voxel_size` 收集候选锚点；
2. 候选数少于阈值 `n` 时，全部作为上下文；
3. 候选数超过阈值时，按距离取最近的 k 个。

该方案更准确，但需要实现确定性的邻域收集，工程成本更高。

#### 6.2.3 上下文特征

对每个当前锚点，从已解码锚点构建：

```text
context_i = concat(
    base_context_i,                 # 现有 calc_context_feat(anchor_i)
    agg({feat_j, scaling_j, offsets_j, mask_j, anchor_j - anchor_i}),  # j ∈ neighbors
)
```

`agg` 先使用 mean/max 池化，后续可替换为小型注意力网络。

新增 `mlp_spatial_ctx`，输入 `context_i`，输出 scaling/offsets 熵参数的调整量：

```text
mean_adj, scale_adj = mlp_spatial_ctx(context_i)
```

#### 6.2.4 范围控制

第一版限定在 chunk 内取前 k 个锚点；验证通过后再实现跨 chunk 上下文。

跨 chunk 时需要把上一 chunk 的已解码 feat/scaling/offsets/mask 保存下来，作为下一 chunk 的上下文来源。

#### 6.2.5 配置

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `spatial_context` | bool | `False` | P0-2 开关 |
| `spatial_context_mode` | str | `"prev_k"` | `prev_k` 或 `density_adaptive` |
| `spatial_context_k` | int | `16` | 使用的相邻锚点数 |
| `spatial_context_radius_factor` | float | `2.0` | 密度自适应半径 = 因子 × voxel_size |
| `spatial_context_threshold` | int | `20` | 稀疏/密集阈值 |
| `mlp_spatial_ctx_hidden` | int | `64` | 空间上下文 MLP 隐藏层宽度 |

### 6.3 与 I1 的关系

- I1 是“位置 → 哈希特征”的层级上下文，不依赖已解码符号；
- P0-2 是“已解码相邻锚点符号 → 熵参数调整”的自回归上下文；
- 两者可叠加，也可以把 P0-2 作为 I1 的替换做消融。

### 6.4 离线验证

在训练好的模型上比较：

```text
H_base  = Σ -log2 p(symbol | 现有熵参数)
H_ctx   = Σ -log2 p(symbol | 现有熵参数, 空间上下文)
```

停止条件：

- `H_ctx` 相对 `H_base` 下降不足 3%，放弃 P0-2；
- 不同 k 值没有单调差异时，记录最佳 k 并继续。

## 8. 实验设计

### 阶段 0：离线熵对比（不训练）

对训练好的模型：

1. 计算现有 scaling/offsets 符号熵；
2. 计算加 `feat_decoded` 条件后的符号熵（P0-1）；
3. 计算加空间上下文后的符号熵（P0-2）；
4. 比较三者，决定是否继续。

停止条件：

- P0-1 离线增益 < 3%，放弃 P0-1；
- P0-2 离线增益 < 3%，放弃 P0-2。

### 阶段 1：P0-1 渐进式编码

交付物：

- `mlp_attr_ctx` 与配置；
- 编码/解码/训练三路径同步修改；
- bit-exact roundtrip 测试。

验收标准：

- 默认关闭时与 PHG v1 完全一致；
- 开启后 roundtrip bit-exact；
- BD-rate 相对基线 ≥3%。

### 阶段 2：P0-2 空间自适应上下文

交付物：

- `mlp_spatial_ctx` 与确定性邻域选择；
- `prev_k` 变体与 `density_adaptive` 变体；
- 跨 chunk 上下文状态管理（第二阶段）。

验收标准：

- 开启后 roundtrip bit-exact；
- 至少一个变体 BD-rate 相对基线 ≥3%；
- 解码耗时增幅可接受（≤50%）。

### 阶段 3：组合实验

消融矩阵：

| P0-1 | P0-2 | 说明 |
| --- | --- | --- |
| 关 | 关 | PHG v1 基线 |
| 开 | 关 | 渐进式跨属性编码 |
| 关 | 开 | 空间自适应上下文 |
| 开 | 开 | 组合 |

最终报告：

- RD 曲线与 BD-rate（PSNR、SSIM、LPIPS）；
- size breakdown；
- 训练时间与解码时间；
- 视觉对比（平滑区域、密集区域、稀疏区域）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 新增 MLP 体积吃掉压缩收益 | 控制网络规模；体积计入 total_MB；若收益 <3% 放弃 |
| 编码/解码上下文不一致 | 每个变体跑 bit-exact roundtrip；上下文只用已解码数据 |
| 跨 chunk 状态管理出错 | 先做 chunk 内变体，再做跨 chunk；增加哈希校验 |
| 训练期码率估计与编解码失配 | `_estimate_rate_terms` 使用与编码相同的 STE feat 路径 |
| 顺序解码变慢 | 记录解码耗时；必要时并行化无依赖部分 |
| 固定 k 对稀疏/密集场景都不好 | 实现密度自适应变体；按数据集分别报告 |
| 与 I1 重复或冲突 | 做 P0-2 on/off 与 I1 on/off 的 2×2 消融 |

## 10. 实施计划

### 阶段 A：离线验证

交付物：离线条件熵对比脚本与报告。

### 阶段 C：P0-2

## 11. 统一评估体系

### 11.1 指标

| 指标 | 说明 |
| --- | --- |
| PSNR | 峰值信噪比，越高越好 |
| SSIM | 结构相似性，越高越好 |
| LPIPS | 感知相似度，越低越好 |
| BD-rate | 同质量码率节省百分比，越低越好 |
| size breakdown | 每个字段、模型、旁路信息的 MB 分解 |
| roundtrip | 编码解码逐位一致 |

### 11.2 口径

1. 所有码率包含属性、几何、模型权重、旁路信息。
2. 所有质量在解码后的码流上评估。
3. 所有实验固定随机种子并记录。
4. 负结果如实报告。
