# 概念删除（压缩域）最小验证实验设计

- 建立：2026-10-01（分支 `feat/concept-deletion-mvp`）
- 背景与竞争格局：`../03-reports/3DGS十方向选题决策_报告_20261001.md` 方向 6/10 节；
  叠加到 DCCA-GS 的可行性讨论见同日对话结论（压缩即删除保障 / 可删除性的码率代价 /
  网格与熵模型侧信息泄漏三个编解码器独有贡献点）。
- 一句话目标：在一个训好的 DCCA-GS 场景上，删掉指定概念（某物体/某人形）对应的锚点，
  定量回答三个问题——归属准不准、网格里还剩什么、解码渲染里还能认出什么。

## 一、可证伪判据（先写死再跑，不事后移动）

| 编号 | 判据 | 达标含义 | 止损线 |
| --- | --- | --- | --- |
| P1 归属 | SAM2 区域掩码投影 + 支持度投票后，取阈值 τ 删除，概念区域在保留视图上的覆盖核查：被删锚点在目标掩码内的投影占比 >95%，同时非目标区域锚点误删率 <5% | 归属机制可用，可进入 P2/P3 | 误删率 >20% 且调 τ 无法拉开 → 归属路线降级（改用逐高斯归属或人工标注） |
| P2 网格泄漏 | 删除锚点、网格原样保留时，被删区域网格特征能量比（norm_ratio_deleted_over_surviving）显著高于远离锚点的基线位置；且与存活特征的最大余弦相似度分布未塌缩到基线水平 | "网格仍在编码被删内容"成立，论文第一图成立 | 与基线无显著差异 → 网格不泄漏（否定结果仍有价值：审计面收窄到锚点+侧信息，故事线改讲） |
| P3 残留审计 | 删除后重编码 + 解码渲染，概念掩码内重识别/检测器命中率为 0（或 <2%），主体区域 PSNR 下降 <0.5 dB（相对未删除解码） | "删除-质量"权衡曲线可画，管线成立 | 主体掉 >2 dB 或残留检出仍高 → 修补环节（方向 10）升级为必做组件 |

P2/P3 都达标 → 故事按 `../05-paper/概念删除_故事线草案.md` 的推荐框架展开。

## 二、三步协议

### 第 1 步：锚点归属与删除（本地 CPU 可跑，代码已就绪）

- 代码：`scripts/deletion_audit/anchor_attribution.py`；冒烟测试 `tests/test_deletion_mvp.py`（6 项全过，2026-10-01）。
- 输入：`train.py` cmd_export 导出的 `attributes.pth`。
- 选择方式三选一：`--ids-file`（下标文件，服务器端生成）、`--sphere`、`--box`。
- 输出：`attributes_deleted.pth`（逐锚点键按第一维过滤：anchor/offset/mask/anchor_feat/scaling/rotation/opacity；
  网格与解码器参数**原样保留**，这是 P2 的被测对象）+ `attribution_report.json`。
- 支持度投影库函数 `mask_project_support_scores`：相机（OpenCV 约定）+ 逐视角区域 id 图 +
  目标区域 id → 逐锚点投票占比。SAM2 区域图来自 `runs/semantic_cache/<scene>`
  （`scripts/extract_semantic_priors.py` 的产物，已具备）。

### 第 2 步：网格泄漏探针（统计本地可跑，HAC++ 前向在服务器）

- 代码：`scripts/deletion_audit/grid_leakage_probe.py`。
- dense 后端（本地 CPU）：稠密网格 + 三线性采样（F.grid_sample，对齐轴序），冒烟测试
  已验证"精确采样 = 网格原值"和"植入泄漏可被统计量识别、干净对照不误报"。
- hacpp 后端（5090，CUDA）：`probe_features_hacpp(model, points)` 对
  `mix_3D2D_encoding`（3D 网格 + xy/xz/yz 三平面）前向取特征，逻辑与 dense 相同。
- 三组采样点：被删锚点位置 / 存活锚点位置 / 远离所有锚点的随机位置（基线）。
- 统计量：能量比 + 与存活特征最大余弦相似度（判读标准见 P2）。

### 第 3 步：残留审计（服务器）

- 渲染：对原始与删除后 checkpoint 各跑一次现有 `train.py` eval 路径（不新增模型耦合）。
- 打分：`scripts/deletion_audit/audit_scoring.py`（本地 CPU）——掩码内/全图 PSNR 下降，
  逐视角配对，缺失报错。掩码即第 1 步的 SAM2 区域图放大回渲染分辨率。
- 检出打分（重识别/检测器）为预留接口 `--detector`，MVP 未实现；接入时优先级：
  开源行人重识别模型 > 通用检测器 > CLIP 相似度。
- 完整版（第二阶段）：删除后**重编码**得到码流再解码，审计对象从模型换成码流；
  以及删除后不清理 vs 清理网格两种条件的对照。

## 三、接入检查项（服务器首跑时逐条确认）

- S1 相机约定：本模块按 OpenCV（x 右、y 下、z 向前）实现；接入 scaffold_gs 数据集前
  核对其 c2w 约定，必要时在投影入口做一次转换（OpenGL 系需翻转 x/y）。
- S2 键名核对：`attributes.pth` 的逐锚点键以 `scaffold_gs/hacpp.py` 装载代码为准
  （当前清单七键已核对）；若 `anchor_feat` 在部分版本叫 `anchor_feats`，
  在 `PER_ANCHOR_KEYS` 中补充。
- S3 环境门：所有新实验在 gsplat 1.5.3 新环境内做配对对比，不跨环境引用旧数字
  （沿用 2026-10-01 变更记录的环境门结论）。
- S4 首个场景选择：优先 Deep Blending 或 Mip-NeRF 360 中含明确可分物体的场景
  （garden 的桌子、room 的沙发类），SAM2 掩码质量先人工抽查 5 张。

## 四、数据与伦理

- 含真人/人脸的实验一律使用合成人形叠加或取得知情同意的自采数据；
  发布物默认只含删除后版本。"删除前后对比"数据集如需发布删除前版本，单独立项评审。
- 生成修补内容（第二阶段的补丁流）须带水印/元数据标识，与
  《互联网信息服务深度合成管理规定》的标识义务衔接（适用范围需法务核实）。
