# 锚点颜色表示 × DCCA-GS 主路径：叠加可行性与实验设计

> 版本：v0.1（2026-08-23）
>
> 对象：[锚点3DGS颜色表示方式分析](../锚点3DGS颜色表示方式分析.md) 中的六条路线；
> 目标：判断哪些颜色表示能**与当前主路径（I2+I6+SPA0.85+MiniSplat，语义可选）叠加**，
> 并给出从离线门到 110k 验证的可执行实验设计。
> 前提约束（硬）：**解码端可复现**——任何新增量要么由解码器从已传输信息重算，
> 要么进入比特流并重新走「压缩→解码→评估」；任何改动不得破坏 bit-exact roundtrip。

---

## 0. 结论先行（可行性）

| 路线 | 与现有路径叠加 | 体积影响 | 主要风险 | 结论 |
| --- | --- | --- | --- | --- |
| C：ASG 外观场（Spec-Gaussian 式） | **高**——由现有 `mlp_color` **预测** ASG 参数，参数不入流 | 几乎字节中性（只涨 `mlp_color` 权重，可量化） | 高光收益依赖场景；ASG 求值要确定且快 | **值得 P0 试**，作为「颜色解码器」的替代 |
| D：SOGS 二阶统计 | **条件高**——只接受「**解码端可重算**的二阶项」；若逐锚点存储 Σ，字节通常是负收益 | 重算型 0 字节；存储型 ≈ +d×r/锚点 | 特征降维是否能补回；重算需与解码端逐操作一致 | P1 试「重算型」，存储型先做字节账 |
| F：DropAnSH 低阶集中/截断 | 低——当前无 SH（mlp_color 直接 RGB），引入 SH 属倒退 | 大概率变大 | 与「特征+MLP 颜色」范式冲突 | **关闭/不优先** |
| E：前馈锚点（AnchorSplat/ATSplat） | 正交但不同范式——换训练/重建方式，不是“叠加” | 取决于场景 | 需新数据管线 | 列为未来方向，不做本设计 |
| B：维持现状（特征+MLP→RGB） | 基线 | — | — | 对照 |

**一句话**：现有主路径的「瓶颈在锚点位置+内容感知分配，而非颜色表示本身」；
颜色表示改动最**正交**的是「替换 `mlp_color` 的输出/输入」：
- 输出改成 ASG 参数 → 字节中性、纯解码器改动、可叠加；
- 输入加一个**零字节的二阶统计量**（由已传输特征/网格重算）→ 试探「特征降维保质量」。

## 1. 现有颜色路径的事实（代码基线）

`scaffold_gs/model.py`（`predict_gaussians`）：

```text
cat_local = concat(anchor_feat(feat_dim), ob_view(3))        # [n, feat_dim+3]
color     = mlp_color(cat_local).reshape(n, K, 3)            # Sigmoid -> RGB
```

- `feat_dim=50`、`K=10`；`mlp_color = Linear(feat_dim+3, feat_dim) → ReLU → Linear(feat_dim, 3K)`；
- 无 SH、无逐高斯颜色存储；`appearance_dim=0`；
- 体积（4-28 110k float32 记账）：Feature 50.6%、Scaling 20.0%、Offsets 12.2%、MLP 权重 5.9%；
- 编解码器只熵编码：feat / scaling / offsets / masks / hash；**颜色本身零逐高斯载荷**；
- MLP 量化（`mlp_quant.py`）已覆盖 `mlp_color`（`mlp_param_items` 含 `mlp_color`）。

## 2. 与现有模块的接口/冲突清单

| 模块 | 是否受影响 | 说明 |
| --- | --- | --- |
| I2 内容感知量化 | 不受影响 | 监督/预测的是 `mlp_complexity`，与颜色解码器解耦 |
| I6 渲染敏感度监督 | 不受影响 | 同上；但颜色改变会带动 loss 梯度分布，需复测其增益是否保持 |
| SPA 锚点预算 | **工程受影响** | 若新增**逐锚点张量**（Σ 或 ASG 状态），必须接入 `cat_tensors_to_optimizer`、`_prune_anchor_optimizer`、`append_depth_anchors`、`_sync_semantic_state`（顺序必须在 `cat` 之后，见 77ec99f 教训）、state_dict 存取；投影头类参数不得被当锚点参数 |
| MiniSplat depth-reinit | **工程受影响** | 新增逐锚点张量在 45k 增密时需与锚点数对齐；`spa_final_n` 钉在增密前 |
| 语义先验 T-A2 | 不受影响（工程注意） | 监督 `mlp_complexity`；若新增张量，`_sync_semantic_state` 的对齐顺序再核对一次 |
| Codec（HAC++ 熵编码） | C 路线：**不用改**；D 存储型：**必须改**（新增流） | ASG 参数由 MLP 生成→不入流；Σ 若重算→不入流；Σ 若存储→新增熵编码流+版本迁移 |
| MLP 量化 | C 路线：现成支持 | `mlp_color` 在量化清单；ASG 若新增小网络需登记 `mlp_param_items` |
| 体积分析 `volume_breakdown.py` | C 路线不改；D 存储型/新增网络需更新分类 | 避免 unclassified 报错 |
| 解码端可复现 | **必须满足** | ASG 求值、Σ 重算需编码/解码逐操作一致（浮点顺序、clip、归一化）|

## 3. 两个候选的详细设计

### 3.1 C：ASG-lite（推荐最先做）

- 改动：`mlp_color` 输出从 `3K` 改为「每高斯 ASG 参数」：
  `axis(3) + lambdas(2~3) + amplitude(1)`（按论文取参数化），再加一个轻量潜在映射回 RGB；
- 字节账：新参数全部由 `mlp_color` **生成**，不入流；`mlp_color` 权重从 `(d,d)→(d,3K)` 变
  `(d, pK)`（p≈6~9），MLP 权重增大约 2–3×（但 MLP 权重仅占总体积 ~5.9%，绝对增量小且可量化）；
- 解码端：新增 ASG 求值 kernel/Python 路径（frozen 小函数），保证确定性；
- 训练期：保持 Sigmoid 输出边界；对 `axis` 归一化、`lambdas` 取 exp/clamp；
- 收益假设：仅对镜面/高光（金属、水、玻璃、夜间车灯）明显；漫反射主导场景收益≈0。

### 3.2 D：SOGS-lite（重算型二阶项）

- 核心问题：**Σ 从哪里来？** 只有「解码端可重算」才零字节。可行来源（按可实现性排序）：
  1. 锚点局部邻域特征 Gram/协方差：`Σ_i = cov({f_j : j ∈ N(i)})`，`N(i)` 用**锚点坐标 Morton/最近邻**在解码端可重算（现有 `Morton序` 工具）；
  2. 每个锚点 K 个神经高斯「已生成特征」的统计：但神经高斯特征要由 MLP 重算（成本高，且与解码端一致性好验证）；
  3. 哈希网格在锚点处的 Jacobian 型二阶项：已经在 `mlp_grid` 里，可能是“免费”的丰富输入。
- 改动：`cat_local = concat(feat, ob_view, second_order(feat, neighbors))`，`second_order` 为冻结函数；
- 字节账：**0 字节**（重算型）；计算量 +O(锚点×邻居)；
- 与 feat_dim：目标是「用 0 字节二阶项换回降维损失」，因此**必须同时扫 feat_dim**；
- 风险：重算型若 `N(i)` 依赖解码顺序（Morton）必须编码/解码严格一致；建议用「锚点坐标最近邻」而非依赖排序状态。

> 反例账（存储型 Σ，供驳回依据）：若 Σ 为 d×r 低秩存储，每锚点新增 d×r 标量；
> feat_dim=50 时，Σ(50×8)=400 vs feat 50 → **单锚点 8 倍开销**，即使 feat_dim 50→16 也
> 需 Σ(16×8)=128 vs 16 → 仍 8 倍；只有 Σ 维度 ≤2（秩 1~2）时才有可能与 50→16 打平。
> 因此存储型默认不做，除非秩≤2 且实测同体积 BD-PSNR>0。

## 4. 实验设计（门控式，沿用项目方法论）

> 所有门都要「compress → decode → eval」闭环；30k 用于快速淘汰，110k 才下结论；
> 每个门给出**通过线**，不通过就关，避免无效投入。

### G0 工程门（改动即验）
- 交付：ASG-lite / SOGS-lite 分支实现 + `tests/test_color_rep.py`；
- 检查项：
  1. 新颜色路径在 `train / eval / compress / decode` 四态行为一致（构造“encode→decode→同一前向”等价测试）；
  2. 逐锚点新增张量（若有）与 `cat_tensors_to_optimizer / _prune_anchor_optimizer /
     append_depth_anchors / _sync_semantic_state` 全对齐；
  3. SPA 开启 + MiniSplat 开启 + 语义开启的三重组合下 3k 步冒烟不崩（重点 regress 顺序 bug）；
  4. `codec_roundtrip_diagnostics.json` 不匹配数全 0；
  5. 每步耗时/显存 ≤ 基线 +20%；
- 失败处理：G0 不过 → 工程问题先修，不进入质量实验。

### G1 快速质量门（playroom 30k，默认主路径）
- 配置：`I2+I6+SPA0.85+MiniSplat`（=cell2 基线），λ=0.004，feat50/K10/1600w；
- 细胞：
  | 编号 | 颜色表示 | 说明 |
  |---|---|---|
  | 1 | 现状 RGB（cell2） | 基线 |
  | 2 | ASG-lite | 输出替换 |
  | 3 | SOGS-lite（邻居 Gram，秩可取1/2） | 输入增强（不改输出） |
  | 4 | SOGS-lite + ASG-lite | 组合（若 2/3 均过） |
- 评估：PSNR/SSIM/LPIPS + total_MB + 锚点数；
- **通过线**：相对 cell2，同体积累积 BD-PSNR ≥ +0.05 dB，或同质量 BD-rate ≤ −3.0%；
  同时体积增量 ≤ +5%（若只有体积涨而质量不涨 → 关闭）。

### G2 解耦/机制门
- 对于过 G1 的表示，回答“到底赢在哪里”：
  - 颜色表示 × 锚点预算：`SPA ± × {ASG/SOGS}`（验证“更丰富颜色是否在少锚点下更值钱”，
    呼应 MiniSplat×SPA 的位置/预算结论）；
  - 颜色表示 × feat_dim：`feat_dim ∈ {16,32,50} × {基线, SOGS}`（SOGS 的核心命题：
    降维保质量；用 same-volume BD 判断，而不是只看 PSNR）；
  - 颜色表示 × MiniSplat：`MiniSplat ±`（确认重排锚点后颜色增益是否仍存在）；
- 通过线：效应不是由体积增加贡献（same-volume BD）；否则定性为“用比特换质量”。

### G3 泛化门
- 场景：playroom（已过）、drjohnson、4-28（110k，1600w）；每场景 seed∈{42,2026}；
- 指标：BD-PSNR/BD-rate 三场景平均；
- 通过线：≥2/3 场景 PB-PSNR > 0 且平均 ≥ +0.05 dB；
- 关闭线：只在 playroom 成立 → 结论降级为“场景依赖”，不写入主路径。

### G4 高光专项（仅 ASG）
- 若 G1 过而漫反射场景收益小：找/合成 1 个反射场景（玻璃/金属/水面；若没有现成数据集，
  用 playroom 中窗玻璃区或 4-28 夜景车灯区做子集评估）；
- 通过线：高光区域 LPIPS 下降 ≥0.02 或 PSNR ≥+0.1 dB，且整体不掉；
- 失败处理：无反射数据 → 记为“待数据”，不关闭但也不推广。

### G5 工程/发布门
- 重做 `mlp_quant` 位宽扫描（`mlp_color` 单独 8/16 bit；ASG 若新增网络一并登记）；
- `volume_breakdown.py` 更新分类；体积口径报告含新字段（若新增 token）；
- 码流版本：若新增比特流字段（存储型 Σ），按 `FORMULA_INPUT_VERSION` 规则升版本并做旧码流迁移测试；
- 记录训练/解码时间与显存。

## 5. 成本与排序

| 实验 | GPU 时间 | 优先级 | 依赖 |
| --- | --- | ---: | --- |
| G0 工程门 | 0.5–1 天（开发+冒烟） | P0 | 实现 |
| G1 playroom 30k ×4 | ~2 GPU·h（4×25min+finish） | P0 | G0 |
| G2 解耦（SPA×feat_dim×MiniSplat，约 8–12 个 30k） | ~5–8 GPU·h | P1 | G1 |
| G3 泛化（drjohnson+4-28×2seed×最优表示） | ~30–40 GPU·h | P1 | G2 |
| G4 高光专项 | ~2–4 GPU·h | P2 | G1(ASG) |
| G5 工程/发布 | 半天 | P2 | G2/G3 |

**推荐启动顺序**：ASG-lite 实现（输出替换，改动面最小、字节中性）→ G0 → G1 → 若过 →
SOGS-lite（重算型）G1 → 选胜者进 G2/G3。

## 6. 风险与备注

1. **不要同时改颜色表示与 I2/I6/SPA 语义**：每步只动一个变量，G1 用 cell2 基线作对照。
2. **解码端一致性是红线**：ASG/Σ 的浮点求值若与编码端不一致，即使 PSNR 高也不能上线；
   G0 必须含 roundtrip 等价测试。
3. **与语义先验的关系**：语义方向刚被判定“比特昂贵”（同比特无净增益）；颜色表示改动不会
   修复语义的性价比，两者是不同轴（位置/预算 vs 颜色表示），不应混为一谈。
4. 文中 SOGS 机制按公开摘要理解，正式实现前以论文 2503.07476 原文为准；
   Spec-Gaussian 2402.15870 同理（ASG 具体参数化需核对）。
