# 语义感知剪枝：训练侧融合重要性 设计

> 版本：v0.1（2026-09-03）
> 定位：方向二。把"敏感度 + 贡献面积 + 哈希上下文派生重要性（+ DINO 语义作消融）"
> 融合成一个**训练侧剪枝分数**，替代/扩展现有的 ADMM 稀疏分数，让"哪些锚点更重要"直接决定剪枝。
> 前置：`语义感知剪枝与空间上下文_实验设计.md`（方向一已判负，见其阶段 A 报告）。

---

## 0. TL;DR

1. 剪枝在**训练时**决定，剩余坐标进码流，解码端不需要重算"为什么删它"。
   → 剪枝分数可以**自由使用任何训练时信号**，没有"解码端必须能重算"的墙。
2. LYH 代码其实**已经实现了一半**：MiniSplat-full 用 `compute_contribution_areas` 算逐锚点
   贡献面积，并已在 `mini_splat_importance_weight=0.25` 下混入 ADMM 分数。方向二不是从零做，
   而是**在这个混合上再追加 敏感度 + 哈希上下文派生重要性 + DINO 语义（消融）**。
3. 融合重要性公式（每个分量先归一化再加权）：

```text
imp = w_a · score_a          # 掩码激活（原 ADMM 分数 a）
    + w_u · spa_u            # ADMM 对偶变量
    + w_area · norm(贡献面积)  # 视觉占用（已有）
    + w_sens · norm(敏感度)    # I6 渲染敏感度（新增）
    + w_ctx · norm(哈希上下文重要性)  # 哈希网格辅助（新增，用户明确要求）
    + w_sem · norm(语义分数)   # DINO 语义（消融项，可选）
```

其中 `哈希上下文重要性` 由一个**训练期小头**（`Linear(ctx_dim → 1)`，只训练、不进码流）
从哈希上下文预测"真实重要性"，`语义分数` 由 DINO 逐锚点语义在"平坦/边界"上打分。

---

## 1. 目标与成功标准

- **目标**：让剪枝按"重要性"选择，而不是按"不透明度/激活度"选择。
  - 保留：前景、近景、高敏感度、高贡献面积、语义边界/细节的锚点；
  - 删除：背景、远/低贡献、低敏感度、语义平坦大块区域的冗余锚点。
- **成功标准**（任一，且体积口径必须来自真实 bitstream）：
  - 同体积下 PSNR 提升 ≥0.05 dB；或
  - 同质量下体积减少 ≥2%。
- **约束**：剪枝是训练侧，比特流零新增字段；任何新增头/分数只用于训练，不进码流。

## 3. 融合重要性：各分量定义

### 3.1 掩码激活 a 与对偶 spa_u（已有）

`a = get_mask.mean(dim=1)`，`spa_u`（ADMM 对偶）保持现状。这是原来的"激活度"主项。

### 3.2 贡献面积（已有）

`area = compute_contribution_areas(self, cams, background, device)`，逐锚点最大贡献像素/（H·W）。
MiniSplat-full 已存入 `core.mini_splat_importance`。

### 3.3 渲染敏感度（新增）

逐锚点 `sensitivity_feat/scaling/offsets`（I6 EMA，已在训练中累积）。合成一个标量：

```text
sens = log1p( sensitivity_feat + sensitivity_scaling + sensitivity_offsets )
```

取 log1p 是因为梯度范数跨量级、长尾，log 后更可比较；也可用 3 个字段的加权和
（feat 权重高，因为特征量化影响最大）。该值只对**可见锚点**非零，未见锚点≈0 → 会被判为低重要性，
这符合直觉（从没被看到的锚点该删）。

### 3.4 哈希上下文派生重要性（新增，用户明确要求）

目的：把哈希网格编码的"几何+隐式视觉"信息，作为**剪枝辅助输入**。

实现：一个**训练期小头**（只训练、不进码流）：

```python
self.importance_head = nn.Linear(ctx_dim, 1)   # ctx_dim=48（无 I1）或 99（有 I1）
imp_ctx = self.importance_head(ctx).squeeze(-1)  # [N]
```

训练信号：回归"真实重要性"代理 = 归一化后的（敏感度 + 贡献面积）。即：

```text
L_ctx = MSE( normalize(imp_ctx), normalize(sens + area) )
```

这样 `imp_ctx` 学会"从哈希上下文猜这个锚点有多重要"。由于哈希上下文对敏感度只有 r≈0.31
（方向一门已测），`imp_ctx` 只能部分预测，但作为剪枝的**辅助信号**已够用（它不是唯一信号）。

> 训练侧无重算墙：`importance_head` 只在训练期存在，推理/码流丢弃，零侧信息。

### 3.5 DINO 语义分数（消融项，可选）

按锚点语义特征（`semantic_target` PCA 或原始特征）算"细节/边界度"：

```text
sem = -||语义特征 - 邻域语义均值|| 的某种度量，或
sem = 语义聚类熵（熵高=边界/多物体=更重要）
```

平坦大区域（天空/地面/墙面）熵低 → sem 低 → 优先删；语义边界 → sem 高 → 保留。
作为**对照项**（`w_sem` 可调，默认先 0，只跑消融时开启），避免 DINO 域偏差误导主判据。

## 4. 注入点（两处）

### 4.1 主入口：SPA ADMM 分数（gaussian_model.py ~1638-1652）

把：
```python
a = self.get_mask.mean(dim=1).detach()
scores = (a + self.spa_u).squeeze(-1)
keep = torch.topk(scores, kappa).indices
```
改为（在 `cfg.fusion_prune` 开启时）：
```python
a = self.get_mask.mean(dim=1).detach()
scores_base = (a + self.spa_u).squeeze(-1)
# 逐分量 z-score 后加权
s = zscore(scores_base) * w_a + zscore(self.spa_u.squeeze(-1)) * w_u
s += zscore(self._fusion_sensitivity()) * w_sens     # 敏感度
s += zscore(self._fusion_area()) * w_area            # 贡献面积
s += zscore(self._fusion_ctx()) * w_ctx              # 哈希上下文重要性
if cfg.fusion_semantic:
    s += zscore(self._fusion_semantic()) * w_sem     # DINO 语义（消融）
keep = torch.topk(s, kappa).indices
```

`_fusion_*` 辅助函数读 `self` 上的状态张量（`sensitivity_*`、`mini_splat_importance`、
`semantic_target/cov`、`calc_context_feat`），并保证与 `a` 同序、同长度（可能因生长/剪枝
需要 pad/截断）。

### 4.2 次入口：MiniSplat-full 分数（hacpp.py ~920-964）

把 `scores = area.squeeze(-1)` 也换成同一融合分数（含敏感度/上下文），保证增密后
"保留哪 kappa 个"按融合重要性选。

## 5. 配置字段（config.py 扩展，均有默认、默认关）

```text
fusion_prune: bool = False             # 总开关
fusion_weight_mask: float = 1.0        # 掩码激活
fusion_weight_u: float = 1.0           # 对偶
fusion_weight_area: float = 0.25       # 复用 mini_splat_importance_weight
fusion_weight_sens: float = 0.5        # 敏感度
fusion_weight_ctx: float = 0.3         # 哈希上下文重要性
fusion_weight_sem: float = 0.0         # DINO 语义（默认关，消融用）
fusion_importance_head_hidden: int = 32
fusion_semantic_enabled: bool = False
```

校验：`fusion_prune=True` 时所有权重 ≥0 且至少一个 >0；与 `spa_enabled` 不冲突（融合在
SPA 之上，独立性用 `spa_ratio` 控制）。

## 6. 消融矩阵（先 playroom 冒烟，再 4-28 / drjohnson）

| 组 | 配置 | 目的 |
| --- | --- | --- |
| 0 | 基线 `fusion_prune=False`（当前 best） | 对照 |
| 1 | + `w_sens`（仅敏感度） | 敏感度是否有用 |
| 2 | + `w_area`（敏感度+贡献面积） | 两类重要性叠加 |
| 3 | + `w_ctx`（再加哈希上下文重要性） | **主目标：哈希网格辅助是否有用** |
| 4 | 全开且 `w_sem>0` | DINO 语义消融（域偏差风险看这里） |

指标：PSNR/SSIM/LPIPS、total_MB（float32 与 MLP 量化双口径）、训练时间、显存峰值；
解码后指标必须来自真实 bitstream。

---

## 7. 决策规则

- 组 3（或组 4）相对组 0：同体积 PSNR +≥0.05dB 或同质量体积 −≥2% → 进入完整验证（组 3 为候选）。
- 若只有组 1/2 有效：说明"敏感度/面积"足够，哈希上下文（`w_ctx`）**无增量** → 按方向一同理，
  关掉 `w_ctx`，保留敏感度+面积。
- 若组 3/4 都无效：检查是否真的用上了融合分数（`imp` 是否非退化、topk 是否按它排序、剪枝比例是否变化），
  确认后关闭方向二。

---

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 敏感度只对可见锚点非零 → 没被看到的锚点被判极低分被删 | 这是期望行为；但对"少见但重要的远景锚点"需保留：给 `w_sens` 设下限，或用 `cov`（可见数）做软门 |
| 各分量量纲不同 | 每分量先 z-score（或 min-max），权重才可解释 |
| 剪枝比例被重要性改变，体积口径变化 | 钉住 `spa_ratio`/`kappa` 预算，比较时用**同体积**口径 |
| 哈希上下文对敏感度只有 r≈0.31，`imp_ctx` 只能部分预测 | 把它当辅助（`w_ctx` 小），不单独依赖 |
| DINO 域偏差（无人机 vs 预训练）误导 | `w_sem` 默认 0，仅降维消融开 |
| 新增小头/状态张量在生长/剪枝后不同步 | **推荐在 topk 时现算分数**（不存 fused state），仅需读各分量张量并按当前锚点数对齐；若必须存，需在 `adjust_anchor`/`growth` 同步 |

---

## 9. 实现要点

### 9.1 不引入新状态张量（推荐，最稳）

融合分数在 `adjust_anchor` 的 topk 前**现算**，只读现有状态（`spa_u`、`get_mask`、
`sensitivity_*`、`mini_splat_importance`、`semantic_target/cov`、`calc_context_feat`）。
这样无需在生长/剪枝后同步新张量。唯一需要的是给 `sensitivity_*`、`mini_splat_importance`
等**已有的** per-anchor 张量在 prune 时切片（SPA 已对 `sensitivity_*`、`spa_z/u` 做了；
需确认 `mini_splat_importance`、`semantic_target/cov` 也在切片/同步清单里——`semantic_target`
已在 gaussian_model.py 同步，确认 `mini_splat_importance` 同样在 `prune_anchor` 裁剪）。

### 9.2 `_fusion_ctx` 的训练头

`importance_head` 是训练器新增参数组（如 `importance_head`），只优化、不进导出。
在 training 步后（或每 N 步）：
```python
if train_step and cfg.fusion_prune:
    ctx = core.calc_context_feat(core.get_anchor, caller="fusion")
    imp_ctx = importance_head(ctx).squeeze(-1)
    target = zscore(core.sensitivity_score + core.mini_splat_importance.clamp_min(0))
    loss = MSE(imp_ctx, target.detach())   # 或只对 cov>阈值锚点
    loss.backward()
```

### 9.3 体积护栏

`importance_head` 不进码流；`fusion_*` 不改布局；只改 topk 分数，不增加任何码流字段。
比较时盯 `total_MB`（float32 / MLP 量化双口径）与解码后 PSNR/SSIM/LPIPS。
