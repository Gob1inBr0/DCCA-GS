## 1. 判定问题

在紧预算档（λ=0.004、稀疏化预算 0.85、场景 1-78），把 B3（阶梯对齐量化训练）
的"离粗格点距离"代数惩罚**换成**基层渲染损失，能否：

1. **消掉满精度档代价**——新环境实测代数惩罚的代价是 −0.176 dB（种子 42）/
   −0.181 dB（种子 104），两种子一致，明确超过噪声；
2. **同时保住基层档（码流首档 P0）增益**——旧环境读数 +0.916 dB；新环境读数
   缺位（fam 批次所有 B3 臂的分层评测未跑，CSV 各行标注 "P0 gain readout
   pending"），本批三臂全部分层评测，一并补上。

## 2. 假设（可证伪表述）

- **已证前提**（b3ns 批次，CSV 组 `b3ns`）：满精度代价不取决于惩罚拉哪个字段、
  拉多用力——去掉 scaling 字段（梯度被 1/Q 放大约 500 倍的头号嫌疑）后代价照旧
  （−0.476 对 −0.482），且惩罚原始值单调下降（0.583→0.358→0.184，符号确实被
  搬上了格点）。结论：代价来自代数惩罚与渲染损失对同一组锚点属性的方向冲突本身。
- **本实验机制假设**：代数惩罚是几何代理——对所有符号均匀用力，不知道挪动
  对画面值多少；基层渲染损失把优化目标换成真实图像误差，两个损失项量纲相同
  （都是渲染图像的 L1+SSIM），优化器自动找到"满精度画质损失换基层画质收益"
  的正确比价：值得挪的符号挪、不值得的不挪。
- **若假设成立**：满精度代价降到噪声级，基层保留大部分增益。
- **若假设不成立**（连真实渲染目标也消不掉代价）：说明冲突是结构性的——末期
  任何把符号搬离渲染最优解的约束都付满精度代价。此负结果同样有价值：它证明
  −0.18 dB 是该机制的内禀代价而非实现不当，B3 的论文表述（紧预算档专用 +
  如实写代价）即是最优表述，方向关闭入负结果台账。

## 4. 实验臂（三臂，同批同代码同种子）

共同配置：场景 1-78、30k 步、增长停止 15000、λ=0.004、种子 42、SPA 0.85、
MiniSplat 深度重初始化默认、新环境（/home/project2）、发车时主线最新提交
（哈希记入 CSV）。

| 臂 | 内容 | B3 惩罚 | 基层渲染损失 | 作用 |
| --- | --- | --- | --- | --- |
| A0 | 无 B3 对照 | 关 | 关 | 满精度与 P0 的基线 |
| A1 | 代数惩罚（复刻 fam 紧档臂） | w=0.05 | 关 | 增益参照；同批重跑补 P0 读数 |
| A2 | 基层渲染损失（实验臂） | 关 | w=0.05，24000 起，每 8 步 | 判定对象 |

- A2 的 w=0.05 与 A1 同名义权重，构成"同权重换机制"的机制对照；也是
  `p0_render_loss` 的默认值。
- **为什么不借用 fam 的 checkpoint 只补编码**：fam 之后代码已前进（GPU 每步
  税优化等，解码侧声明逐位一致，但训练轨迹是否受内核变化影响未验证）。配对
  判定必须同代码，三臂同批重跑；fam 原数字只作 A0 的守门参照（见 §5 哨兵），
  不进判定。
- 为什么不设"惩罚+渲染损失"组合臂：判定问题就是"换掉代理"。组合臂按 §7
  决策树在第二批出现。

命令模板（占位符按服务器实际填）：

```bash
RUNS_ROOT=<runs_dir> RUNROOT=<repo> CONDA_ENV_BIN=<env>/bin \
GSPLAT_ROOT=<gsplat> bash scripts/runner_phg_cell.sh \

  --cfg.model.spa-enabled --cfg.model.spa-ratio 0.85 \
  --cfg.model.mini-splat-enabled --cfg.model.mini-splat-reinit-iter 15000 \
  --cfg.model.mini-splat-max-new 4000 --cfg.model.mini-splat-views 8 \
  --cfg.model.mini-splat-voxel 0.0 --cfg.seed 42 \
  --cfg.model.sensitivity-start-iter 0 --cfg.model.spa-post-ratio 0.85
```

逐臂追加旗标：

- A0：无追加；
- A1：`--cfg.model.coarse-ladder-align --cfg.model.coarse-ladder-weight 0.05`；
- A2：`--cfg.model.p0-render-loss --cfg.model.p0-render-weight 0.05`。

训练后三臂全部分层编码与逐档评测（同时产出 full 档 150 视角指标）：

```bash

  --run <run_dir> --data-dir <data_dir> --field-aware \
  --data-factor 1 --max-width 1600 \
  --out <out>.json --bin <out>.bin
```

再走 `scripts/full_view_eval.py` 逐前缀 150 视角逐档评测（与 fam/arscan
同管线，150 视角 / 1600px GT / 生产量化栅格）。

## 5. 预注册判定门（发车前写死）

记号：`full(X)`、`P0(X)`、`MB(X)` 分别为臂 X 的满精度档 150 视角 PSNR、
码流首档 PSNR、满精度总字节。

| 门 | 判据 | 依据 |
| --- | --- | --- |
| **主门（消代价）** | `full(A2) − full(A0) ≥ −0.05 dB` | 噪声地板量级；A1 的同配对代价 −0.176/−0.181 远超此线 |
| **副门（保增益）** | `P0(A2) − P0(A0) ≥ +0.15 dB` **且** `P0(A2) ≥ P0(A1) − 0.15 dB` | 前半取 b3ns 副门同量级的绝对线；后半要求拿到惩罚方案大部分增益 |
| **码流门** | `MB(A2) ≤ 1.02 × MB(A0)` | 对齐机制不应推高码长；b3ns 观察过对齐反而省 0.56 MB |
| 哨兵 1（触发排查，不判负） | `|full(A0) − 27.3354| > 0.15 dB` → 停判，先排查代码漂移 | A0 应落在 fam_base_l0004_s42 的种子带内 |
| 哨兵 2 | A2 步时增幅 > 5%（对照 A0 的 ms/步） | 每 8 步多一次渲染+反传，粗算 +2~3% |

机制旁证（不设门，判定时一并解读）：A2 训练日志 `[P0Render]` 行自 24000 起
出现且 raw 值趋势下降；`P0(A2)` 字节与 `P0(A1)` 相近（±5%，符号对齐生效的
间接证据）；A1 的 P0 增益本身是 fam 缺失读数的补测值，单独登记。

**主副门同过 → 采纳**；主过副不过 / 主不过 → 走 §7 决策树。判定只用同批
三臂数字，不跨批次比较。

## 6. 发车前阻塞项（冒烟测试，任一不过不发车）

1. **梯度通路**：200 步短训 ×2（同种子），`--cfg.optim.max-steps 200
   --cfg.model.p0-render-start-iter 100`，一条 `p0-render-weight 0`、一条
   `=5.0`；backward 后打印 `model._view.anchor_feat.grad` 范数（临时调试
   打印，用完即删）。w=5.0 必须使范数可见地不同——相同即 p0 项梯度没接上
   （损失是常数），阻塞发车修复。若拿不准差异是否够大，w=0 再跑一遍测
   原子操作噪声水平作对照。
2. **日志确认**：短训中 `[P0Render]` 行自 start_iter 起按 interval 打印，
   数值非零。
3. **内存**：正式臂训练跨过 24000 时记录 `[Mem]` alloc 增量（p0 多挂一张
   渲染反传图）；相对 A0 增幅写入 CSV 备注。
4. **发车检查清单**（双开事故教训）：发车前 `ps -ef | grep train.py` 确认
   无存活进程；每臂独立结果目录、单写者；runner 带自动重试，发车 10 分钟后
   复核 launch.log 与进程数，发现 `.attempt` 日志即排查。

## 7. 决策树（预注册）

- **主过 + 副过** → 基层渲染损失提名为 B3 默认实现候选。第二批（约 5–10
  GPU·时）：① 种子 104 复现三臂配对（过双种子关）；② λ=0.002 / w=0.01 档
  配对（推荐操作点上验证"不伤满精度、补基层增益"，把适用条件从紧预算档
  放宽到整条曲线的表 claim）；③ garden 标准场景配对一对（与标准基准矩阵
  共用机时，直接喂剩余任务清单 #4"渐进感知量化表述定稿"）。
- **主过 + 副不过** → 方向对、幅度不足。第二批三臂小批：组合臂（惩罚
  w=0.025 + 渲染损失 w=0.05）、渲染损失 w=0.02、w=0.10（预注册的两点权重
  扫描，到此为止，不扩大）。
- **主不过** → 方向证负关闭。结论升级为"末期任何把符号搬离渲染最优解的
  约束都付满精度代价，与代理还是真实目标无关"；B3 论文表述维持紧预算档
  专用并如实写内禀代价；负结果入 README 台账与 CSV。

## 9. 风险与已知坑

| 风险 | 说明 | 处置 |
| --- | --- | --- |
| 直通估计的梯度失真 | 两次取整几乎处处真实梯度为零，反向用恒等近似（与现有 `STE_multistep` 同一套路） | 标准量化感知训练做法，不额外处理；冒烟测试保证通路接通 |
| w=0.05 不适度 | 太弱搬不动符号、太强重蹈 w=0.05 惩罚的塌方 | 决策树中间分支的两个权重点；注意渲染损失与主损失同量纲（w=0.05 即基层目标占 5%），与惩罚的 1/(L·Q) 量纲不可比 |
| A1 新环境 P0 增益本身缩水 | 旧环境 +0.916 dB 可能随环境/口径漂移 | 副门前半是绝对线不受影响；后半自动放宽（同批比较，不跨批次） |
| 随机数流分叉 | p0 渲染不消耗 `torch.rand`，但原子操作浮点不确定性使 24000 后轨迹分叉 | 预期内；配对在臂间进行，不受影响 |
| 与内容自适应量化的叠加 | 两者在 24000–30000 同时生效（后者 20000 起渐进） | 这正是生产配置，按原样叠加判定 |

## 10. 更正（发车前，2026-10-12）：冒烟测试配方

§6 第 1 条原配方（200 步短训对比 w=0/w=5.0 梯度范数）有缺陷：`generate_gaussians`
的 p0 去量化分支以 **step > 10000 为硬编码条件**（10000 步处先调
`update_anchor_bound`），200 步短训根本走不到两次取整代码，验证的是空转路径。
发车前更正为两部分冒烟（判定效力只增不减）：

1. **冒烟 B（梯度通路，阻塞项）**：新增脚本 `scripts/p0r_smoke.py`——绕开
   trainer 门控，直接以 step=10500 调 `model.render(quant_mode="p0")`（与生产
   每 8 步的额外渲染同一条代码路径），同一模型同一相机各做一次 w=0 / w=5.0
   的完整前向+反向。通过判据：anchor_feat 梯度范数比值 |log2| > 0.5，且 p0
   渲染图与主渲染图平均绝对差 > 1e-4（证明去量化路径真的走到）。任一不满足
   退出码 1，阻塞发车。注：step=10500 处内容自适应量化尚未激活（起始
   20000），冒烟验证的是两次取整直通估计本身，不覆盖与内容自适应的叠加——
   该叠加由正式 A2 臂按生产配置判定。
2. **冒烟 A（trainer 接线，阻塞项）**：600 步短训（`--cfg.optim.max-steps 600
   --cfg.model.p0-render-start-iter 100 --cfg.model.p0-render-weight 5.0`），
   验证 trainer 门控逻辑、`[P0Render]` 打印（500 步处）与显存不爆。此短训
   step<10000，p0 分支空转属预期——去量化路径由冒烟 B 覆盖。

§5 判定门与 §7 决策树不变。
