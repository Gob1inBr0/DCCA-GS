# 渐进码流方向探索（2026-09-20）

> 前置事实（全部已确证，见 `../03-reports/离线任务第二批_20260920.md`）：
> ① Morton 排序判负（字节-覆盖曲线输给随机，因字节先铺满包围盒一角）；
> ② 贡献降序拿到 80% 场景覆盖只要 21.5% 的字节（随机 79.8%）；
> ③ 逐锚点比特、覆盖面积、解码端结构统计量都有现成导出；
> ④ 码流逐字段分批存储（228 批 × 字段），截断自同步问题真实存在。
> 约束（不可违反）：解码端零边信息（一切顺序/条件信息要么在码流里、
> 要么解码端可重算）；逐位还原校验必须通过。

## 0. 问题定义

目标：**收到前 k% 字节时就能渲染出尽可能好的画面**，k 从 0 扫到 100 得到一条
"字节-画质"曲线，曲线下的面积（AUC）是优化目标。

评测指标（预注册）：
- 主指标：字节-PSNR 曲线 + AUC（k = 5/10/25/50/75% 处的 PSNR 表）；
- 辅指标：首帧可用时间（拿到多少字节能渲染出 PSNR ≥ 20 dB 的图）；
- 成本指标：渐进版相对原码流的体积开销（排序元数据 + 分层开销）。

## 1. 设计空间总览

| 家族 | 一句话 | 改动量 | 解码端顺序信息 |
| --- | --- | --- | --- |
| A 排序分组 | 定一个锚点优先级顺序，按组写入码流 | 只改打包顺序 | 元数据或可预测 |
| B 分层量化 | 每个属性先存粗版本再存细化残差（类似 JPEG 的质量分层） | 改量化与打包 | 天然分层，无需额外信息 |
| C 条件熵模型 | 熵模型的上下文包含"已经收到的部分"（自回归） | 重训练 | 解码端天然可重算 |

## 2. 方向清单

### A 家族：排序分组

**A1 贡献排序 + 组号元数据（基线方案，S1 后定为默认排序）**
- 机制：锚点按贡献（覆盖面积）降序分成 G 组（G=16/32/64），逐组编码；每组
  一个自包含的算术编码段 + 段头。解码端读组号元数据（G=32 时约 5 bit/锚点
  ≈ 2% 载荷）。
- 判定线（预注册）：总开销 ≤ +3%，且 25% 字节处 PSNR 比随机排序高 ≥ 0.3 dB。

**A2 贡献的可预测性（省掉元数据）——S1 判负，免元数据路线放弃**
- 机制：用解码端已有的结构统计量（锚点密度、缩放各向异性、偏移能量、
  掩码存活率——I2 的四个输入）预测贡献排序，能预测则解码端自己算顺序、
  元数据归零。
- 判定线：预测顺序的曲线达到真顺序 AUC 的 95% 以上 → 元数据可省；否则回到
  A1。实测组合排序只达 81.6%（§6），按预注册回到 A1。

**A3 次模贪心顺序 = 最优前缀顺序——空间格代理上判负**
- 机制：Phase 1 的次模实现每周期产出的选择序列就是现成的渐进顺序；用贪心
  选择顺序重算字节-覆盖曲线 vs 贡献降序（字节-覆盖曲线是代理指标，真正的
  字节-PSNR 见 D4）。
- 判定线：次模顺序的曲线 AUC 比贡献降序高 ≥ 5% → 采用次模顺序作为默认
  排序；否则用贡献降序。空间格代理实测贪心 0.872 对贡献 0.905（§6）；
  真实边判定见 §7 读法三。

**A4 几何先行**：锚点坐标走独立的 GPCC 流（1.29 MB，占载荷约 6%），把它放在
文件最前 + 属性按 A1/A3 排序；这是打包顺序改动，配合 D4 渲染实验评估。

**A5 视口加权排序**：默认视角集合下的可见贡献排序（贡献 × 视角命中），必须存
元数据（视角相关顺序解码端不可算）；优先级低（先做好视角无关版本）。

### B 家族：分层量化（SNR 分层）

**B1 比特平面分层**：每个量化符号拆成"粗比特平面 + 细比特平面"：先收高位
（大尺度数值），后收低位（精度）；收完粗层就能用粗值渲染。与 A 正交：
A 决定"哪些锚点先来"，B 决定"每个锚点的属性以什么精度渐次到达"。

**B2 两遍量化（粗层 + 残差层）**：B1 的简化版：粗层用大步长 Q 重新量化一份，
细层存 (原符号 − 粗层×Q/Q粗) 的残差；实现比比特平面简单，两层就够。

### C 家族：条件熵模型

术语事实：自回归在熵编码里指"当前符号的概率由已经解码的符号决定"；渐进场景
收到的部分就是已解码部分，拿它当上下文不违反零边信息（解码端手里真的有这些值）。

**C1 前缀条件自回归（完整形态，重训练）**：解码第 k 组符号时，熵模型的上下文
包含第 0..k−1 组的已解码值（例如按 Morton 邻居取已解码锚点的属性统计量作为
条件输入）；训练时用因果掩码（只能看"更早的组"）强制这个性质。旧负结果
"跨锚点邻居条件熵增益不到 1%"是在无序全量设置下测的静态邻居条件，机制不同；
先跑 C2 的离线版估收益上限，过不了就不训练。

**C2 层间条件（C1 的离散版，离线可估）**：两层结构里，细层的概率模型以粗层
已解码值为条件（粗层先到）。判定线：条件熵比无条件低 ≥ 0.3 bit/符号 → 值得
训练细化版；否则 C 家族整体记负结果（与旧邻居条件负结果合并成完整证据链）。

**C3 组摘要先导层（超先验类比）**：文件最前面放一个极小的"摘要层"（每组每
字段的均值/尺度参数，几 KB），主码流的熵模型以摘要为条件；摘要是码流一部分，
零边信息成立。

### D 家族：工程与评测（所有方向共用）

- **D1 截断自同步**：算术码切 G 段，每段独立可解 + 段头带长度校验；网络截断
  落在段中间时丢整段。
- **D2 渲染策略**：缺失锚点跳过（预注册基线）；进阶做"邻居属性插值补洞"
  作为对照。
- **D3 参照系**：和"同锚点数的重训练模型"（如 r055/基准的中间点）对比。
- **D4 轻量渲染实验**：截断解码 + 渲染若干视角 → 字节-PSNR 实测曲线，是所有
  离线代理指标的最终校验。

## 3. 推进阶梯（预注册）

| 阶段 | 内容 | 成本 | 出口判定 |
| --- | --- | --- | --- |
| S1 离线 | A1 开销精算；A2 可预测性；A3 次模顺序曲线；C2/C3 条件熵收益上限；D1 分段损失 | 零 GPU | 各自判定线；任何一条通过即有可立项路径 |
| S2 轻渲染 | D4 字节-PSNR 实测（A1/A3 两种排序 + B2 粗层） | 分钟级 GPU | 曲线形状与离线代理一致；25% 字节 PSNR ≥ 视口无关可用线（20 dB） |
| S3 端到端 | 组合胜出方案做成真码流（改打包器）+ 逐位还原校验 | 代码工程，无训练 | 开销 ≤ +3%，曲线达标 |
| S4 重训练（可选） | 仅当 C2 上限 ≥ 0.3 bit/符号：C1/C3 训练 | 1–2 次训练 | 条件模型相对 S3 再省 ≥ 3% 体积或抬曲线 |

优先顺序：S1 全部 → S2 → S3（A3 若赢用 A3 否则 A1）→ S4 视 C2。

## 4. 相邻工作（2026-09-20 查证更新）

直接对口的渐进 3DGS 压缩已有两篇：

- **PCGS**（arXiv 2503.08511，2025-03；AAAI 2026 Oral，代码开源）：渐进靠
  训练期调度——数量侧"渐进掩码"（训练中按调度逐步解除锚点的掩码，新锚点
  渐进纳入、已纳入的继续细化，训练本身就是码率爬升过程）、质量侧"渐进量化"
  （量化步长随训练逐步减小，属性精度逐级提高）；支持码流复用（低带宽先传
  低档，带宽增加后在已有码流上增量增强，不重传）。顺序来源是**训练动力学**
  （掩码解除的先后），非显式为前缀质量优化；分层是训练期的副产品（嵌入式
  分层）。≈ A（数量）+ B（质量）家族，但顺序不可控、层数与训练耦合。
- **ProGS**（arXiv 2603.09703，2026-03）：把高斯/锚点放进八叉树，渐进 =
  父闭前缀（收到一个节点前必先收到其父），从粗到细；用八叉树层级节点间的
  相关性（互信息表述）增强上下文、去结构冗余——**这是结构邻域条件，不是
  "已解码前缀自回归"**；动态调整八叉树与锚点归属；宣称相对原始 3DGS 格式
  45 倍压缩（口径：原始格式，非对 SOTA 压缩器的 BD-rate）。≈ A 家族的
  空间层级排序 + C 家族的结构条件版。
- **Octree-GS**（arXiv 2410.03175，ICLR 2025）：八叉树锚点 LOD 渲染（非压缩），
  ProGS 的结构前身；C3DGS（NeurIPS）的锚点上下文是熵侧前身。
- 经典参照：渐进 JPEG / SVC 可伸缩视频（B 家族谱系）；神经图像压缩的超先验
  与局部解码（C 家族谱系）。

### 4.1 机制对照表

| 机制 | PCGS | ProGS | 我们的位置 |
| --- | --- | --- | --- |
| 谁先到（顺序） | 训练动力学 | 八叉树父闭前缀 | **显式优化**：次模贪心顺序（A3）/预测排序（A2） |
| 多细地到（分层） | 渐进量化步长 | 层级本身 | B 家族比特平面/两遍量化 |
| 压缩上下文 | 训练期耦合 | 八叉树结构邻域 | **前缀自回归**（C1，待 C2 上限过线） |
| 零边信息顺序 | 嵌入式（免元数据） | 结构固有（免元数据） | A2 预测（免元数据）/A1 组号（2%） |
| 评测 | 点/码率档 | 流式指标+45× | 字节-PSNR 曲线 + AUC（预注册） |

## 6. S1 离线检查结果（2026-09-20 执行，脚本 `scripts/s1_progressive_checks.py`，
数据 `docs/data/s1_progressive_lambda0005.json`）

| 检查 | 及格线 | 结果 | 判定 |
| --- | --- | --- | --- |
| A1 组号元数据 | 开销 ≤3% | 32 组 = 0.43 MB = 2.06%（8–128 组 1.2%–2.9%） | **过** |
| A2 顺序可预测性 | 预测顺序达真顺序 AUC 的 95% | 五个解码端统计量的秩相关全部弱（\|r\|≤0.16）；组合排序只达 81.6% | **不过**——元数据路线（A1）保留 |
| A3 次模顺序（空间格代理） | 贪心顺序 AUC ≥ 贡献排序 +5% | 贪心 0.872 对贡献 0.905（去重口径）——**更差** | **代理上不过**。原因：每锚点只盖 ≤2 格、平均 1.65 锚/格，代理的冗余结构太弱，次模去冗余无从发挥。次模顺序假设是否成立取决于真实渲染覆盖的重叠强度——正是 S2 要测的（真实边做贪心，成本已就位） |
| C2 层间条件上限 | ≥0.3 bit/符号 | 低 3 位以高位为条件：省 0.374（λ0005）/ 0.356（λ0002）bit/符号（≈4.6%） | **过**——按阶梯解锁 C 家族训练（C1/C3），两档一致 |
| D1 分段开销 | 不显著 | 分段后逐组熵之和反而略低（−0.02~−0.07 bit/符号）；注意直方图过拟合告警 | **过**（排序让组内同质，分段可能白赚） |

### 6.1 S1 结果要点

- **A1（2.06%，过）**：0.43 MB 买到的是"21.5% 字节拿 80% 覆盖"的曲线斜率。
- **A2（不过，81.6%）**：贡献（渲染覆盖面积）是**依赖视角**的量，五个解码端
  统计量全是纯几何量；组合秩相关只到 81.6%，联合信号存在但天花板远低于 95%。
  按预注册执行：放弃免元数据路线。
- **A3（代理上不过）**：代理参数 416,120 格、平均 1.65 锚/格、每锚 ≤2 格；
  重叠度这么低时集合覆盖退化成"每格挑一个代表"，贪心会为了格子质量牺牲
  锚点价值密度。真实边的更快裁判：先量真实覆盖二部图的重叠度（每锚点覆盖
  多少像素块、每块被多少锚点覆盖——训练时提供器现成产出、只需加一行日志
  转储）。重叠度高（比如 ≥5 块/锚点、高重数）才值得在真实边上跑贪心；否则
  A3 永久关闭、贡献降序定案。
- **C2（0.374/0.356 bit/符号，过）**：scaling 字段换算 0.37 × 412 万符号 ≈
  0.19 MB（λ0005），单字段占载荷 0.9%；按阶梯解锁 C 家族训练（C1/C3）。
  feat 字段重测见 §6.2。两个限制：① 0.37 是"层内独立同分布"假设下的上界，
  真实自适应编码达不到满额；② 端到端收益会小于字段收益（省下的比特会被
  码率-画质权衡重新花掉），但它附带在 B 家族本来就需要的分层结构上——边际
  成本接近零。与 ProGS 的差异化：ProGS 的条件是八叉树结构邻域，我们的是
  **质量层间**（粗比特层预测细比特层），两个正交的槽位。
- **D1（过）**：分段后逐组熵之和更低，机制是"按贡献排序 → 组内锚点统计同质
  → 组内符号分布更窄"——**组号本身就是熵模型的有效条件**。由此解锁一个比
  C1 便宜得多的中间方案（记为 C2.5）：每组每字段存一组分布参数（均值/尺度，
  几十字节/组），符号按组内参数编码——不训练任何网络，纯编码端改动，能吃到
  D1 观测到的同质化收益的一部分。加进 S3 的实现清单，作为 C 家族的
  "零训练版"先行。

S1 结论与下一步：
1. **默认排序 = 贡献降序 + 32 组号元数据（2.06%）**——A1/D1 双过，A2/A3
   均不支持免元数据或换顺序（在代理上）。
2. **S2 轻渲染实验**是两个问题的裁判：真实覆盖重叠下贪心顺序能否反超
   （A3 的真检验）；字节-画质实测曲线校准代理指标。
3. **C 家族训练解锁**（C2 过线）：按阶梯 S4 设计条件混合模型，排在 S2/S3
   之后（先把不训练的路线做实）。

### 6.2 feat 字段的 C2 上限重测（2026-09-20，脚本 `scripts/c2_feat_check.py`）

feat 字段（32 符号/锚点，载荷最大字段 10.6 MB）的层间条件增益：
**0.31–0.39 bit/符号（b=3/b=5 两档分层，两个 λ 档一致）**——与 scaling
的 0.37 同区间，层间条件收益对字段类型不敏感，结构性成立。

两个口径说明（诚实记录）：
1. **恢复率告警**：feat 的量化步长整除性恢复成功率只有 0.6%（scaling
   是 100%）——feat 的实际符号化路径比"每锚点标量步长"复杂，本测量
   用了插值步长，0.3–0.4 bit 的数字可信度中等；精确版要读编码器实际
   下发的 Q（`hac_meta.json` / 编码路径），待精化。
2. **奖池更正**：全锚点口径下 feat 的层间条件节省 ≈ 0.389 bit ×
   68.7 万锚点 × 32 符号 ≈ **1.07 MB**（λ0005）；加 scaling 的 0.19 MB，
   C 家族总奖池约 **1.3 MB ≈ 载荷 6%**。

结论：C 家族过线且奖池可观，但执行顺序不变——C2.5（组参数条件，零
训练）先吃一部分，C1/C3 重训练版排在 S2/S3 之后。当前上下文编码已经
很强（feat 仅 2.6–3.9 bit/符号，符号边际熵的两成以下），条件混合模型
的边际收益要按此基线校准预期。

## 7. S2 前缀渲染实测（2026-09-21 执行，脚本 `scripts/render_prefix_sweep.py`，产物 `analysis/s2_prefix_sweep/prefix_sweep.json`、图 `docs/figures/s2_prefix_bytes_psnr.png`）

**设置**：λ0.0005 s42 解码模型（681,228 个存活锚点，解码-训练锚点按坐标最近邻
映射回统计量行，99.99% 距离 <5e-3，冲突行 0.59%，全部记录在产物里）；贡献降序
（anchor_stats 面积）与随机（种子 0）两种排序 × 前缀 {5,10,25,50,100}%，固定
16 个验证视角；字节轴 = 固定开销 + 几何按比例 + 保留锚点的逐锚点属性比特和
（估算上限，满前缀 22.47 MB 对实际码流 19.94 MB，各前缀一致故形状有效）。

| 前缀 | 贡献降序 MB / PSNR | 随机 MB / PSNR | 排序增益 |
| --- | --- | --- | --- |
| 5% | 1.74 / 14.14 | 1.35 / 8.05 | +6.1 dB |
| 10% | 3.22 / 16.49 | 2.46 / 10.27 | +6.2 dB |
| 25% | 7.55 / 20.62 | 5.80 / 14.66 | +5.9 dB |
| 50% | 14.37 / 24.61 | 11.35 / 19.38 | +5.2 dB |
| 100% | 22.47 / 26.95 | 22.47 / 26.95 | — |

**读法一：排序信号真实且巨大**（各前缀 +5~+6 dB）——A 家族"顺序是杠杆"的
前提被实测证实，A1 的 2.06% 元数据开销买到的就是这条曲线对随机的差距。

**读法二：曲线不是"前面很肥"的形状**——贡献降序前 50% 锚点只有 24.61 dB
（差满锚点 2.3 dB），前 25% 差 6.3 dB。纯选择式渐进给的是"平滑降级"，给不了
"低字节高画质"。选择式渐进的天花板就在这条曲线上。

**读法三：A3 真实重叠判定**——预登记槛"每锚点 ≥5 块"未过（均值 3.7，
中位数 0：16 视角下一半锚点没碰过任何像素块，与盲锚点分析一致）；但**重数
方向爆炸**：每块平均被 316 个锚点覆盖（中位数 242、p90 608）。贪心去冗余
需要的结构（高重数重叠）在真实像素块图上远比 3D 格代理丰富——真实边上跑
贪心"值不值"的答案从"代理说不行"翻转为"结构上可行、但见读法二的天花板"。

**对路线的影响**：两条腿走路——
1. **B/C 家族（分层量化+条件熵）升为主结构**：底层保全部锚点（不挖洞），
   精度换码率；C2 的 0.31–0.39 bit/符号层间条件增益直接适用。选择式前缀
   做不到的"低字节覆盖完整"，分层结构天然做到。
2. **A 家族收缩为排序与元数据层**：顺序增益（+5 dB 级）用于层内排序和
   传输顺序，不承担画质主线。

S2 预注册计划的其余项（贪心在真实边上的实际曲线）按读法三降级为可选——
结构可行但天花板已知，优先级排在 B/C 家族之后。

## 8. S3 第一步：C2.5 分层重编码实测（2026-09-22 执行，脚本 `scripts/c25_layered_curve.py`，
产物 `analysis/s2_prefix_sweep/c25_layered_curve.json`、图 `docs/figures/c25_vs_s2_curves.png`）

**做法**：λ0.0005 s42 解码模型上，把 feat/scaling/offsets 三字段重排成嵌套质量
层（4×粗步长全锚点 → ±1 残差精化到 2× → 再精化到原步长），量化步长走解码端
可复现路径重建（逐符号校验 100% 匹配，零边信息契约实测成立）；熵记账用 32
贡献分组的离散拉普拉斯（C2.5 的零训练条件机制）；每个层级真实渲染 16 视角。
满精度层作为校验锚点（26.953 dB，与 S2 满锚点完全一致）。

| 层级 | 字节（静态编码器记账） | PSNR | 相对满精度 |
| --- | --- | --- | --- |
| L0（4×粗，全锚点） | 23.11 MB | **26.357** | −0.60 dB |
| L1（2×） | 28.31 MB | **26.747** | −0.21 dB |
| L2（原步长） | 36.82 MB | 26.953 | — |

**读法一：B/C 家族核心前提端到端证实**——所有锚点粗 4 倍只损失 0.60 dB。
"低字节完整覆盖"的渐进形态成立，S2 的选择式天花板不是渐进的天花板。

**读法二：字节轴口径差必须诚实标注**。分层曲线用的是零训练静态分组编码器
（全精度总量 36.8 MB），比学习式编解码器（21.4 MB）贵约 1.75 倍——这是
C2.5"零训练"的固有代价（学习到的上下文模型在 offsets/scaling 上极强）。
按 1.75 倍归一化估算，L0 的学习式等价字节 ≈ 13.2 MB @ 26.36 dB，而选择式
要达到 26.36 dB 需约 20.4 MB（学习式记账内插值）——**分层路线在同画质下
估计省约 7 MB**。此为估算，落论文前需真实的分层学习式编码器（S4）。

**读法三：本实验顺带产出两个工程结论**。① 量化步长解码端重建 100% 精确
（feat/offsets 100%、scaling 99.999%），S1 的"feat 恢复率 0.6%"告警正式
撤销；② `attributes.pth`（编码时写入）与解码模型张量在少数行上差异巨大
（scaling 最大差 21，log 空间）——解码端做了边界裁剪，**渲染实验永远要以
解码模型张量为准，不能用盘上属性文件**（本实验曾因此三次渲染报废，校验
锚点机制避免了错数出街）。

**判定与下一步**：渐进主结构定为分层（B/C），排序保持元数据角色不变。
S3 剩余工作按序：① 真实熵编码器（区间编码）替换熵记账，产出可直接传输的
分层码流 + 前缀解码器；② C2.5 的组参数升级为层间条件（C2 上界 0.31–0.39
bit/符号的落地）；③ S4：条件混合熵模型重训练，消除静态编码器 1.75 倍的
字节差距——那之后才是与选择式/相邻工作的正式 RD 对比。

## 9. 真实分层码流落地（2026-09-24，脚本 `scripts/c25_real_bitstream.py`，
产物 `analysis/s2_prefix_sweep/c25_real_*.json/.bin`）

区间编码器（constriction，隔离目录安装）替换熵记账，产出**真实可传输、
任意层边界截断可解的 `.bin` 文件**；残差层升级为**层间条件模型**（按
"组 × 粗层符号大小 {0,1,≥2}"分桶，解码端可重算，零边信息保持）。三条曲线：

**1-78 λ0.0005 s42（新协议，条件化）**：14.06 MB→21.89、19.86→25.06、
25.70→**26.36**、30.43→26.75、37.92→26.93（校验锚点 ✓）。细层编码时用已解码的粗层符号当上下文
无条件省 **2.33 MB**（与 C2 上界 0.35 bit/符号×每层符号数≈1 MB/层×4 层
同量级，交叉一致）。

**2-06（旧协议 base，跨数据集验证）**：8.94→17.29、13.57→21.85、
18.73→24.71、22.51→25.62、28.32→26.09（✓）。映射自动生成、无统计文件时
Morton 均匀分组回退均工作——**管线跨数据集泛化成立**。

**1-78 λ0.004（旧协议，低码率点）**：5.73→14.40、8.74→18.50、12.68→23.40、
15.85→25.77、20.69→26.81（✓）。条件化省 1.93 MB。

**诚实的发现**：① 阶梯存在"粗化过头画质骤降"——16×/8× 层画质崩塌（scaling 为
log 值，粗化直接破坏几何），**可用渐进区间从 4× 层开始**，更粗的层需要
对 scaling 单独保护（进 S4 设计）；② 真实字节轴上，静态编码器仍比学习式
贵（满精度 37.9 对 21.4 MB），同画质对比选择式暂无体积优势——差距收敛
靠下面的 S4。

**S4 设计（廉价版重定位）**：不是重训三维场景，而是**后置训练一个小型
条件熵模型头**（输入：已解码粗层符号 + 组号 + 敏感度统计【量化路径 B 并入】
，输出：细层符号分布），在现有 run 的符号上离线训练、即插即用到同一阶梯。
按预先写定的标准做的对照测试（预登记）：学习式头的累计字节在同画质下比分组频率统计表（每组存中位数、零占比、幅度进位占比，随码流传输）省 ≥15%（对 1.75× 差距的
三分之一）；训练数据用 ms_wave1 12 个 run 的符号（出数即有）。工程量：
一个小型网络 + 训练循环，不占场景训练卡时（GPU 需求小时级）。

## 11. S4 apply 集成结果：架构失配的负结果（2026-09-25）

用小 MLP 按分组预测概率参数的细层编码模型（学习式，区别于频率统计表版）（NLL 上省 15.4%/17.2%，过门）接入真实把整数拆成一串是非题逐位编码码流后，
**真实字节反而变贵**：

| 场景 | 分组频率统计表（每组存中位数、零占比、幅度进位占比，随码流传输）满精度 | 用小 MLP 按分组预测概率参数的细层编码模型满精度 | 差 |
| --- | --- | --- | --- |
| 1-78 λ0.0005（分字段粗化档位） | 29.95 MB | 40.38 MB | +35% |
| 2-06 λ0.0005（uniform） | 30.77 MB | 42.54 MB | +38% |

**根因（架构失配，非场景偶发）**：按预先写定的标准做的对照测试比较的是"每符号 NLL"——用小 MLP 按分组预测概率参数的细层编码模型预测
的分布更贴数据；但真实码流用的是**把整数拆成一串是非题逐位编码框架**，每个符号拆成一串二元
决策、每决策一比特级开销。用小 MLP 按分组预测概率参数的细层编码模型预测的 σ 比分组频率统计表（每组存中位数、零占比、幅度进位占比，随码流传输）按二元框架拟合的更宽，
二元决策的概率离 0/1 更远，逐决策比特更多——NLL 的收益被框架开销吃掉。
**教训：NLL 按预先写定的标准做的对照测试必须在与生产编码器同构的框架内做**；跨框架比较会给出
方向相反的结论。分组频率统计表（每组存中位数、零占比、幅度进位占比，随码流传输）保持生产选择。

**这一步的价值**：S4 的"高效码流"问题现在有了完整回答——在这个框架里，
分组频率统计表（每组存中位数、零占比、幅度进位占比，随码流传输）（组 × 粗层幅度桶）已经是接近该架构上限的形态；要把学习式
收益真正兑现，需要用小 MLP 按分组预测概率参数的细层编码模型直接输出二元决策概率（而不是高斯 σ 再映射），
那是一个新的训练目标，列为后续可选项而非本期承诺。
